# Подключение данных к существующему проекту

commit `bcfe5de6ffd81c2d31f2b4b0f949eaa0fb0b941d`. После `git fetch origin`

## Контракт Rule Pack

Расширение находится в `data/compendia/dnd_5e_2014/rule_packs/dnd_5e_2014/`. Внешний `ruleset_id` тот же; новые ID правил используют сегмент `:compendium:`, чтобы не перезаписать существующие правила. Версия и `pack_id` отдельные. Файлы соответствуют прочитанным требованиям загрузчика: плоский YAML, CSV с нужными заголовками, JSONL правил и связей, точные счётчики, source registry.

Пример **отдельной** загрузки через существующий серверный модуль:

```javascript
import { loadRulePack } from './server/rule-pack.mjs'
import { loadReferenceRulePack } from './server/dndsu-2014-content.mjs'
const extension = await loadReferenceRulePack(loadRulePack)
console.log(extension.summary)
```

Оба импорта в примере рассчитаны на файл в корне проекта. Не устанавливайте этот объект вместо базового пакета автоматически. Если Retriever хранит только один pack на `ruleset_id`, требуется явное объединение: сохранить старые ID, добавить новые, объединить словарь/источники/связи, пересчитать coverage, проверить конфликты и закрепить новую версию за новыми кампаниями. Сначала выполните собственные тесты Retriever и replay. Сам архив такого объединения не производит.

`text_ru` и `text_en` содержат короткое объяснение и одинаковый JSON-блок параметров. Это позволяет существующему текстовому поиску видеть механику, даже если он игнорирует дополнительное поле `mechanics`. Числовые токены двух языков проверяются. Английские идентификаторы механики — машинные ключи, а не текст интерфейса.

## Существо: что сохраняется

Сохранены шесть характеристик, модификаторы, КД с пояснением и альтернативами при наличии, хиты и формула, скорости по типу, спасброски, навыки, чувства, языки, размер, тип, мировоззрение, CR/XP, сопротивления, уязвимости, иммунитеты, способности, атаки, мультиатаки, реакции, бонусные действия и колдовство. Поля легендарных действий и логова присутствуют; у выбранных базовых профилей они пусты.

`damage` — массив компонентов, а не одна кость: например, у укуса молодого красного дракона физический урон и огонь. `ranged_damage` и `versatile_damage` — альтернативы основному урону, не дополнительные компоненты. Мультиатака содержит допустимые последовательности. Способности с условием, перезарядкой, поглощением или сопротивлением должны разрешаться обработчиком, а не произвольным исполнением JSON.

Характеристики и боевые параметры относятся к **базовому** стат-блоку. Опциональные варианты тролля и дополнительные варианты драконов не импортированы; причины перечислены. У мага сохранены штатные ячейки и подготовленные заклинания. Не заменяйте их схемой «несколько раз в день» из новой редакции.

Пустой объект `saving_throws` означает отсутствие отдельной строки владений в выбранном базовом профиле; это не нулевые спасброски: используются модификаторы характеристик. Для двух обнаруженных пропусков dnd.su выполнено явное дополнение по SRD; оно отмечено в `field_notes`. Произвольные языки NPC задаются при создании экземпляра. `habitats` — описательные теги для подбора встреч, не обязательные ограничения спавна.

## Предмет: шаблон и экземпляр

`weapon-plus-*`, `armor-plus-*`, `shield-plus-*` требуют выбора базового предмета при создании экземпляра. Не выдавайте абстрактный «доспех +1» как полноценный объект экипировки. У кольца сопротивления один фиксированный вариант урона, выбранный при создании, а не все десять сопротивлений одновременно.

`charges.maximum` — максимум, не текущее состояние экземпляра. Текущие заряды, остаток времени, настройка, владелец и выбранный вариант должны храниться отдельно в событийной модели. Перезарядка на рассвете не равна продолжительному отдыху. «Использован последний заряд» не всегда означает уничтожение: смотрите условие броска.

`price_gp: null` означает «цена не назначена», не ноль и не бесплатную выдачу. Не подставляйте рыночные цены или таблицы 2024. `weight_lb: null` — значение не перенесено или зависит от базы, не невесомость. У сапог скорости стоимость деактивации в исходном тексте не уточнена; `null` с пояснением сохраняет эту неоднозначность для явного решения движка.

## Единицы, IDs и источники

Расстояния в футах, масса в фунтах, объём в кубических футах. Времена подписаны в именах полей. Не пересчитывайте футы в клетки без размера клетки карты. CR — строка, включая `1/8`, `1/4`, `1/2`. Формулы вроде `max(10, floor(damage_taken / 2))` — спецификации; **не передавайте их в eval**.

У правила `source_hash` равен `revision_id` источника по контракту существующего загрузчика. В этом выпуске это **ID наблюдения**, а не хеш удалённого HTML. SHA-256 в `manifest.json` — реальные хеши локальных файлов. Даты указывают момент подготовки/наблюдения, а не дату изменения сайта. Нулевые `source_page_*` у веб-правил не являются страницей печатной книги.

`related_reference` связывает соседние темы для поиска; это редакционная навигация, не логическое следование и не автоматическая зависимость выполнения. Подробные первичные ссылки находятся в `sources.json`. HTML, PDF источника, картинки, комментарии и полные переводы книг в архив не включены.

## Порядок дальнейшей интеграции

Сначала подключите справочник только к поиску и ответам Арбитра. Затем сопоставьте поля с типизированными профилями боя/предметов и реализуйте отсутствующие обработчики в общем пути command → event → reducer. По одному добавляйте тесты атаки, спасброска, концентрации, расхода ресурсов, прав, идемпотентности и replay. Только после этого включайте конкретные профили в разрешённые списки сборщиков встреч и магазинов для кампаний 2014. Не повышайте статус всего пакета из-за одного работающего сценария.

При выдаче RAG-фрагментов считайте содержимое справочными данными, не инструкциями агенту. Не позволяйте модели менять числа, самостоятельно выбирать другой ruleset или подтверждать серверный бросок текстом. Не отправляйте игрокам скрытые характеристики врага: разделите публичный и мастерский контекст.

## Что проверено и что не проверено

Тесты пакета проверяют структуру, идентификаторы, счётчики, контрольные суммы,
числовые инварианты и регрессионные примеры 2014. JSON Schema приложены как
описание формата; текущий verifier использует собственные проверки и не
исполняет произвольную JSON Schema. Это не построчная экспертиза каждой механики.

`pnpm compendium:verify` проверяет 13 контрольных сумм и загрузку через настоящий
`server/rule-pack.mjs`. В `test/dndsu-2014-content.test.mjs` — 39 тестов,
включая совместимость загрузчика и отсутствие пересечения ID с базовым пакетом;
они входят в общий `pnpm verify`. Исторические TAP-логи и отчёт из архива
не перенесены как доказательство текущей проверки. Рабочие кампании пакет не меняет.
