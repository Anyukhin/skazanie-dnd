# Заказ ассетов: детализация карт

Рабочий лист третьей волны растра (октябрь 2026). Цель — карты уровня
нарисованной вручную боевой карты: тонкие стены вместо стен в целую клетку,
свой пол у каждой комнаты, плотная обстановка гарнитурами, река с набережной,
крупные скалы по краю. Всё ниже нужно и для 2D-доски, и для 3D: 2D берёт
штампы и фактуры, 3D — модели (у части предметов они уже есть в наборах CC0,
для остальных ниже даны промпты генерации 3D).

Стиль — тот же, что у двух готовых наборов: **блок стиля для штампов** из
`docs/prop-stamps-prompts.md`, раздел 2, и **блок стиля для фактур** из
`docs/floor-wall-stamps-prompts.md`, раздел 2. Не менять их между листами —
только так новый растр ляжет рядом со старым без шва в стиле.

## Готовый пакет — 2 октября 2026

По этому заказу подготовлены 34 исходных растровых файла: 19 фактур и 15
листов. В PR добавлен собранный набор `public/assets/maps/detail-v1/`: 19

`model-preview.png` в том же каталоге. `manifest.json` содержит размеры,
футпринты, SHA-256 исходников и готовых файлов, способы создания и хеши рецептов.

Растр создан встроенным инструментом OpenAI ImageGen по запросу владельца.
Инструмент вернул PNG **1254×1254**, несмотря на указанные ниже 2048×2048;
фактический размер записан в манифесте. Исходные листы и отброшенные варианты
сохранены в локальном `assets-src/map-detail/`, который не входит в Git.
GLB созданы из оригинальных геометрических рецептов с помощью установленного
Three.js; сторонний сервис текст→3D не использовался. У каждой модели один
материал, встроенная палитровая текстура, размеры в метрах и не больше 4000
треугольников. Все 64 модели проверены загрузкой и отрисовкой в браузере.

Машиночитаемый заказ — [map-detail-assets-spec-v1.json](map-detail-assets-spec-v1.json).
Повторная сборка из локальных исходников:

```bash
node tools/build-map-detail-assets.mjs --out tmp/map-detail/package
```

Это подготовленный пакет ассетов. Расстановка новых предметов, выбор пола
комнаты, тонкие стены и набережная ещё требуют подключения к существующим
генераторам и рендерам; действующие атласы и закреплённые выпуски карт этой
сборкой не заменяются. Шаги раздела 7 описывают именно последующее подключение.

## 0. Как пользоваться

1. **Фактура** (разделы 2–3): блок стиля фактур + задание. Кадр 2048×2048,
   заполнен целиком, без фона. Правила — раздел 3 документа фактур:
   ровная плотность, ни одного выделяющегося пятна, масштаб задан явно.
2. **Лист предметов** (разделы 4–5): блок стиля штампов + общие правила
   раскладки (раздел 3 документа штампов) + задание листа. Кадр 2048×2048,
   сетка 3×3, фон `#FF00FF`, предмет «лицом» к нижнему краю, пропорция
   рисунка равна футпринту (2×1 — вытянутая полоса, 2×2 — квадрат).
3. Не понравился один предмет — перегенерировать **лист целиком**.
4. Просить у модели **PNG без повторного сжатия** (иначе муар в фоне).
5. Готовые файлы класть в `assets-src/map-detail/` под именами из заданий и
   прислать мне. Дальше я: режу листы (`pnpm props:atlas`), сшиваю фактуры
   (`pnpm terrain:tiles`), заношу предметы в `server/asset-registry.mjs`,
   подключаю 3D, пишу хеши прав (`pnpm props:rights`, `pnpm terrain:rights`)
   и учу генераторы ставить новое.
6. Права: как и у двух прошлых наборов — собственная генерация владельца;
   подтвердить словами, и я запишу это в `docs/map-library.md`.

Порядок сдачи свободный, каждый файл подключается отдельно. Приоритет —
раздел 1.

## 6. Модели 3D

Для предметов с пометкой «генерация 3D». Подойдёт любой генератор
текст→3D, который отдаёт **GLB** (Meshy, Tripo, Rodin и подобные). Стиль
должен совпасть с наборами Quaternius и KayKit, которые уже стоят на доске:
низкополигональный, мультяшный, с плоскими цветами.

### 6.1 Блок стиля 3D — вставлять в каждый промпт без изменений

```
Stylized low-poly fantasy game prop, in the style of Quaternius and KayKit
asset packs: chunky simple shapes, bevelled edges, flat solid colors with a
subtle hand-painted tint, muted earthy palette (warm wood, grey stone, brass,
dark iron, faded red and green cloth). No photorealism, no PBR metal shine,
no fine noise texture. Clean silhouette readable from a top-down camera.

Single isolated object, no ground plane, no base platform unless the object
itself has one, no background, no people, no animals, no text, no logos.
Under 4000 triangles. One material atlas texture, 1024 px or less.
```

### 6.2 Технические требования к файлу

| Что | Требование |
| --- | --- |
| Формат | GLB, одна сетка или группа, без анимации и без скелета |
| Оси | Y вверх, «лицо» предмета смотрит в −Z (к камере по умолчанию) |
| Начало координат | в центре основания предмета, на уровне пола |
| Масштаб | метры: клетка 5 футов = 1,5 м; предмет 2×1 — 3 м на 1,5 м по основанию |
| Высота | по таблице ниже — доска всё равно ограничит её `PROP_MODEL_MAX_HEIGHTS` |
| Имя файла | `<id>.glb`, папка `assets-src/map-detail-3d/` |

### 6.4 Что с моделью потом

Я положу GLB в `public/assets/models/environment/` отдельным набором со своей
записью в манифесте (источник, лицензия, хеш), впишу в каталог моделей
(`src/prop-model-catalog.ts`) и в `PROP_MODEL_MAX_HEIGHTS`. Пока модели нет,
3D-доска строит предмет из простых примитивов (`buildModel` в
`src/board3d-props.ts`), а незнакомый ей вид — запасной фигурой, поэтому
2D-штампы можно подключать раньше 3D: на 3D-доске предмет будет, просто
грубее.

## 7. Что сделаю, когда растр придёт

1. Нарежу листы и сошью фактуры, подключу в манифесты, запишу хеши прав.
2. Внесу предметы в `server/asset-registry.mjs` с футпринтами из таблиц, а
   полы — в материалы карты.
3. Генераторы:
   - у каждой комнаты свой пол по назначению: таверна — тёмные доски, усадьба —
     паркет, кухня — плитка, храм — плиты и мозаика, амбар — солома, улицы
     города — булыжник;
   - стены станут тонкими по рёбрам клеток, со стыками из листа 24;
   - комнаты обставляются гарнитурами (кузня — горн, наковальня, закалка;
     спальня — кровать, комод, ширма; кухня — печь, разделочный стол);
   - у мельницы появятся колесо и жернова, у реки — набережная, лодки и
     камыш, по краю карты — скалы вместо прямой кромки.
4. Проверка карты и эталонные сцены получат новые правила, а 3D-доска —
   модели.
