# Браузерная проверка игры 4 октября 2026 года

**Аудит завершён по просьбе владельца.** Сохранены два завершённых цикла
с 11 игровыми протоколами, план исправлений и доказательства. Третий цикл
не завершён и отдельно описан в [границах проверки](cycle-03-incomplete.md).
Новые прохождения не запланированы автоматически. PR #132 не слит в `main`.

Проверка актуального `main` проекта «Сказание» через основной пользовательский
интерфейс. Результат — предложения по исправлениям и развитию, а не изменение
игровой механики. Отчёт предназначен для выбора следующих задач разработки.

Создание героев, базовый бой, внебоевая магия, торговля, передача предметов и
сохранение двух игроков после restart прошли проверенные сценарии. Основные
препятствия обнаружены в продолжении истории: повреждённое назначение
голосования, непонятный переход по найденной улике и устаревшая цель после
прибытия. Позитивный финал приключения на пройденном маршруте не достигнут.
Во втором цикле подтверждены пустой бой с ложной победой и открытие
несвязанного контейнера по фразе о рычаге и двери; оба вывода проверены по
ограниченным выборкам событий после браузерного прохождения.

Начать чтение стоит с [сводного плана конкретных изменений](proposals.md).
В текущем PR меняется только документация и доказательства; исправления
продукта предлагаются для последующей реализации.

## Проверяемая версия и метод

- Репозиторий: `Anyukhin/skazanie-dnd`.
- Перед началом выполнен `git fetch origin --prune`.
- Первый игровой цикл: `c7efdca614cc33f706258d036e86f01c1f189404`
  (`Merge pull request #124 from Anyukhin/claude/first-evening-release`).
- Отдельная рабочая копия и ветка `codex/browser-playtest-2026-10-04`.
  Незакоммиченные изменения исходного каталога не входят в проверку.
- Обычные тестовые учётные записи, отдельное временное хранилище.
  Подготовка администратора и учётных записей — настройка стенда;
  кампании, герои и игровые действия создаются через интерфейс.
- Агенты наблюдают текущий DOM и изображения страницы, затем нажимают кнопки
  и вводят текст. Запросы к API и подмена состояния не заменяют игровой маршрут.
- Каждый маршрут сопровождается наблюдениями и снимками экрана. Чтение кода
  после воспроизведения помогает выбрать место будущего исправления, но само
  по себе не доказывает пользовательскую ошибку.

Приложение собрано штатным `pnpm build`, зависимости установлены по
`pnpm install --frozen-lockfile`. Сервер слушает `127.0.0.1:8891`; локальные
прокси на `127.0.0.11–.13`, `127.0.0.15–.18` разделяют cookies игроков по
хостам и сохраняют `Host`/`Origin`. Все эти адреса ведут к одному серверу и
хранилищу. `/api/health` ответил `200`, провайдер RouterAI настроен; фактическая
работа генерации проверяется в маршрутах. Генерация изображений во время игры
выключена. Ключи, cookies и пароли тестовых учётных записей в отчёт не включены.

В начале Node не доверял цепочке сертификатов провайдера
(`SELF_SIGNED_CERT_IN_CHAIN`). Сервер перезапущен с `NODE_USE_SYSTEM_CA=1`,
с тем же хранилищем и с включённой проверкой TLS. После этого штатный
`llmClient.probe()` подтвердил готовность всех пяти настроенных автоматических
моделей. Ранние сцены с резервным рассказчиком отмечены в протоколах отдельно;
их художественное качество не используется для выводов о живой модели.

В первом цикле пять маршрутов агенты прошли в собственных браузерных сессиях. Для маршрута
двух игроков браузер не был доступен назначенному агенту: клики и ввод
выполнил главный агент, а назначенный агент разобрал переданные наблюдения
и подготовил протокол. Это ограничение инструмента, а не дефект продукта.

Во время проверки `main` обновился до
`e1d927f5aa68dc9eca912b527cccf3974ba3e9e7` (PR #123, #125–128). Перед итоговым
gate ветка отчёта обновлена до него fast-forward. Входящие изменения касаются
геометрии, декора и отображения карт; в `DungeonMap.tsx` изменена легенда высот.
Проверенные участки маршрутизации, квестов, создания героя, магии и торговли
этими коммитами не исправлялись. Первый игровой цикл относится к `c7efdca6`;
второй — к `7c1dd98` на кодовой базе `e1d927f`. Во втором цикле заново
созданы и проверены две карты после этих изменений. Это не проверка всех
сидов и типов карт; старые визуальные замечания нельзя переносить автоматически.

## Как читать результаты

**Дефект** — наблюдаемое расхождение с обещанием интерфейса, правилами
закреплённой редакции или документированным поведением. **Предложение** —
улучшение, которое требует продуктового решения. **Известное ограничение**
сопоставляется с `docs/known-limitations.md` и не объявляется новой поломкой.

P1 означает остановку существенного игрового маршрута или неверный
подтверждённый результат; P2 — помеху с обходным путём; P3 — улучшение ясности
или удобства. Серьёзность определяется последствиями для игрока.

Не достигнутый этап отмечается как непроверенный. Отсутствие ошибки в одном
маршруте не доказывает полноту D&D, всех классов, заклинаний или генераторов.
