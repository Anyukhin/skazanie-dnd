# Предложения по результатам браузерной проверки

Это очередь предлагаемых доработок для версии `c7efdca6`, а не перечень уже
внесённых исправлений. Полные шаги и границы каждого наблюдения находятся в
[протоколах](README.md#протоколы). Однотипные наблюдения разных игроков
объединены; успешные проверки и гипотезы не посчитаны отдельными багами.

## Сначала непрерывность приключения

### 1. Сохранять назначение перехода независимо от подписи голосования

**P1, [QP-05](quest-progression.md).**
После голосования действительно создано место `«Другой п`: это полное имя
в сохранённой хронике, а не только визуальное многоточие заголовка.
Главный агент повторно открыл кампанию и подтвердил результат в
[тексте хроники](../evidence/playtest-2026-10-04/quest-root-chronicle.txt).

Проследить `request_party_decision` в `server/index.mjs`,
`interpretResolvedPartyDecision` в `server/scene-architect.mjs` и
`server/party-exit-intent.mjs`. Исполнение должно использовать полное
проверенное назначение, а сокращённая подпись — только отображаться игроку.
Переиспользовать существующие структурированные поля маршрута, где они уже
есть; новые поля добавлять обратно совместимо. Для старых interaction без
полных данных неполный адрес нужно уточнять, а не превращать в новую локацию.
Фразу «найти другой путь» отдельно проверить на ошибочное прочтение как имени
места.

**Приёмка:** длинное исходное место и длинная цель дают полный проверяемый
маршрут; короткая подпись не меняет результат. Повтор команды и replay ведут
в то же место. В браузере пройти голосование двумя игроками и проверить
заголовок, карту мира и хронику после restart.

### 2. Давать выполнимый следующий шаг после улики

**P1 для пройденного маршрута, [QP-06](quest-progression.md).**
После успешного осмотра рассказ сообщил о следах к старой арке. Две конкретные
попытки пойти туда были отклонены, а вопрос о дороге не дал направления.
Сохранённая [хроника](../evidence/playtest-2026-10-04/quest-root-chronicle.txt)
содержит всю последовательность. Финал на этом маршруте не достигнут.

В `server/player-request-router.mjs`, `server/party-exit-intent.mjs` и
`server/world-memory.mjs` сначала установить, является ли арка существующим
публичным местом, объектом текущей сцены или лишь текстом рассказчика. Для
подтверждённого места выдавать доступный переход/действие с его ID; для
неподтверждённой детали уточнять действие и не обещать готовую дорогу.
Не создавать авторитетный waypoint только потому, что модель упомянула его.

**Приёмка:** через основной сайт пройти «проверка → подтверждённая улика →
следующий шаг → новая сцена». Отдельно проверить неизвестное название,
локальный объект вместо локации и недоступную модель. Ни отказ, ни уточнение
не должны расходовать игровые ресурсы или закрывать цель.

### 3. Согласовать публичные зацепки и знания NPC

**P2, [QP-01](quest-progression.md).**
Публичный план города называет Мару обнаружившей подмену рейки, а адресованный
ответ Мары отрицает знание этой подмены. Проверить отбор фактов в
`server/npc-social-controller.mjs` (`briefFor`, `npcFacts`) и передачу
публичных city hooks из `server/world-map.mjs`.

Передавать только уже раскрытые сведения, относящиеся к NPC и месту; при
расхождении отличать подтверждённый факт, слух и ложь персонажа. Не открывать
игроку скрытые city hooks и не добавлять в этот PR новый тип события лишь ради
проверки текста. **Приёмка:** контекст NPC содержит разрешённую зацепку;
ответ не отрицает её случайно, закрытая информация остаётся закрытой.

### 4. Делать цель и продолжение маршрута понятными

**P2, [SE-11 и SE-14](social-exploration.md), [QP-04](quest-progression.md).**
В промежуточной локации продолжение нашлось через «Решение группы», хотя
заголовок цели и «продолжим» не помогли. После прибытия в Дормар осталась цель
«Продолжить путь из Айрская башня к “Дормар”» — главный агент подтвердил это
после нового открытия страницы.

У существующего перехода показывать явное действие «Продолжить маршрут».
Проверить обновление travel objective в `server/scene-architect.mjs`,
`server/scene-memory.mjs` и маршрутах `src/App.tsx`; сбрасывать только
достигнутую промежуточную цель, сохраняя незавершённые задания. В журнале
`src/AppViews.tsx` отличать главную цель от переносимых сюжетных нитей.
**Приёмка:** маршрут A → B → C предлагает следующий шаг в B и перестаёт
отправлять в C после прибытия; две настоящие параллельные задачи сохраняются.

## Отдельные продуктовые решения

- **Отдых после победы — известная политика, а не новая ошибка расчёта.**
  [MC-03](martial-combat.md) показывает, что «Продолжим» неожиданно для игрока
  запускает восстановление с продвижением времени. Минимальная доработка —
  заранее объяснить длительность и эффект. Удаление или изменение
  `post_encounter_recovery` в `server/autonomous-orchestrator.mjs` требует
  отдельного решения и проверки последствий для павших героев.
- **Награде встречи нужна видимая сводка** ([MC-05](martial-combat.md)).
  Показывать предметы и происхождение после `EncounterRewardsDistributed`,
  используя результат команды в `server/index.mjs`/`src/useGameSession.ts`.
  Не создавать труп с инвентарём волку: награда встречи и добыча с тела — разные
  механики, для первой `LootPanel` не является владельцем.
- **Резервный ведущий должен честно описывать свои границы**
  ([MC-01](martial-combat.md), [QP-02](quest-progression.md),
  [SE-04](social-exploration.md)). Не повторять весь пролог вместо ответа и не
  утверждать присутствие конкретного противника без готового NPC/encounter.
  Начинать с `fallbackOpening` и `fallbackDisclosure`; не добавлять LLM в
  горячий путь обычных действий.
- **Копия карты в рассказе и предмет в сумке — разные результаты**
  ([QP-07](quest-progression.md)). Если подтверждена только запись знания,
  сказать «сохранено в хронике». Создание документа требует обычного
  серверного пути предмета и проверки нужных материалов, а не только текста.
- **Мелкие улучшения:** переиспользовать `spellRangeLabel` для «Касание»
  ([MG-03](magic.md)); добавлять расстояние и подсказку подхода к объектам
  ([SE-13](social-exploration.md)).

## Что сначала нужно воспроизвести точнее

- **QP-03:** нулевой счётчик при содержательном тексте улики ещё не доказывает
  отсутствие `WorldFactRecorded` или ошибку clocks. Связать конкретный бросок,
  proof fact, ID цели и её допустимый следующий переход на реальном
  `/api/narrate` пути. Не продвигать произвольную цель за каждый успешный бросок.
- **OB-03:** пустая начальная панель магии — наблюдение; в коде уже есть
  автоматическое заполнение. Проверить загрузку проекции и сохранённую
  раскладку в чистой сессии, прежде чем менять зависимости эффекта.
- **MG-04:** временное различие DOM-счётчиков после отдыха — кандидат на гонку,
  без установленной причины. Записать оба значения одновременно после
  завершения команды и исключить переходное состояние запроса. Серверная
  потеря ячеек не доказана.
- **OB-04:** одна улика может поддерживать две задачи. Проверять дублирование
  самих задач и ясность названий, а не запрещать несколько связей факта.

Для реализации использовать существующие `node:test`-сторожа и ручную
браузерную приёмку, не добавляя тестовый фреймворк или новые зависимости.
Серверные изменения сохраняют авторизацию, проекцию видимости, идемпотентность
и старый replay. После каждого выбранного изменения нужен `pnpm verify`;
этот отчёт не заменяет повторного прохождения исправленного сценария.

## Минимальное воспроизведение разбора повреждённого назначения

Выполнено после браузерного QP-05 на том же commit. Команда не меняет игру и
не вызывает модель: она воспроизводит нормализацию подписи из
`request_party_decision` и передаёт её настоящему классификатору. Это
локализация причины; отдельный HTTP-тест сохранения interaction ещё нужен.

Из корня репозитория в PowerShell:

```powershell
@'
import { proposeAgentInteraction } from './server/player-request-router.mjs';
import { classifyPartyDecision } from './server/party-exit-intent.mjs';
const destination = 'Старая арка у провала после соляных складов другой путь к разгадке';
const state = {
  scene: { location: 'Смотровая дамба' },
  worldMemory: { quests: [{ id: 'quest:main', title: 'Найти следы', status: 'active' }] },
};
const card = proposeAgentInteraction('Отправляюсь в «' + destination + '»', state);
const raw = card.options[0];
const persisted = raw.replace(/\s+/gu, ' ').trim().slice(0, 100);
console.log(JSON.stringify({
  rawLength: raw.length, persistedLength: persisted.length,
  classified: classifyPartyDecision(persisted),
}));
'@ | node --input-type=module
```

Получено: `rawLength: 105`, `persistedLength: 100`,
`classified: {kind: "move", destinationHint: "разг", abandonsQuest: false}`.
Ожидание будущего исправления — полное назначение сохраняется отдельно от
укороченной подписи, а повреждённые старые данные не порождают новое место.
