# Записи решений

Запись решения, или ADR, объясняет важный технический выбор, для которого были
реальные альтернативы и долговременные последствия. Она не пересказывает diff,
не заменяет спецификацию возможности и не создаётся ради каждого нового модуля.

## Когда создавать

ADR оправдана, если решение:

- задаёт авторитетный путь изменения состояния или границу доверия;
- выбирает формат события, хранения, совместимости или миграции;
- влияет на несколько будущих доработок;
- принимает осознанное ограничение или технический долг;
- будет трудно понять или безопасно изменить только по текущему коду.

Принятая ADR не переписывается задним числом. Исправления фактов допустимы, но
новый выбор оформляется следующей записью, которая помечает предыдущую как
`заменена`.
