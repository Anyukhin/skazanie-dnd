# Что нужно сгенерировать взамен удалённых ассетов

Ассеты с неподтверждёнными правами удаляются, чтобы репозиторий можно было
сделать публичным. Здесь записано, что именно ушло и чем это заменить.

Решение владельца от 2026-07-26: набор Dyson Logos и портреты противников не
нужны, заменяются собственной генерацией.

Доска обязана оставаться играбельной без арта — это решение Р6 из
`docs/tactical-map-plan.md`, и оно соблюдается: доска рисуется по данным, а не
по картинке.

---

## 1. Иллюстрации карт — набор Dyson Logos

**Закрыто 2026-07-30.** Удалённый набор заменён пятью собственными светлыми
top-down фактурами в `public/assets/maps/library/skazanie/`. Промпты и
происхождение записаны в `docs/board-backdrop-prompts.md`, хеши — в
`data/asset-rights.json`.

Удалено пять файлов из `public/assets/maps/library/dyson-logos/`:

| Категория | Файл | Чем был |
| --- | --- | --- |
| `cave` | `dyson-logos-cavern.webp` | пещера |
| `dungeon` | `dyson-logos-dungeon.webp` | подземелье |
| `tavern` | `dyson-logos-estate.webp` | интерьер, усадьба |
| `temple` | `dyson-logos-temple.webp` | храм |
| `village` | `dyson-logos-village.webp` | поселение |

**Зачем они были нужны.** Одна иллюстрация нарезалась по всем клеткам общей
системой координат и давала атмосферный фон доски. Механику она не определяла:
нарисованный проход не становился проходимым, если его нет в структурированной
карте.

**Как заменено.** Фон не дублирует планировку: это низкоконтрастная бесшовная
фактура без нарисованных стен, дверей, сетки и объектов. Серверная карта
по-прежнему остаётся единственным источником проходимости и коллизий.

## 2. Портреты противников

Удалено одиннадцать файлов из `public/assets/enemies/`. Их подставляют профили
из `SRD_5_2_1_MONSTER_ALLOWLIST` в `server/encounter-assembler.mjs`, поле
`image`, и показывает фишка противника на доске.

| Нужен портрет | Кто это |
| --- | --- |
| `goblin` | гоблин-налётчик и гоблин-воин, один портрет на двоих |
| `hobgoblin` | хобгоблин |
| `orc` | орк |
| `kobold` | кобольд |
| `skeleton` | скелет |
| `zombie` | зомби |
| `wolf` | волк |
| `giant-rat` | гигантская крыса |
| `giant-spider` | гигантский паук |
| `giant-wolf-spider` | гигантский паук-волк |
| `bugbear` | багбир |

**Замена нужна.** Без картинки фишка противника показывает векторный значок
`EnemyGlyph` по виду существа — играбельно, но безлико.

**Требования к генерации.** Портрет, а не вид сверху: он показывается на фишке и
в ленте инициативы, обрезается кругом. Значит — поясной или погрудный кадр,
существо смотрит в кадр, фон простой и тёмный, без текста и рамок. Стиль общий
для всех одиннадцати, генерировать одним листом или подряд в одной сессии.

Размер по факту прежних: около 250×250, формат webp.

---

## 3. Что сделать после генерации

1. Положить файлы по прежним путям — тогда код менять не придётся, поля `image`
   в профилях противников и маршрутизация библиотеки карт уже указывают туда.
2. Зарегистрировать хеши в `data/asset-rights.json` с источником и датой.
3. Перевести `rights_status` с `review_required` на решённый и
   `default_distribution` с `blocked` на выбранный.
4. Поднять счётчик ассетов в `test/content-integrity.test.mjs` под фактическое
   число.
5. Прогнать `pnpm verify` и `node tools/verify-content-integrity.mjs --release`.
