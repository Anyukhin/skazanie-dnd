# Трек `claude/loop-ui` — интерфейс

Бриф для длительного автономного агента. Он перечитывается **в начале каждой
итерации**: у цикла нет общей памяти между запусками, вся преемственность живёт
в журнале и в истории ветки.

## Дерево и ветка

| | |
| --- | --- |
| Ветка | `claude/loop-ui` |
| Базовая ветка | `main` |
| Журнал | `docs/loop-ui-journal.md` (в git, коммитится вместе с работой) |

Первым делом — четыре проверки из `AGENTS.md` §10:

```bash
pwd
git branch --show-current    # обязано быть claude/loop-ui
git status --short           # чужие правки — это стоп, а не фон
ls node_modules/typescript   # зависимости на месте
```

Ветка не та или в дереве чужое — **остановиться и написать пользователю**. Не
переключать ветку, не прибирать чужое.

## Что читать перед работой

1. `docs/loop-ui-journal.md` — что уже сделано, что отложено и почему.
2. `docs/product-principles.md` — каким продукт обязан быть. При расхождении с
   реализацией правда за документом.
3. `docs/interface-interaction-audit.md` — разобранный список дефектов с
   критериями приёмки, это основной источник задач.
4. `AGENTS.md` §4 (карта кода), §6 (порядок реализации), §8 (критерий готовности).

## Границы владения

Правишь только это:

```
src/**   public/**   index.html   vite.config.ts
tools/build-icon-*.mjs
docs/interface-*.md   docs/loop-ui*.md
test/ui-*.test.mjs        # свои тесты заводить только с этим префиксом
```

Не трогаешь **никогда**: `server/**`, `data/**`, `storage/**`, `.env`,
`prompts/**`, `eval/**`, `AGENTS.md`, `README.md`, `package.json`,
`pnpm-lock.yaml`, `Dockerfile`, `compose.yaml`, `.dockerignore`.

Параллельно на ветке `claude/loop-rules` работает второй агент и владеет
`server/**`. Если задача упирается в сервер — она **не твоя**: запиши её в
журнал разделом «Требует серверной правки» и возьми следующую.

## Одна итерация — одна задача

Расширение объёма за пределы одной задачи — повод откатить работу целиком, даже
если код выглядит хорошим: иначе утреннее ревью не отличит нужное от попутного.

Порядок:

1. Прочитать журнал, выбрать **одну** следующую задачу по приоритету.
2. Воспроизвести дефект и записать, чем именно он подтверждён.
3. Починить минимальным изменением.
4. Проверить (ниже).
5. Закоммитить перечислением файлов.
6. Дописать журнал и закоммитить его тем же коммитом.

Если задача оказалась больше, чем на одну итерацию — разбей её и сделай первый
кусок, а остаток запиши в журнал. Незавершённое в коммит не идёт.

## Стартовый бэклог

Приоритет P1 → P2 → P3. Формулировки и критерии приёмки — в
`docs/interface-interaction-audit.md`, здесь только очередь.

**P0 — заведено 2026-07-27, вне аудита**

- `vite.config.ts` жёстко проксирует `/api` и `/generated` на `127.0.0.1:8787`.
  Пока порт не читается из окружения, свой экземпляр приложения не поднять и
  визуально проверить правку негде. Сделать это первой задачей.
- 532 отдельных PNG в `public/assets/ui/action-icons/` (35 МБ) вместо прежнего
  атласа. Даже с кешем холодная загрузка тяжёлая. В `data/asset-rights.json`
  числится `ui/action-icons/action-atlas-v1.webp` на 654 КБ — разобраться,
  можно ли вернуться к атласу или хотя бы грузить рисунки лениво. Реестр прав
  правит другой трек, поэтому изменения `data/` только предложить в журнале.

**P1** — пункты 1–4 аудита: обрезка маркеров краем карты, история поверх
маркеров, конфликт вращения с кликами, размер маркеров на мобильном.

**P2** — пункты 5–8: история закрывает свободный бросок, текст кнопки
«Пригласить», изоляция мобильного меню, горизонтальный scrollbar свёрнутой
панели.

**P3** — пункты 9–10: сброс камеры при переходе между разделами, индикация угла
и управляемый возврат.

**Дальше — своя разведка.** Когда список закончится, ищи новое сам, но проверяй
находку на продуктовых принципах, а не на вкусе:

- принцип 2 «предложения интерфейса не являются границами» — свободный ввод
  действия обязан быть доступен на любом экране, где действие вообще возможно;
- принцип 3 «никаких невидимых сюжетных стен» — запрет обязан объясняться
  конкретной причиной, а не молчаливо неактивной кнопкой;
- статусы механики `verified` / `partial` / `heuristic` / `ruling-only` обязаны
  быть видны игроку и отличимы друг от друга (`docs/known-limitations.md`);
- клиент не авторитетен: интерфейс показывает проекцию и отправляет намерения,
  он не считает урон, дальность и видимость сам.

## Проверка

Обязательна до коммита, полностью:

```bash
pnpm verify        # tests + typecheck:server + build
```

Дополнительно для правок, которые видно на экране:

```bash
AGENT_PORT=8788 pnpm dev:agent
pnpm dev:client -- --port 4174
```

и смотреть глазами через браузер. `storage/` у дерева своё, чужую игру этим не
испортишь. Порт 8787 не занимать — он может быть занят приложением пользователя.

`pnpm content:verify` и `pnpm cutover:audit` красные по построению
(`docs/production-readiness.md`) — это не регрессия.

Красная проверка — работа не коммитится. Откатить (`git restore` по своим
файлам), записать в журнал, что не получилось и почему, взять следующую задачу.

## Коммит

```bash
git add <перечислением файлов>      # никогда -A и не commit -a
git branch --show-current           # сверить перед коммитом
git commit
```

Сообщение — по-русски, в повелительном наклонении, с объяснением **почему**, а
не только что. В коммит не должно попасть ни одного файла вне списка владения.

После зелёной проверки — выложить **свою и только свою** ветку, чтобы результат
был виден с любой машины:

```bash
git push origin claude/loop-ui
```

Не делать: `push` в `main` или в чужую ветку, `push --force` в любом виде,
`merge`, `rebase`, `checkout` другой ветки, `reset --hard`, работу в чужих
каталогах. ПР не открывать — ветку разберёт пользователь.

## Когда остановиться и написать пользователю

- Бэклог кончился и новых обоснованных находок нет.
- Задача противоречит `AGENTS.md` или `docs/product-principles.md`.
- Проверка красная три итерации подряд по одной причине.
- В дереве появились чужие изменения.
- Требуется правка вне границ владения, без которой дальше нельзя.

Молча выбирать между противоречащими требованиями — нельзя. Записать вопрос в
журнал и остановиться.
