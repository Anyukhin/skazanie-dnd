# Трек `claude/loop-immersion` — погружение: рассказчик, режиссура, мир

Бриф для длительного автономного агента. Перечитывается **в начале каждой
итерации**: у цикла нет общей памяти между запусками, вся преемственность живёт
в журнале и в истории ветки.

Цель трека — чтобы партия за столом чувствовала живой мир: рассказчик помнит
историю, NPC звучат как люди, кампания разнообразна на длинной дистанции.
Серверный авторитет неприкосновенен: модель рассказывает, сервер считает.

каждому своя копия репозитория.

## Инварианты — нарушение любого = откат итерации

- Модель не назначает урон, КД, СЛ, координаты, цены, награды, исходы. Она
  рассказывает и предлагает; сервер выбирает и проверяет числа.
- В LLM уходит только party-видимое: цели и убеждения профиля NPC, gm_only
  факты и скрытые параметры врагов не попадают в бриф ни одним путём. Всё,
  что ушло в модель, может дословно оказаться в тексте перед игроком.
- Каждый вызов `completeJson` собирает user-сообщение через
  `buildDataOnlyContext` — сторож `test/injection-surfaces.test.mjs`.
- Replay/restart идентичны; idempotency сохраняется.
- `heuristic`/`ruling-only` не исполняются молча.

## Живые вызовы модели — по умолчанию нет

Ключ может лежать в `.env`, но живой вызов тратит деньги пользователя.
Правила прежние: живые прогоны только если пользователь явно разрешил их в
задании; не больше **20** вызовов за итерацию; количество и токены — в журнал.
Всё остальное проверяется подставным клиентом. Раннер
`eval/live-narrator-eval.mjs` — образец: жёсткий предел `--max-calls`,
детерминированные судьи, отчёт в git.

## Стартовый бэклог

Приоритет P1 → P2 → P3. Одна итерация — одна задача.

### P1 — рассказчик и честность текста

1. **Verifier не ловит семантические изменения мира.** Живой eval поймал:
   рассказчик описал передачу предмета («достаёт свиток — обещанное
   сокровище») без события. Расширить `WORLD_CHANGE_ASSERTION_PATTERN`
   (`server/security.mjs`) на передачу/получение предметов (вруча\w*,
   переда\w*, достаёт и отдаёт, вкладывает в руки…) под constraint
   `no-unconfirmed-world-changes`. Осторожно с ложными срабатываниями:
   сначала корпус примеров в тесте, потом паттерн.
2. **`permitted_npc_reactions` всегда пуст в основном пути.**
   `game-orchestrator.mjs` передаёт `[]`; наполнить bounded-реакциями
   присутствующих NPC (по `story_context.present_npcs`): кто может видимо
   отреагировать и как (нахмуриться, насторожиться, шепнуть) — presentation,
   не механика. Критерий: реакции только для party-видимых NPC текущей
   локации, не больше 3, промпт narrator объясняет их назначение.
3. **Детерминированный fallback сух.** Когда все модели недоступны, игрок
   видит «Проверка Харизмы: 15 против СЛ 12». Расширить
   `deterministic-narration.mjs`: шаблонные, но живые фразы по типу события и
   `story_context` (место, имя NPC), без случайности — replay обязан давать
   тот же текст.
4. **Расширить живой eval.** Добавить сценарии: критический момент боя
   (падение героя), торговый диалог, переход сцены; вести журнал прогонов
   (дата, модель, счёт) в `docs/live-narrator-eval.md`. Только по явному
   разрешению пользователя на живые вызовы.

### P2 — режиссура длинной кампании

5. **Контентные таблицы встреч и лута ограничены** (4 темы, 3 tier’а —
   `docs/autonomy-readiness-audit.md`). Расширить server-owned таблицы
   (`encounter-assembler.mjs`, loot policy) до 8–10 тем с bounded-структурой;
   каждая тема — детерминированный тест сборки.
6. **Автономная тактика примитивна:** герои и NPC «подойти и ударить».
   Server policy выбора действий из уже исполняемых: лечение союзника при
   низких HP, контроль при скоплении врагов, отход стрелка из ближнего боя.
   Только typed commands и `verified`-карточки; никаких вызовов LLM в тактике.
7. **Репутация записывается, но ни на что не влияет.** Прокинуть
   faction/witness события в социальные политики: tier отношений и репутация
   фракции двигают цены торговца (bounded basis points), готовность NPC
   говорить, доступность услуг. Каждый эффект — отдельное правило с тестом.
8. **Арки кампании.** Milestone-прогрессия: завершение квеста главы создаёт
   `MilestoneAwarded`, N milestone — предложение уровня; финал главы пишет
   session summary и открывает downtime-активности. Всё событиями, replay-stable.

### P3 — подготовка к мультиплееру (серверная часть)

9. **SSE-поток вместо polling.** `campaignStreams` в `server/index.mjs` уже
   есть — довести до полного канала: события комнаты пушатся подписчикам,
   polling остаётся fallback. Клиентская подписка — «Требует правки
   интерфейса», записать в журнал.
10. **Per-player projection дальше:** знание героя (`knowledge_ledger`) уже
    личное; проверить, что SSE/poll отдают каждому игроку только его
    проекцию, и закрыть тестом на two-viewer расхождение.

**Дальше — своя разведка** по осям: причинность мира (решения влияют на
будущие сцены), разнообразие (одинаковые ли встречи/лавки/реплики на длинной
кампании), честность (текст не обещает того, чего нет в событиях).

## Проверка

Обязательна до коммита, полностью:

```bash
pnpm test                # база: 3 известных падения content-integrity, ни одним больше
pnpm typecheck:server    # строго 0 ошибок
pnpm build               # строго 0 ошибок
```

`pnpm content:verify` и `pnpm cutover:audit` красные по построению — это не
регрессия. Порт 8787 не занимать: `AGENT_PORT=8788 pnpm dev:agent`.

Красная проверка — работа не коммитится: откатить, записать причину, взять
следующую задачу.

## Коммит

```bash
git add <перечислением файлов>      # никогда -A и не commit -a
git branch --show-current           # сверить перед коммитом
git commit
git push origin claude/loop-immersion
```

Сообщение — по-русски, в повелительном наклонении, с объяснением **почему**.
Не делать: `push` в `main` или чужую ветку, `--force`, `merge`, `rebase`,
`checkout` другой ветки, `reset --hard`. ПР не открывать — ветку разберёт
пользователь.
