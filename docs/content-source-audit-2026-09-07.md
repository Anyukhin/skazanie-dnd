# Аудит источников контента 2014 — 2026-09-07

Проверен текущий рабочий снимок репозитория на 2026-09-07. Аудит ограничен
существующим compatibility-каталогом из 439 заклинаний, расширением 2014 из
32 предметов и 24 существами, а также уже работающими каталогами предметов и
врагов. Новые записи с сайта не импортировались. Описания и изображения с
dnd.su не копировались.

## Как читать dnd.su

Для редакции 2014 проверялись страницы с явным хостом `5e14.dnd.su`: [каталог
заклинаний](https://5e14.dnd.su/spells/), [магических
предметов](https://5e14.dnd.su/items/) и [бестиария](https://5e14.dnd.su/bestiary/).
На карточках редакция видна по меткам `PH14`, `DMG14` и `MM14`. Например,
[Сопротивление](https://5e14.dnd.su/spells/332-resistance/) помечено `PH14`,
[Гоблин](https://5e14.dnd.su/bestiary/4-goblin/) — `MM14`, а [Зелье
лечения](https://5e14.dnd.su/items/61-potion-of-healing/) — `DMG14`.

Хост `5e14` не означает, что каждая карточка относится к базовым книгам 2014:
сайт также показывает официальные дополнения. [Расщепление
разума](https://5e14.dnd.su/spells/3050-mind-sliver/) и [Призыв духа
зверя](https://5e14.dnd.su/spells/3063-summon-beast/) помечены `TCE`, а [Искусная
острота](https://5e14.dnd.su/spells/3946-silvery-barbs/) — `SCC`. Это выпуски
после 2014 года, поэтому их нельзя молча считать частью core `PHB14`/`DMG14`/
`MM14`. Отдельный сайт [next.dnd.su](https://next.dnd.su/) прямо описывает себя
как справочник ревизии 2024 года; его страницы нельзя использовать для
заполнения полей 2014.

Основные правила формата сверялись с [использованием
заклинаний](https://5e14.dnd.su/articles/mechanics/157-spellcasting/) и
[описанием блока
статистики](https://5e14.dnd.su/articles/mechanics/485-bestiary/). Для
снаряжения использовалась [таблица немагического
инвентаря](https://5e14.dnd.su/articles/inventory/147-armor-arms-equipment-tools/).

Таким образом, число **107 предметов и 50 врагов** нельзя выдавать за объём
2014-каталога. Для 2014 сейчас корректная статистика — **32 магических предмета,
24 существа и 439 карточек compatibility-заклинаний**. Предметы остаются
`data_only`; 24 reference-существа уже частично исполняются на арене через
`combat-lab-monsters`, но это не полный runtime cutover. Расширение 2014 также содержит 91 структурированное
правило, 91 термин, 81 связь и 56 записей источников; эти числа не являются
числом предметов, заклинаний или существ.

## Заклинания: найденные расхождения

В `dndsu-spells-0-6.json` у всех 439 карточек есть имя, уровень, школа, классы,
время, дистанция, длительность и `sourceUrl`, но отсутствуют поля
`edition_family`/`book_code`/`source_ref`. Все 439 `sourceUrl` ведут на
`www.dnd.su`, а не на зафиксированную карточку `5e14` с меткой книги. Поэтому
каталог нельзя отфильтровать до core 2014 без повторной сверки каждой записи.
В нём фактически присутствуют как PHB14, так и дополнения `TCE`, `SCC` и другие
официальные книги. Поля `sourceUrl` достаточно для справочной ссылки, но
недостаточно для механического allowlist.

Исходный baseline до волны правки описаний (2026-09-07): **149 raw markers** из
439 карточек — 98 раз
`«особый или внебоевой эффект»`, 33 раза `buff` и 18 раз `summon`. Это не
полное описание заклинания и не основание для исполнения правила. После
переделки текстов этот подсчёт нужно повторить и запретить такие значения
проверкой качества. Описание должно оставаться самостоятельным пересказом,
без копирования абзацев dnd.su.

Критический edition mismatch — `resistance`. 2014-карточка [PH14
Resistance](https://5e14.dnd.su/spells/332-resistance/) говорит о касании
существа, одном к4 для одного спасброска и завершении заклинания после броска.
В локальном override `resistance` описано другое правило: выбор типа урона и
снижение каждого подходящего урона на 1к4 раз за ход. Именно это правило
показывает [карточка Resistance ревизии
2024](https://next.dnd.su/spells/10625-resistance/). Override должен быть
разделён по редакциям или явно помечен как compatibility house rule. Нельзя
менять уже сохранённые события существующих кампаний.

Три проверенных страницы подтверждают границу дополнений: `Mind Sliver` и
`Summon Beast` имеют метку `TCE`, `Silvery Barbs` — `SCC`. Рекомендация —
добавить к каждой spell-записи `edition_family`, `book_code`, `source_ref` и
`allowlist_scope` (`core`/`supplement`), затем оставить дополнения отдельным
opt-in-пакетом. Удалять их из текущего compatibility-снимка без миграции не
нужно; достаточно не разрешать их в core 2014.

## Предметы: что совпало и что ещё отсутствует

Проверенные 2014-предметы структурно переданы аккуратно:

- [Зелье лечения](https://5e14.dnd.su/items/61-potion-of-healing/) содержит
  четыре варианта силы; локальные четыре записи поэтому считаются отдельными
  вариантами корректно.
- [Оружие +1/+2/+3](https://5e14.dnd.su/items/160-weapon-1-2-3/), [доспех
  +1/+2/+3](https://5e14.dnd.su/items/33-armor-1-2-3/) и щит разделены по
  редкости, но локальная модель требует выбрать базовый предмет. Это правильно:
  абстрактный «доспех +1» не заменяет тип доспеха.
- [Кольцо сопротивления](https://5e14.dnd.su/items/107-ring-of-resistance/)
  даёт один выбранный вид сопротивления; локальная запись хранит десять
  вариантов и не выдаёт все виды сразу.
- [Сумка хранения](https://5e14.dnd.su/items/227-bag-of-holding/) имеет
  ограничения массы, объёма, воздуха и взаимодействия с межпространствами;
  эти факты присутствуют в локальном структурированном описании.

Все 32 записи имеют `book_code: DMG14`, `full_source_text_included: false`,
`description_origin: independent_short_mechanical_summary` и
`mechanics_status: data_only`. У них нет runtime handler-а, command/event/reducer
пути, генерации экземпляра и пользовательского сценария. Их нельзя считать
«готовыми в игре» только потому, что JSON и схема валидны.

Рабочий каталог из 107 предметов — другой набор: все его ID начинаются с
`srd_5_2_1`, а не с `dnd_5e_2014`. Для него тесты подтверждают картинки, но это
не меняет редакцию механики. 2014-предметы должны получить собственный
edition-aware каталог и только затем подключаться к магазину, стартовым наборам
и добыче. Цены, настройка, заряды и стоимость действия нужно переносить одним
профилем из DMG14, не брать отдельные поля из 2024-каталога.

## Враги и бестиарий

Сэмпловая сверка 2014-профилей прошла по базовым числам и ключевым действиям:

- [Гоблин](https://5e14.dnd.su/bestiary/4-goblin/) — MM14, КД 15, 7 HP,
  CR 1/4 и бонусное действие Nimble Escape;
- [Маг](https://5e14.dnd.su/bestiary/434-mage/) — MM14, КД 12, 40 HP,
  CR 6, заклинатель 9-го уровня, СЛ 14 и +6 к атаке заклинанием;
- [Гигантский паук](https://5e14.dnd.su/bestiary/3-giant-spider/) — PH14/MM14,
  КД 14, 26 HP, укус со спасброском Телосложения и «Паутина» с перезарядкой
  5–6;
- [Молодой красный дракон](https://5e14.dnd.su/bestiary/109-young-red-dragon/)
  — MM14, КД 18, 178 HP, иммунитет к огню, дыхание-конус 30 футов,
  перезарядка 5–6.

Эти значения совпадают с локальными четырьмя профилями. Это выборочная сверка,
а не построчная экспертиза всех 24 стат-блоков. В локальном наборе у всех 24
`book_code: MM14`, `data_status` — `reviewed_transcription` у 22 и
`reviewed_with_secondary_completion` у 2, а `mechanics_status: data_only`.
У двух профилей явно отмечено дополнение отсутствовавших полей по SRD 5.1;
это не должно смешиваться с числами другого стат-блока.

Три 2014-профиля имеют spellcasting, но их заклинания хранятся как внешние
ключи с пометкой `external_spell_key_requires_2014_catalog`; готового runtime
исполнителя для этих стат-блоков нет. У всех 24 пусты `legendary_actions` и
`lair_actions`; это честно отражает выбранный срез, но не полный бестиарий.

Рабочий runtime allowlist в `encounter-assembler.mjs` содержит **50** профилей и
50 портретов, но называется `SRD_5_2_1_MONSTER_ALLOWLIST`. Его `dnd.su`-ссылки
не делают эти записи профилями 2014: URL — только русская сверка, а источником
чисел является SRD 5.2.1. Нужен отдельный `dnd_5e_2014` allowlist с цельными
стат-блоками, а не переименование текущих 50 профилей.

Особенно нельзя собирать профиль по частям. Например, [карточка
мантикоры](https://5e14.dnd.su/bestiary/226-manticore/) явно содержит 24
хвостовых шипа и две альтернативы мультиатаки; если переносить это существо,
нужно переносить весь MM14-блок, включая атаки и ограничения. Политика
репозитория правильно запрещает добавлять к 2024-блоку отдельное число из
legacy-карточки.

## Текст, изображения и права

Локальная [политика источников](content-source-policy.md) разрешает использовать
dnd.su как справочный источник для структурированных фактов и самостоятельных
коротких пересказов, но запрещает распространять полные тексты страниц,
переводы, комментарии и иллюстрации. Публичная доступность страницы не является
лицензией. В `data/compendia/dnd_5e_2014/sources.json` у 54 наблюдений dnd.su
стоит `rights_status: review_required`; два вспомогательных источника SRD 5.1
помечены CC BY 4.0. Поля `revision_id` — ID наблюдения, а не хеш HTML.

Имеющиеся runtime-изображения — собственные/сгенерированные файлы проекта,
связанные с локальным реестром хешей. Хеш подтверждает идентичность файла, но
не доказывает авторство или право распространения. Сейчас
`data/asset-rights.json` имеет `rights_status: review_required` и
`distribution: blocked`; `pnpm content:verify` поэтому подтверждает целостность
файлов, но не готовность к публикации. Картинки для 2014-каталогов следует
создавать заново или брать из источника с явно подтверждённой лицензией и
записывать происхождение отдельно от прав на текст.

## Проверки

Запущены проверки, относящиеся к аудиту:

- `node tools/verify-dndsu-2014-content.mjs` — **passed**: 91 правило,
  24 монстра, 32 предмета, 81 связь, 56 источников, 13 контрольных сумм;
  `runtime_activation_allowed: false` и `mechanics_execution: not_integrated`.
- `pnpm spells:verify` — **passed**: 248 override и 439 карточек, проблем
  структуры не найдено. Проверка не определяет, 2014 это или 2024-механика.
- `pnpm content:verify` — целостность **ok**, но `release.ready: false` из-за
  частичного покрытия, `DNDSU_RIGHTS_UNVERIFIED` и
  `PUBLIC_ASSET_RIGHTS_UNVERIFIED`, среди прочих блокеров.
- `node --test test/item-images.test.mjs test/action-icon-manifest.test.mjs
  test/srd-creature-expansion.test.mjs` — **12/12 passed**: манифесты предметов,
  439 spell/action icon-ID и 50 портретов runtime-врагов согласованы с файлами.

## Рекомендации для текущей доработки

1. Завершить авторские русские описания 439 карточек и повторить аудит
   заглушек; отдельно показывать в UI школу, компоненты, концентрацию,
   ритуал, дальность, спасбросок, урон/лечение и масштабирование.
2. Добавить per-card provenance для заклинаний и оставить `TCE`, `SCC` и другие
   post-2014 книги opt-in. В core 2014 разрешать только подтверждённые
   `PHB14`/`DMG14`/`MM14` записи.
3. Исправить или разделить override `resistance`, явно сохранив поведение уже
   существующих кампаний и не переписывая старые события.
4. Подключать 32 предмета и 24 профиля только через цепочку
   command → Rules Engine → event → reducer с тестами прав, отказа,
   idempotency и replay. До этого показывать им статус справочника, а не
   доступной механики.
5. Для новых изображений использовать собственные или лицензированные ассеты;
   галерея dnd.su не является разрешением на копирование. После добавления
   ассетов обновлять реестр прав и проверять публикационный блокер.
