- Этап 1 начат: 439 ID инвентаризированы автоматически из действующего каталога;
  четыре пилота имеют подробные черновики, остальные 435 требуют индивидуального
  разбора. Этап 1 целиком ещё не принят.
- Исправлен импорт двух компонентных строк: M и А больше не смешиваются.
  Это подготовка компонентного слоя, без реализации платежа и разблокировки.

## Как получить текущую матрицу

```powershell
pnpm spells:acceptance
pnpm spells:acceptance --details
```

Владелец рабочих профилей остаётся `server/combat-spells.mjs`. Аудит читает
тот же каталог и не импортируется игровым сервером. Отдельного списка 439 ID
для ручного ведения нет. Исходные группы извлекаются из двух файлов коммита
`9277df0`; в публикационной копии с другой историей они будут `unavailable`.
Текущая инвентаризация при этом работает, но не подменяет исходные группы
новыми статусами.

Отчёт содержит хеши каталога, override, Rule Pack и владельцев механики,
а при наличии Git — коммит и хеш дерева с незакоммиченными изменениями.
Это привязка результатов к версии, не автоматическое подтверждение правил.
`ok: true` означает валидную структуру отчёта. Для Longstrider подключён
[сохранённый receipt](acceptance/longstrider-evidence.json); другие ID по-прежнему
не получают автоматической готовности. Receipt пока `pending` до окончательного
gate. После записи результата аудит требует `testedRevision`, дату, запись об
успешном `pnpm verify`, ссылки сценариев на прогоны и SHA-256 исходных логов.
Результат запуска записывает проверяющий; CLI не запускает тесты и не выводит
успех из существования лога или тестового файла.
Обязательные отпечатки охватывают сервер, каталог/override, UI и тесты, включая
сам аудит; текст хешируется после приведения CRLF к LF, чтобы Git autocrlf не
инвалидировал тот же код. Сам receipt и документы исключены из этого набора: изменение текста
не инвалидирует проверенную механику и не создаёт самохеш. Несовпадение любого
обязательного файла даёт `stale`, а сценарии снова становятся `pending`.
Наличие файла теста без записи успешного запуска ничего не подтверждает.
Сценарий `normal-acquisition-and-cast` включает HTTP и UI: успешный HTTP-прогон
можно приложить как отдельный отчёт, но весь сценарий и измерение `playerPath`
остаются `pending` до ручной проверки основного сайта. `presentation` также
требует ручной записи; правила, устойчивость и права могут подтверждаться отдельно.

## Текущий пилот: Longstrider

Добавлен `partial`-профиль: +10 футов скорости, касание, усиление по числу целей,
независимые экземпляры эффекта и точное истечение через час. Текущая скорость
вычисляется из базы и активных эффектов; новые Dash сохраняют число рывков,
поэтому их добавочный бюджет меняется вместе со скоростью. Проекция разделяет
базу, текущую скорость, расход и остаток, основные карты читают готовые значения.

Часы сохраняют полные минуты и остаток секунд до 0.001, без второго полного
счётчика. Полный раунд даёт 6 с между TurnEnded и TurnStarted; финальный начатый
действием раунд оплачивается один раз перед CombatEnded. Пустое начало/окончание
боя времени не создаёт. Вне боя локальное движение оплачивает стоимость пути
через текущую скорость и делит расчёт в точке истечения эффекта. Это не реализация
скорости дальнего путешествия. Старые журналы сохраняют минутную семантику.

Есть отдельные тесты правил, секундных часов и реального HTTP-пути двух обычных
игроков, включая получение магии, отказы, повтор, конфликт и restart. Эти тесты
и изменения UI ещё должны пройти окончательный gate; здесь его успех не заявлен.
Ручная приёмка двух игроков в 2D/3D с анимацией и звуком остаётся `pending`:
инструмент не обнаружил доступных браузеров IAB/Chrome. Полностью принятых ID — 0.
Переход к следующему пилоту этим изменением не объявлен.

Контракт и независимые ожидаемые числа — в [паспортах пилотов](spell-pilot-acceptance.md).

## Проверки

Исходный `pnpm verify` завершился кодом 1: из 4138 функциональных проверок
4133 прошли, одна упала, четыре явно пропущены; budget 12/12, MVP 3/3.
Ошибка — `persistent-campaign-api.test.mjs`: тест не нашёл легального шага
после завершения истории. Это не таймаут; длинный сценарий прошёл за 244,9 с.
Типы и сборка того прогона не выполнялись из-за отказа тестового gate.

Причина разобрана по детерминированным броскам вдохновения:
`SequenceDiceRng([1, 5, 1, 1])`, код `PERSIST-API`, регион «подземный город».
Выбор стартовых клеток обходил стены и двери, но не учитывал непроходимый
реквизит; герой мог оказаться в кармане между бассейном, сталагмитом и стеной.
Теперь bootstrap выбирает связную область с учётом `blocksMove` и свободным
выходом для отряда. Геометрический `reachableCells` получил необязательный
набор препятствий; остальные потребители сохраняют прежнее поведение.
14 регионов проверены реальным серверным `MoveActor`, повторён HTTP-сценарий
создания/завершения истории/restart. В тестовом поиске шага отдельно убран
ложный запрет декоративного `feature`, при сохранённой проверке реального пути.
Сохранённые позиции существующих кампаний не мигрируются.

Диагностика MVP теперь сохраняет последнюю команду через ограниченный список
полей, seed карты, ожидаемую реакцию/групповое решение/проверку, версию и стадию,
код выхода/сигнал процесса и ограниченный хвост логов с маскированием секретов.
Ожидающий HTTP-запрос отмечается до получения ответа. Боевые кости сервера
пока используют `CryptoDiceRng`: их seed честно отмечен как недоступный, а seed
карты не выдаётся за способ повторить бой. Лимиты тестов не увеличены.
Четыре исходных skip относятся к пересборке ассетов из внешних исходников;
игровые сценарии из-за ошибки не исключались.

Для окончательного дерева требуются:

```powershell
node --test test/generate-dndsu-spells.test.mjs test/spell-components-catalog.test.mjs test/spell-components-mechanics.test.mjs test/spell-acceptance-audit.test.mjs
pnpm spells:verify
pnpm content:verify
pnpm verify
```

Результат итогового запуска сохраняется отдельным логом и относится к
окончательному дереву. Браузерная приёмка заклинаний, 2D/3D и звук этим
срезом не подтверждены; ни один ID не повышен до `verified`.
