# Приёмка стола на пятерых

Дата прогона: 2026-07-30.

## Как воспроизвести

```bash
pnpm build
node .agent-tasks/table-of-five-smoke.mjs
```

Сценарий поднимает production-сборку на свободном локальном порту, создаёт
временный `DND_STORAGE_DIR` и запускает пять изолированных Chrome-контекстов
через raw CDP. Рабочий `storage/` не читается и не изменяется. После прогона
сервер, браузерные контексты и временный каталог закрываются.

Машиночитаемый результат: [`protocol.json`](evidence/table-of-five/protocol.json).

## Пройденный путь

1. Владелец создаёт кампанию на пять героев, четыре аккаунта входят по отдельным
   одноразовым приглашениям.
2. Четыре игрока начинают сцену; пятый присоединяется позднее и получает
   актуальную проекцию. Шестой аккаунт получает `409`, потому что свободных
   героев больше нет.
3. Второй игрок печатает намерение, остальные видят кратковременный typing.
4. Два разных героя одновременно отправляют свободные намерения. Сервер
   проверяет принадлежность `actor_id`; в бою дополнительно действует
   ограничение активного участника.
5. Отряд открывает account-level голосование. Один проголосовавший отключается,
   его голос становится закреплённым policy воздержанием, остальные разрешают
   решение большинством.
6. Начинается встреча. Отключение активного игрока не сдвигает инициативу;
   после возвращения ход и состояние совпадают.
7. Сервер перезапускается на том же временном хранилище. Версия состояния,
   инициатива и активный ход сохраняются, все браузеры снова читают комнату.
8. После боя игрок открывает лавку, получает серверные котировки и выполняет
   проверенный `BargainWithMerchant`.
9. Принятое решение переводит отряд в новую сцену; все пять браузеров видят
   одинаковую локацию.

## Что исправлено по итогам прогона

- максимальный размер новой кампании увеличен с четырёх до пяти героев;
- `/api/narrate` принимает только принадлежащего сессии героя и не подменяет
  автора глобально выбранным участником;
- повторный вход участника комнаты больше не требует новую invite-ссылку;
- при занятых местах интерфейс честно сообщает, что режима наблюдателя нет;
- в составе отряда видны online/offline и typing, а в решении — имена
  голосующих и статусы «голос учтён», «ждём», «не в сети», «воздержался»;
- свободная сцена больше не создаёт ложную очередь: говорить может любой герой,
  а групповые решения идут через голосование;
- карточка голосования и нижняя строка намерения не схлопываются на 1280×800.

## Зафиксированные ограничения

- Обрыв во время открытого голосования по действующей policy считается
  воздержанием; повторно проголосовать в том же решении нельзя.
- Отключившийся активный герой удерживает боевой ход до возвращения.
  Автоматический пропуск требует отдельного продуктового решения.
- Приглашение одноразовое и закрепляет одно место; владелец создаёт отдельную
  ссылку для каждого гостя.
- Роли наблюдателя нет.
