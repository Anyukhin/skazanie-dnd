## 1. Прижать версии зависимостей

Сейчас в `package.json` все зависимости указаны как `latest`. Лок-файл пока
удерживает установку, но его обновление может молча притащить мажорную версию
и сломать сборку посреди работ по картам.

```bash
grep -c '"latest"' package.json   # сколько исправлять
```

Взять фактические версии **из `pnpm-lock.yaml`**, а не из `node_modules` —
pnpm хранит пакеты в стороне. Заменить каждое `"latest"` на `^X.Y.Z`.

На момент написания в локе: `react` и `react-dom` 19.2.7, `vite` 8.1.4,
`typescript` 7.0.2, `dotenv` 17.4.2, `lucide-react` 1.24.0. Версии
`@vitejs/plugin-react`, `@types/react`, `@types/react-dom` взять оттуда же.
**Если в локе другие значения — брать из лока.**

**Проверка:**

```bash
pnpm install --frozen-lockfile
git diff --exit-code pnpm-lock.yaml   # лок не должен измениться
pnpm verify
```

**Готово когда:** в `package.json` нет ни одного `"latest"`, лок не изменился,
`pnpm verify` проходит.

Эти файлы не используются ничем — ни кодом, ни инструментами. Они выглядят
рабочими и будут сбивать с толку при работах по картам.

`prompts/verifier/v1.txt`, `prompts/worldkeeper/v1.txt`,

- роль планировалась, но не подключена → оставить файл и записать строку в

**Проверка:**

**Готово когда:** мёртвые файлы удалены, по каждому промпту решение принято и

## 3. Включить проверку типов на сервере

Инфраструктура плюс узкий срез файлов. **Весь сервер сейчас не типизировать** —
только то, чего коснётся M0 карт.

### 3.1. Инфраструктура

Создать `tsconfig.server.json`:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "lib": ["ES2022"],
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "allowJs": true,
    "checkJs": true,
    "noEmit": true,
    "strict": true,
    "skipLibCheck": true,
    "resolveJsonModule": true
  },
  "include": []
}
```

`"include": []` пустой намеренно: файлы добавляются по одному, чтобы проверка
типов никогда не была красной.

Добавить путь в `references` в `tsconfig.json`, добавить скрипт
`"typecheck:server": "tsc --noEmit -p tsconfig.server.json"` и включить его в
gate: `"verify": "pnpm test && pnpm typecheck:server && pnpm build"`.

**Проверка:** `pnpm verify` проходит. Проверять пока нечего — это норма.

### 3.2. Типизировать карто-смежные файлы

По одному, в этом порядке. Для каждого: добавить в `include` → прогнать
`pnpm typecheck:server` → расставить JSDoc (`@typedef`, `@param`, `@returns`)
до зелёного → `pnpm verify` → коммит.

| Файл | Строк | Зачем перед M0 |
| --- | --- | --- |
| `server/contracts.mjs` | 28 | разминка, проверить что инфраструктура работает |
| `server/dynamic-map.mjs` | 251 | генератор карт, M0 меняет его выход |
| `server/viewer-projection.mjs` | 464 | проецирует клетки игроку, меняется вместе с контрактом |

Здесь же описать типом текущую форму клетки — `type`, `material`, `variant`,
`pattern`, `revealed`, `feature`, `edge_mask`. Это станет отправной точкой
миграции в M0 и заодно зафиксирует, что было **до** изменений.

**Правило:** если файл требует правок рантайма, чтобы пройти проверку типов —
остановиться и вынести это отдельной задачей.

**Готово когда:** `pnpm typecheck:server` в составе `pnpm verify`, три файла в
`include`, все тесты зелёные без правок самих тестов.

## 5. Зафиксировать базовую линию

M0 меняет форму сохранённых данных — это единственная работа в бэклоге,
способная испортить существующие кампании. Перед ней нужна точка отката и
эталон для сравнения.

```bash
pnpm backup                    # резервная копия storage/
pnpm cutover:audit             # текущие расхождения, до изменений
pnpm test 2>&1 | tail -20      # эталон: сколько тестов и какие падают сейчас
```

Записать результат `cutover:audit` и итог прогона тестов в
`docs/known-limitations.md` или в отдельную заметку с датой. После M0 сравнить
с этой же линией: расхождения не должны появиться новые.

**Готово когда:** резервная копия создана, базовая линия записана с датой.
