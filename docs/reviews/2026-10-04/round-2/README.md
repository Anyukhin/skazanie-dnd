## Что опровергнуто или ограничено

- Смена actor в проверенном command retry уже получает `409
  IDEMPOTENCY_CONFLICT`; это не новая дыра полномочий.
- Общий namespace ключей между endpoint-ами допустим, если они выражают одну
  логическую операцию. Finding относится к несовместимым запросам.
- Переназначение героя проверено для legacy `user.heroIds`. Современного
  membership-revoke endpoint нет; его реальное поведение не заявляется.
- Проба приватности показывает различие политики на уже существовавшем поле,
  не доказывает получение нового секрета после переназначения.
- Ошибка нормализатора роли после успешного metered-return уже не теряет
  usage. COST-01 касается низкоуровневой проверки содержания до этого возврата.
- Повторяемый `usageRequestId` пока не передаётся production callers; COST-02
  — риск интерфейса перед его расширением, а не массовая текущая регрессия.
- Между верхними полями ответа и `authoritative_state` крупных точных повторов
  нет. Повтор обнаружен внутри `worldMemory`; поля `mechanics` имеют разный смысл.
- Три локальных performance-наблюдения не доказывают ускорение относительно
  предыдущей серии из двадцати и не являются production SLO.

## Уточнение очереди улучшений

Перед расширением игрового ввода и числа пользователей к R01/R02 первого плана
стоит добавить отзыв SSE-доступа и durable fingerprint всего нормализованного
запроса. R02 должен учитывать ошибки парсинга с известным provider usage, а не
только маршрутизацию LoreAuthor через wrapper.

В оптимизации появилась конкретная первая мишень: лишняя транспортная копия
knowledge ledger. Потенциальная экономия в этой фикстуре — около 1,78 МБ за
ответ. Старые replay-форматы и canonical memory менять для этого не нужно.
Дальше следует измерять полную проекцию, многократные загрузки и обновление
клиента, сохраняя полную совместимую синхронизацию на reconnect.

Повторный CLI-анализ TypeScript на новом срезе показал **32 из 37** файлов с
`// @ts-check` в программе. Новый `scene-dressing.mjs` включён через импорты;
пять ранее пропущенных файлов остались теми же. Это уточнение знаменателя
QA-02, а не шестая новая ошибка.

Все probes используют синтетические данные, отдельные временные каталоги и
локальные/fake provider. Исправления runtime в PR не входят. Подробные команды,
ограничения и первичные результаты находятся в отчётах каждой проверки.
