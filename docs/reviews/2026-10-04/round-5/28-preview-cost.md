# Стоимость новой геометрии предпросмотра: ограниченный замер

Срез `88c620e6011ae607913efb224cb8f850b4ee5028`. Измерены четыре настоящие
функции из `src/move-preview.ts`, скомпилированные локальным TypeScript.
[Скрипт](28-preview-geometry-benchmark.mjs) и
[исходный результат](28-preview-geometry-benchmark.json) приложены. Runtime и
зависимости не менялись.

**Срочный рефакторинг генерации строк не обоснован этим замером.** На открытом
поле с запасом движения 30 футов размер карты не увеличивает область
досягаемости: 84 клетки без стартовой и на 32×32, и на 96×64. В этой нагрузке
p95 четырёх функций вместе меньше 0,1 мс. Это положительный контроль узкого
этапа, а не проверка FPS или плавности интерфейса.

## Методика и результат

Windows, Node `v24.19.0`, AMD Ryzen 7 9800X3D. Для каждого случая — 30 прогревов
и 200 последовательных измерений. Вход — пустое прямоугольное поле с актором
в центре; допустимые клетки построены по ортогональному расстоянию и цене
5 футов за шаг. Маршрут имеет два шага. Замер включает `moveReachFill`,
`moveReachOutline`, `moveRoutePath`, `moveDifficultPath`, но исключает построение
`movementPaths`, React, разбор SVG/`Path2D`, растеризацию и GPU.

Нельзя выдавать 118 КБ строк за стоимость каждого наведения по большой карте.
Порядок случаев, JIT и фоновая нагрузка могут влиять на числа; этот одиночный
прогон не является SLA или доказательством различия между двумя малыми p95.

## Где проходит полезная граница расширения

Новый чистый модуль уже разделяет данные предпросмотра и их геометрию.
`BoardMovePreview` одинаково обслуживает SVG и Canvas. Эту границу стоит
сохранить: новый вид движения может дополнять данные, а renderer не должен
заново вычислять серверную допустимость.

Если браузерный профиль покажет значимую стоимость, первый небольшой шаг —
отдельно кэшировать постоянную геометрию `reach` и геометрию наведённого пути.
Сейчас `moveReachFill` и `moveReachOutline` каждый строят свой `Set`, а
3D-слой заново создаёт `Path2D` при перерисовке:
[`move-preview.ts#L95-L120`](https://github.com/Anyukhin/skazanie-dnd/blob/88c620e6011ae607913efb224cb8f850b4ee5028/src/move-preview.ts#L95-L120),
[`TacticalBoard3D.tsx#L548-L582`](https://github.com/Anyukhin/skazanie-dnd/blob/88c620e6011ae607913efb224cb8f850b4ee5028/src/TacticalBoard3D.tsx#L548-L582).
Для чистой геометрии достаточно корректно сравнивать её входы `start` и
`reach`; пересчёт допустимых клеток остаётся у текущего владельца. Не стоит
создавать ещё одну политику стоимости движения внутри кэша. Если кэшируется
более широкая модель доски, одного номера версии разных кампаний недостаточно.

Пока выше по приоритету проверка корректности и существующие гипотезы затрат
`DungeonMap` из [первого прохода](../04-client-and-rendering.md). Перед
оптимизацией нужен браузерный pointer trace с раздельными замерами поиска
маршрутов, построения клеток, React commit, разбора пути и paint. Полный
рендер может быть дорогим при дешёвой генерации строк; обратное тоже нельзя
вывести только из количества клеток.
