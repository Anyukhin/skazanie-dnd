## Направление обобщения

Новый `move-preview.ts` уже удачно отделяет геометрию от механики. Стоит
сохранить этот простой интерфейс и укрепить входные данные: по возможности
использовать общие чистые серверные правила, как уже делает клиентский
адаптер `actor-footprint`. При неполной проекции нужен явный статус
неопределённости, а не обещание точной цены скрытого маршрута.

Сетевой preview может быть полезен при подтверждении сложного намерения, но
запрос на каждое наведение не следует вводить без измерения задержки и
нагрузки. Копирование всей механики в React создаст ещё один независимый
источник правил. В [отчёте 25](25-movement-contract.md) сравниваются более
узкие варианты.

Для `partial` сначала использовать существующее поле `supportNote` и
проверить профиль нужного ruleset. Новый общий descriptor оправдан, когда
несколько семейств действительно требуют одних и тех же полей, а не просто
похожей подписи на карточке. Это продолжает общий
[план небольших изменений](../09-improvement-options.md).
