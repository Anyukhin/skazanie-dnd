# Полное ревью «Сказания»: архитектура, надёжность и развитие

**4 октября 2026 · срез `c7efdca614cc33f706258d036e86f01c1f189404` · предложения, не реализация.**

Этот документ подводит итоги первого прохода. Аудит продолжен на актуальном
срезе `e1d927f5`; новые проверки живого доступа, повторов команд, карт,
передачи состояния и учёта модели собраны во
[втором проходе](round-2/README.md). Выводы разных срезов не подменяют друг друга.

Основу проекта стоит сохранить. Серверный авторитет, событийная история,
детерминированная механика, проекции видимости и тесты дают хорошую базу для
расширения. Основные препятствия — разрывы между существующими модулями,
несколько обходных путей, высокая стоимость полного состояния большой
кампании и необходимость менять много мест для одной новой механики.

Рекомендуемое направление: закрыть конкретные разрывы, затем последовательно
выделять доменные части за прежними интерфейсами. Переписывание стека, новая
база и универсальный plugin framework сейчас не обоснованы.

## С чего начать

1. **Привязать бросок к объявленной проверке.** Generic `/api/roll` без
   `check_id` выдаёт результат, который принимается обычной проверкой. Игрок
   может выбирать удачный серверный d20. Итоговые модификаторы пересчитываются
   сервером: это не прямая подмена HP/СЛ.
   [SEC-01](03-persistence-and-security.md), [проба](roll-probes.mjs).
2. **Замкнуть учёт AI-расхода и генерацию изображений.** `LoreAuthor` получает
   необёрнутый клиент; item images используют отдельный provider call, хотя
   проверяющий генератор уже существует. Нужна миграция этих callers в
   имеющиеся модули. [AI-02](05-ai-world-and-maps.md).
3. **Проверять верхние этажи библиотечных карт.** Валидность ground floor не
   гарантирует структурную допустимость остальных уровней. Искусственный
   дефект воспроизведён; пользовательская библиотека не менялась.
   [AI-06](05-ai-world-and-maps.md), [проба](map-library-probe.mjs).
4. **Подключить все opt-in-файлы к typecheck.** Пять файлов с `// @ts-check`
   отсутствуют в программе TypeScript; зелёный gate не проверяет их обещанный
   контракт. [QA-02](06-quality-and-delivery.md).
5. **Оптимизировать полный HTTP-путь большой кампании по профилю.** В свежем
   локальном benchmark p95 команды — **7,33 с** против **111 мс** у маленькой
   кампании; ответ — около **6,17 МБ**. Причину нельзя свести к диску или
   retriever без профиля стадий. [Методика и JSON](08-evidence-and-method.md).

При расширении полезны проверки ссылок/коллизий rule packs, ограниченная
очередь SSE, явная политика current/legacy событий и перенос оставшихся
писателей в существующий `AuthoritativeExecutor`. Последовательность,
альтернативы и критерии — в [плане небольших PR](09-improvement-options.md).

## Независимая ось Standards

Проверка сопоставила код с `AGENTS.md`, существующими владельцами задач и
эвристиками сложности. Пять основных результатов:

- прямой item image provider path дублирует общий генератор и его проверки;
- raw lore-клиент обходит `MeteredLLMClient` и общую квоту;
- merchant economy clock остаётся документированным атомарным исключением
  из общего executor; переносить его следует целиком, сохраняя атомарность;
- writer guard сканирует только верхний уровень `server/`, поэтому будущая
  запись из подкаталога может пройти незамеченной;
- `index.mjs` совмещает несколько причин изменения; выделение маршрутов —
  эвристическое предложение, не баг из-за 5 742 строк.

Самый прямой разрыв этой оси — обход общих provider/budget-модулей. Большой
файл и single-writer deployment сами по себе нарушениями не объявляются.

## Независимая ось Spec

Проверка использовала `product-principles.md` и спецификации играбельности.
Шесть кандидатов: свежая браузерная приёмка обычной группы; причинная главная
цель; семейство свободных действий с наблюдаемым последствием; поимённый пакет
проверенных правил; опциональная тактика героев; долгая кампания и recovery.

Цикл обычных игроков, бой, награда, restart и три сцены уже проверяются
HTTP-MVP; создавать этот путь заново не нужно. Оставшийся разрыв — полнота
пользовательских сценариев и правил относительно общей цели продукта.
Старые заявления об отсутствии membership, trace projection, quota и
level-up UI частично устарели; это долг документации, а не текущие отсутствующие
функции.

Итого по осям: **5 Standards-наблюдений** и **6 Spec-кандидатов**. Они не
являются единым счётчиком багов. Тематические findings отдельно различают
дефект, известное ограничение и гипотезу оптимизации.

## Проверки и границы

Базовый `pnpm verify` прошёл: **5 661 passed, 6 skipped, 0 failed**, server
typecheck и build успешны. Повторён существующий benchmark с временными
данными без LLM; сохранены измерения и runnable probes ключевых находок.
Зелёный suite не означает, что покрыты обнаруженные промежутки контрактов.

Аудит охватывает подсистемы всего репозитория; это не построчная сертификация
4 882 файлов. Рабочие данные и секреты не использовались. Не выполнялись
новая live-LLM оценка, браузерная приёмка, production нагрузка, потеря питания
или проверка нескольких writers. Ветка `claude/maps-depth` и её
незакоммиченные изменения находятся вне закреплённого среза.

Этот PR сохраняет анализ и предложения. Он не реализует перечисленные
исправления и не меняет утверждённые продуктовые требования.
