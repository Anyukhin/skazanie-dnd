# Проба транспорта памяти: один alias вместо двух

Срез `cb045a8466f35696ff24abe9020d6f39dee89462`. Использованы настоящие функции
проекции и нормализации с отдельной синтетической фикстурой; код приложения не
изменялся. Скрипт и результат: [probe](33-memory-transport-probe.mjs),
[JSON](33-memory-transport.json).

Проверен конкретный вариант на границе публичного JSON: после `turnResultForViewer` удалить ровно один из `worldMemory.knowledge_revealed` и `worldMemory.knowledge_ledger`, оставив второй. Канонический state не меняется, а нормализатор памяти может восстановить удалённый alias.

Результат поддерживает удаление одного alias для экономии JSON и gzip. На
Brotli выигрыш не гарантирован: в этой пробе удаление alias увеличило сжатый
ответ для игроков и немного уменьшило его для admin. Это наблюдение о
конкретном входе и настройках компрессора, а не доказательство внутренней
причины такого результата. Эксперимент не является runtime-правкой.

В таблице удаляется именно `knowledge_revealed`, а `knowledge_ledger`
сохраняется. Обратный вариант также проверен и записан в JSON; его размеры
немного отличаются из-за имени поля и сжатия.

| viewer | фактов в public memory | `gm_only` вне проекции | полный JSON | экономия JSON при удалении alias | экономия gzip | экономия Brotli |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `hero-1` | 301 | 265 | 762 495 | 177 851 | 7 120 | −38 |
| `hero-2` | 251 | 315 | 739 178 | 177 860 | 7 177 | −460 |
| `admin` | 566 | 0 | 1 583 001 | 355 714 | 14 501 | +241 |

Размеры в таблице — весь envelope `turnResultForViewer`, а не только память.
Несжатый JSON экономит размер массива и синтаксис удалённого поля (у admin —
355 692 байта массива). Gzip экономит гораздо меньше — 7–14,5 КБ.
Использованы `gzipSync` и `brotliCompressSync` из `node:zlib` с настройками
по умолчанию; версии runtime записаны в JSON. Конфигурация HTTP-сжатия
production-хоста этим не проверялась, SLA по времени не измерен.

Проверки видимости прошли для трёх ролей: `hero-1` видит собственную приватную улику `fact:hero-a-private`, но не улику `hero-2`; `hero-2` видит обратную пару; `fact:unlearned-private-1` игрокам не отдается; admin видит обе приватные и нераскрытые записи. В полном public memory оба alias-массива побайтно совпадают по JSON.

Для каждого viewer и каждого направления удаления проверено:

- все поля вне двух alias имеют тот же SHA-256 и глубокое равенство;
- оставшийся alias не меняется;
- `normalizeWorldMemory(compact)` побайтно совпадает с нормализованным полным memory;
- исходный канонический state не мутируется.

Fixture ограничен 20% от `DEFAULT_COUNTS` (`eval/world-data-measurements.mjs:materializeLongState`), чтобы проба оставалась bounded; поэтому цифры нельзя переносить как новый production baseline или напрямую сравнивать с round-2. HTTP, storage, LLM и replay не запускались. Проверка нормализует только `worldMemory` и не доказывает совместимость полного replay или всех клиентов.

Запуск:

```text
node --check docs/reviews/2026-10-04/round-7/33-memory-transport-probe.mjs
node docs/reviews/2026-10-04/round-7/33-memory-transport-probe.mjs
```

Фильтрация по историческому `asOfMinutes` здесь отдельно не проверялась.
Совпадение нормализованной памяти не заменяет проверку сетевого протокола,
декодирования клиентом, reconnect или сохранённых событий.

Полные `structuredClone` в probe изолируют сравниваемые варианты; это не
предлагаемая production-реализация adapter-а. Для удаления одного поля не
нужно снова копировать всё дерево кампании. Сам поздний transport-adapter
также не сокращает уже выполненное построение полной viewer projection или
повторные загрузки Event Store — эти затраты требуют отдельного профиля.
