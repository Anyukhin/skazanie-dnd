# Переключение кампании при ожидающем свободном действии: браузерная проверка

Код: `e1d927f5aa68dc9eca912b527cccf3974ba3e9e7`. Локальный production build,
настоящий HTTP-сервер, Codex In-app Browser и отдельный fault proxy. Все
кампании, учётные записи и файлы хранения синтетические. LLM отключён пустым
ключом; рабочий `storage/` и `.env` не использовались.

**REC-04 подтверждён через основной интерфейс:** после выбора кампании B URL
содержит B, но экран показывает сцену и журнал A. Перезагрузка страницы
возвращает правильную B. Это ошибка клиентского применения снимка, а не
доказанная порча серверного состояния B или обход прав доступа.

## Порядок действий и результат

1. Запущен [существующий helper](../round-3/browser-smoke-server.mjs) с
   `--switch-test`. Он создаёт A (`BROWSER-REVIEW3`, сцена «Тихая площадь») и B
   (`BROWSER-OTHER4`, сцена «Комната Б»), затем делает три штатных серверных
   движения в A. Версия A становится выше версии B.
2. Тестовый игрок вошёл через страницу входа и открыл A. У него есть доступ к
   обеим legacy-кампаниям. Включён обычный ручной бросок; настройка auto-roll
   для этого сценария не использовалась.
3. Через поле свободного действия отправлено «Проверяю силу». Proxy получил
   от сервера HTTP 200 и удержал ответ. Поле ввода стало недоступно.
4. Пока запрос ожидал ответ, helper отправил допустимый `MoveActor` в A через
   серверный admin fixture. Сервер вернул 200, `room_version: 6`,
   `state_version: 8`; обновление A пришло подписанному клиенту.
5. Через обычный `CampaignModal` выбрана B. Это штатный путь без передачи
   предварительно загруженного состояния.

| Наблюдение | После выбора B | После перезагрузки той же вкладки |
| --- | --- | --- |
| Параметр URL `room` | `BROWSER-OTHER4` | `BROWSER-OTHER4` |
| Заголовок сцены | **«Тихая площадь» — A** | «Комната Б» |
| Видимая кампания | `BROWSER-REVIEW3` — A | B |
| Журнал | Движения A и текст «Проверяю силу» | Пустой журнал B |
| Поле нового действия | Доступно | Обычное состояние B |

До перезагрузки удержание ответа снято. Результат зафиксирован чтением DOM и
скриншота через браузерный инструмент. React state, JavaScript приложения и
browser storage напрямую не изменялись. Сохранённый
[JSON наблюдений](browser-queue-observations.json) — протокол ручной проверки,
не автоматически исполняемый браузерный тест. Скриншот просмотрен, отдельный
файл изображения не сохранялся.

## Что подтверждают квитанции

[Ответ narrate](narrate-switch-receipts.json) подтверждает backend 200 и
удержание proxy. `state_version: null` здесь ожидаемо: ручной запрос выдаёт
карточку проверки, а дополнительное изменение A пришло отдельной командой.
Это не воспроизведение двойного commit из [отчёта 22](22-narrate-retry.md).
[Квитанция обновления A](narrate-switch-pulse.json) содержит обе серверные
версии. Названия `version` и `state_version` обозначают разные счётчики и не
должны смешиваться.

Механизм соответствует [пробе реальных callback-ов](23-queued-room-state.md):
ожидающий `submitAction` удерживает снимки в очереди; переключение применяет B
и снимает состояние повествования; effect выбирает более высокий номер из
очереди A без проверки кампании. `actionEpoch` защищает поздний ответ action,
но не отдельную очередь room snapshots.

## Контроль тактического запроса

В отдельном запуске удерживался ответ `MoveActor`, после чего игрок также
выбрал B. Экран остался на B. При возвращении в A появился индикатор
неизвестного результата; явный повтор использовал тот же ключ и вернул
`idempotent_replay: true` при неизменной версии 8. Оба ответа записаны в
[тактических квитанциях](tactical-switch-receipts.json).

Этот контроль показывает различие путей обычного и тактического действия.
Задержка могла достичь таймаута, поэтому он **не доказывает** корректное
отбрасывание успешно полученного позднего ответа во всех вариантах timing.
Более полный положительный сценарий тактического retry и reload описан в
[предыдущем проходе](../round-3/20-browser-recovery.md).

## Как повторить и что исправлять

После `pnpm build` запустить:

```powershell
node docs/reviews/2026-10-04/round-3/browser-smoke-server.mjs --switch-test
```

Helper печатает URL, синтетические данные входа и абсолютные пути `hold`,
`pulse`, `receipts`, `stop` своего временного каталога. Создание пустого файла
`hold` включает удержание ответов `/api/narrate` и typed commands; файл `pulse`
запускает серверное обновление A. Затем в UI повторить шаги выше. Удаление
`hold` освобождает ответ; создание `stop` останавливает helper и удаляет его
временное хранилище. Опциональный `--receipts=<путь>` сохраняет квитанции вне
этого каталога. Родительская директория пути должна существовать.

Минимальное исправление — привязать очередь к кампании, очистить её при
переключении и проверять campaign identity до сравнения версий. Не требуется
переписывать всё управление состоянием. Будущий regression-сценарий должен
проверять одновременно URL, видимую кампанию, local cache и принадлежность
следующей команды; в текущей проверке новая команда после рассинхрона не
отправлялась.

Ограничения: один аккаунт, два готовых legacy-сохранения, один браузер;
обновление второго участника заменено разрешённой серверной командой fixture.
Полный сценарий двух независимых игроков здесь не выполнен. Стенды завершены,
созданные ими временные каталоги удалены.
