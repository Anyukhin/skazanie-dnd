# Браузерная проверка неизвестного результата тактической команды

Срез: `e1d927f5aa68dc9eca912b527cccf3974ba3e9e7`, 4 октября 2026.
Использован Codex In-app Browser и локальная production-сборка приложения.
Это узкая проверка интерфейса восстановления, а не новая приёмка всей кампании.

## Стенд и независимость от пользовательских данных

[Временный сервер](browser-smoke-server.mjs) запускает настоящий
`server/index.mjs` с отдельным `DND_STORAGE_DIR`, пустым dotenv-файлом и
`ROUTERAI_API_KEY=''`. Обратный proxy слушает `127.0.0.2` на свободном порту,
чтобы тестовая cookie не смешивалась с обычным localhost. Production-код не
изменяется. Proxy может потерять один ответ либо отвечать HTTP 503 после того,
как backend уже завершил команду с HTTP 200.

Администратор скрипта создаёт синтетическую кампанию с одним героем. Через UI
выполнены обычный вход игрока, выбор кампании, движение по карте, повтор
запроса и reload. Это legacy-fixture с готовым героем; мастер создания,
приглашения, два одновременных игрока и реальная модель здесь не проверялись.

Область браузерной проверки — `/?room=BROWSER-REVIEW3`:
тактическая 2D-карта, предупреждение «Результат действия неизвестен», кнопка
«Повторить запрос», доступность поля свободного действия и хроника движения.
Действия выполнялись через видимый DOM/доступность браузера, без инъекции
React-state или вызова скрытых browser API. Были просмотрены DOM и снимки
экрана в ходе проверки; в PR сохранены структурированные наблюдения и квитанции
сервера, а не новый автоматизированный browser suite.

## Сценарий BROWSER-01 — единичный обрыв ответа

Proxy принял ответ backend после MoveActor и закрыл соединение до передачи
ответа браузеру. В [квитанциях](browser-first-receipts.json) два POST имеют
один idempotency key: первый ответ потерян, следующий прошёл. В UI осталось
одно сообщение о движении, поле действия снова стало доступно.

В `src` не найден автоматический retry этой команды: `fetchWithTimeout`
делает один fetch, а повтор тактической команды связан с явной кнопкой.
Следовательно, по этому запуску нельзя приписать второй POST приложению.
Браузерный сетевой стек/proxy-путь не инструментировался достаточно для
точной атрибуции. Доказано только сохранение ключа и корректный видимый итог;
это полезный положительный результат, а не найденный дефект.

## Сценарий BROWSER-02 — HTTP 503 после успешного commit

Чтобы не зависеть от поведения сетевого стека при закрытии соединения,
следующая проверка использовала явный HTTP 503 от proxy после backend 200.

1. Игрок нажал соседнюю клетку `(1, 0)`.
2. Backend записал движение и вернул версию 2. Proxy заменил ответ на 503.
3. В браузере появилась карточка «Результат действия неизвестен» с описанием
   исходной команды. Поле свободного действия и новые перемещения были
   заблокированы. Последующее обновление комнаты не сняло карточку самовольно.
4. После отключения fault policy игрок нажал «Повторить запрос».
5. HTTP повтор содержал прежний key, вернул `idempotent_replay: true` и ту же
   версию 2. Карточка исчезла, поле действия стало доступно. В хронике осталось
   одно движение.

Это ровно нужное разделение: SSE может показать сохранённое состояние,
но закрытие неопределённого запроса подтверждается его собственным ответом.

## Сценарий BROWSER-03 — reload той же вкладки

Второе движение в `(0, 0)` прошло тем же путём backend 200 → proxy 503 и
повысило состояние до версии 4. До нажатия повторной кнопки вкладка была
перезагружена штатным browser reload.

После завершения загрузки:

- предупреждение неизвестного результата осталось (`recoveryNoticeCount=1`);
- поле действия было заблокировано (`actionEnabled=false`);
- хроника содержала два движения;
- автоматического нового POST этой команды при reload в квитанциях нет.

После снятия fault policy и явного повтора карточка исчезла, поле действия
разблокировалось, версия осталась 4 и третьего движения не появилось.
[Квитанции двух сценариев](browser-recovery-receipts.json) дают последовательность
версий **2, 2, 4, 4** и ключей **A, A, B, B**. На диске были ровно два commit
файла и четыре события. Сводка сохранена в
[`browser-observations.json`](browser-observations.json).

Объяснение находится в существующем owner: `useGameSession` использует
[sessionStorage для recovery](https://github.com/Anyukhin/skazanie-dnd/blob/e1d927f5aa68dc9eca912b527cccf3974ba3e9e7/src/useGameSession.ts#L464-L506),
а `retryPendingTacticalCommand` восстанавливает исходный request
[здесь](https://github.com/Anyukhin/skazanie-dnd/blob/e1d927f5aa68dc9eca912b527cccf3974ba3e9e7/src/useGameSession.ts#L1571-L1591).
Фраза «только текущая вкладка» не означает потерю при reload этой вкладки.
Закрытие вкладки, новый browser context и другой аккаунт — отдельные сценарии.

## Вывод для обобщения

Для остальных мутаций стоит сначала переиспользовать проверенный контракт
pending operation: scope аккаунта/кампании, исходный body и key, неопределённый
статус, блокировка несовместимого действия и явный retry. Не нужен второй
клиентский command bus. Однако автоматически объявлять все endpoints безопасными
нельзя: свободный ввод, голосование, общий бросок и торговля имеют разные
семантические условия и требуют собственных сквозных проверок.

В [клиентском аудите](16-client-recovery.md) следует отделять эти ограничения
от тактического пути, который в выполненных сценариях сработал корректно.
Ошибок механики или повторного движения в этой браузерной пробе не обнаружено.

## Воспроизведение вручную

```powershell
node docs/reviews/2026-10-04/round-3/browser-smoke-server.mjs
```

Скрипт печатает URL, синтетические login-данные и пути управления своим временным
каталогом. Создание marker `fail-command-responses` включает 503 для следующих
ответов `/commands`; удаление marker выключает fault policy. Marker
`drop-next-command` теряет только один ответ. Marker `stop` штатно завершает
proxy и backend. Срок жизни стенда ограничен двадцатью минутами.

Браузерная вкладка была закрыта. После завершения tool-сессии proxy уже не
отвечал, процесса helper не было; остаточный каталог синтетических данных
удалён отдельной проверенной операцией. Рабочий `storage/` не затронут.
