# Аудит правил компонентов заклинаний — 19 сентября 2026

Исторический снимок до заполнения компонентов всех 439 карточек. Текущее
покрытие, проверки и оставшиеся ограничения — в
[журнале общих механизмов](combat-foundations-progress.md).

Это read-only аудит перед расширением компонентного контракта. Он сверяет
текущий WIP с D&D 5e 2014 и карточками `5e14.dnd.su`. Он не поднимает статусы
заклинаний и не утверждает полного покрытия корпуса.

## Что уже есть в текущем WIP

- В `server/rules-engine.mjs:7902-7960` есть авторитетный каркас проверки для
  кампании `dnd_5e_2014`: V/S, тишина и кляп, свободная рука, War Caster,
  компонентная сумка, классовый фокус и отдельная проверка алмаза для
  `chromatic-orb`.
- `CastSpell` вызывает этот каркас до выбора и расхода ячейки
  (`server/rules-engine.mjs:6418-6453`). Собственная команда подготовки
  заклинания теперь тоже проверяет компоненты на старте
  (`server/rules-engine.mjs:12771-12782`). Выпуск заготовленного заклинания
  повторно не должен проверять или списывать уже подготовленный ресурс.
- Классовый профиль сохраняет `spellcastingClass`
  (`server/combat-spells.mjs:213-237`). Для NPC нормализатор сохраняет
  `components_required` и `components_not_required`, а per-entry значения
  имеют приоритет над trait-level значениями
  (`server/combat-spells.mjs:315-375, 394-429`). Это важно: наличие
  `innateSpell` само по себе не означает отсутствие компонентов.
- UI показывает V/S/M в существующей карточке и принимает блокировку только
  через server-owned `componentAvailability`; отдельного меню с кнопкой
  «Применить» для этого нет (`src/types.ts:308-350`,
  `server/viewer-projection.mjs:1372-1377`).

## Текущая граница пилота

Структурных компонентов пока нет в `data/dndsu-spells-0-6.json` и в
`data/dndsu-spell-mechanics-overrides.json`: эффективный профиль всех 439
заклинаний сейчас имеет `components: 0/439`. Поэтому текущая серверная проверка
возвращает `SPELL_COMPONENTS_UNKNOWN` для 2014-профиля, пока конкретный профиль
не получил source-backed данные. Для `srd_5_2_1` общий availability сейчас
сохраняет совместимость и возвращает `available: true`.

Единственный готовый costly-пилот — `chromatic-orb`: требуется каталожный алмаз
стоимостью не менее 50 зм, деньги, фокус и дешёвый камень не подходят; алмаз не
расходуется. Это проверка наличия, а не полное покрытие компонентов.

Расходуемые материалы пока не исполняются. Для `arcane-lock`,
`continual-flame`, `stoneskin`, `find-familiar` и `revivify` ещё нет общего
подбора реального каталожного предмета и события `ItemConsumed`, связанного с
`CastSpell`. Наличие записей фокусов, сумки и `diamond-50gp` в
`server/item-catalog.mjs:888-1003` само по себе не подключает их к заклинанию.

Минимальная source-backed форма для следующих пилотов:

```json
{
  "components": {
    "verbal": true,
    "somatic": true,
    "material": {
      "description": "алмаз",
      "costGp": 50,
      "consumed": false,
      "focusSubstitutable": false
    }
  }
}
```

Для материала без объявленной цены нужно хранить `costGp: null`, а не выводить
нулевую цену из свободного текста. Пилоты должны отдельно описывать
`focusSubstitutable`, `consumed` и, для особых материалов, каталожный тип.

## Требования источника

Правила компонентов 2014 года говорят следующее:

- V требует слышимых магических слов; кляп и область `silence` запрещают
  заклинания с V.
- S требует свободной руки.
- M можно заменить сумкой с компонентами или допустимым фокусом, если у
  компонента нет объявленной цены. Компонент с ценой должен быть реальным
  предметом; деньги не заменяют его.
- Расходуемый M нужно предоставить при каждом накладывании. Рука, которая
  держит M или фокус, может одновременно выполнять S.

Первичный источник: [D&D Beyond — Spellcasting 2014](https://www.dndbeyond.com/sources/dnd/basic-rules-2014/spellcasting).
Инвентарь фокусов и сумки: [D&D Beyond — Equipment 2014](https://www.dndbeyond.com/sources/dnd/basic-rules-2014/equipment).

Классовый фокус нельзя заменить одним универсальным `classKey` без проверки
самого типа предмета. В PHB 2014 подтверждены музыкальный инструмент для барда,
святой символ для жреца и паладина, друидический фокус для друида и арканный
фокус для чародея, колдуна и волшебника. В Basic Rules 2014 у следопыта
отдельного раздела Spellcasting Focus нет: [D&D Beyond — Ranger 2014](https://www.dndbeyond.com/sources/dnd/basic-rules-2014/classes).
На `dnd.su` друидический фокус для следопыта отмечен как отдельная
опциональная возможность TCE, поэтому её нельзя включать в базовый
`dnd_5e_2014` автоматически: [dnd.su — Ranger](https://5e14.dnd.su/class/97-ranger/), раздел «Заклинательная фокусировка».

## Реакции, подготовка и длительное накладывание

`CastSpell` сначала разрешает возможность и ячейку, затем в исполнении может
открыть окно Counterspell до `ResourceSpent`
(`server/rules-engine.mjs:13303-13394`). При успешном Counterspell текущий код
самостоятельно списывает ячейку исходного заклинателя и пишет `SpellCast` с
`countered: true` (`server/rules-engine.mjs:12683-12711`). Компонентная
резервация и политика расхода материала для этого промежуточного исхода ещё не
определены событием; её нельзя случайно получить порядком анимации или UI.

Долгое накладывание сейчас запрещено в активном бою
(`server/rules-engine.mjs:6442-6444`), а вне боя всё время продвигается одним
`TimeAdvanced` до записи результата (`server/rules-engine.mjs:13303-13311`).
Это не является продолжимой операцией: нет состояния «начато/прервано», нет
отдельного владельца ожидания и нет проверки, что при потере концентрации слот
не расходуется. Правило 2014 требует, чтобы прерванное долгое накладывание
провалилось без расхода ячейки: [D&D Beyond — Spellcasting 2014](https://www.dndbeyond.com/sources/dnd/basic-rules-2014/spellcasting).

Заготовленное заклинание теперь проверяет компоненты на старте и хранит слот до
выпуска (`server/rules-engine.mjs:12771-12803`). Выпуск повторно не должен
проверять M или списывать предмет; это означает, что будущая реализация должна
либо записывать резервирование/использованный экземпляр в `ActionReadied`, либо
явно хранить его в pending-состоянии.

## Subtle Spell, War Caster и редакции

Для `dnd_5e_2014` Subtle Spell убирает только V и S. M с ценой или расходованием
остаётся обязательным; это следует из [PHB 2014 — Sorcerer](https://www.dndbeyond.com/sources/dnd/basic-rules-2014/classes).
Для SRD 5.2.1 правило Subtle Spell шире: убираются V/S/M, кроме M с указанной
ценой или расходованием: [SRD 5.2.1](https://media.dndbeyond.com/compendium-images/srd/5.2/SRD_CC_v5.2.1.pdf).
Эти ветви нельзя смешивать.

War Caster освобождает только от требования свободной руки для S, когда руки
заняты оружием или щитом. Он не заменяет V и не создаёт дорогой или расходуемый
M. Правило «одна рука может одновременно держать M/фокус и выполнять S» остаётся
отдельной проверкой компонентов.

`spellComponentAvailabilityFor` пока полностью пропускает компонентную проверку
для `srd_5_2_1`; это совместимость текущего legacy-профиля, а не доказательство
полного покрытия 2024-компонентов.

## Магические предметы и врождённые заклинания

Правила магических предметов 2014 года задают отдельную активацию: заклинание
идёт на минимальном возможном уровне, не расходует обычную ячейку и обычно не
требует компонентов, если описание предмета не говорит обратное; концентрация
самого заклинания сохраняется. Источник: [D&D Beyond — Magic Items 2014](https://www.dndbeyond.com/sources/dnd/basic-rules-2014/magic-items).

`UseItem` для жезла волшебных стрел живёт отдельной веткой
(`server/rules-engine.mjs:18037-18092`), что соответствует этому исключению.
Эту ветку нельзя автоматически смешивать с `CastSpell` героя и Counterspell.
Другие предметные заклинания пока не имеют общего обработчика компонентов и
концентрации.

Врождённость также не является универсальным исключением. У playable Drow на
карточке PHB есть уровни, лимиты и Харизма, но нет отказа от M: [dnd.su — Elf/Drow](https://5e14.dnd.su/race/79-elf/).
У NPC Drow отдельный stat-block прямо объявляет отсутствие материальных
компонентов: [dnd.su — Drow](https://5e14.dnd.su/bestiary/145-drow/). Поэтому
`components_not_required` должен приходить только из соответствующего
source-backed trait/stat-block; `innateSpell: true` сам по себе ничего не
отменяет.

## Что ещё отсутствует

- source-pack компонентов и provenance для всех 439 ID;
- общий matcher дорогих и расходуемых предметов по каталожному типу и стоимости;
- `ItemConsumed`/резервирование для расходуемого M и его replay/idempotency;
- сохранение component override у hero species/feat grants и всех NPC entry;
- поддержка bard musical instrument как каталожного фокуса;
- отдельная политика для TCE-опционального ranger focus;
- продолжимая long-cast операция с прерыванием без расхода слота;
- явные сценарии Counterspell для нерасходуемого и расходуемого M;
- тесты на component bypass через direct `resolveCommand`, `readiedRelease`,
  additional beam и item path.

До появления этих частей компонентная система остаётся пилотом: `chromatic-orb`
проверяет costly-материал, расходуемые компоненты ещё не исполняются, а статус
439 заклинаний не повышается автоматически.
