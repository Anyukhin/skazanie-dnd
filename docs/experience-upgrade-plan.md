# План доработок: импровизация, рассказчик, боёвка

Дата: 2026-08-02. Владелец: Антон. Статус: утверждён к исполнению, брифы формируются по этапам.

## Зафиксированные решения владельца

- Приоритеты: (1) рассказчик реагирует на любую импровизацию, (2) качество рассказчика и долгая память кампании, (3) глубина боёвки — все четыре направления сразу.
- Два режима импровизации: **«хаос»** (игроки могут всё, режиссёр перестраивает сюжет и создаёт локации на лету) и **«сюжетный»** (странные действия разрешены, но главный квест в приоритете). Выбирается при старте кампании; админ может переключить по ходу.
- Генерация локаций в хаос-режиме — **без жёсткого лимита, но с алертом админу** о расходе после порога.
- Рекапы «в прошлой серии» — делаем **вместе со слоем памяти** (один источник фактов).
- TTS — **в браузере у каждого игрока** (не Discord-бот). Начинаем с Web Speech API.
- Картинки — **только заранее** (режим подготовки ассетов); в рантайме генерация сцен выключена.
- Боёвка: нужен **калькулятор сложности энкаунтеров**, масштабируемый от фактического состава партии. Бои могут быть честно смертельными, если игроки сами провоцируют («пришли в гильдию всех убивать» — гильдия отвечает в полную силу).
- Подсказки новичкам — обязательно **отключаемые/закрываемые**.
- Кап 12-го уровня остаётся. Надёжность (бэкап, двойные действия) — **отложена целиком**. Многоуровневые карты L3+ — заморожены.
- Формат игры: и кампании, и ваншоты. Состав игроков смешанный и плавающий.

## Этап 0 — Предусловия (мелкие, перед стартом)

- **0.1 Заморозка лестниц.** ОТМЕНЁН 2026-08-02: параллельный агент многоуровневых карт реализовал механику перехода между этажами (L3, коммит db7ef85) — лестницы становятся настоящими, замораживать нечего.
- **0.2 Синхронизация AGENTS.md.** Исправить ссылки на версии промптов (`social_v3`, `campaign_creator/v3`), размеры модулей — иначе агент-исполнитель будет планировать по неверной карте. Готово, когда: AGENTS.md совпадает с фактическим кодом.

## Этап 1 — Режимы импровизации

- **1.1 Настройка `improv_mode`.** Поле `chaos | story` в campaign-settings (рядом с моделью/стилем), выбор в мастере создания кампании, admin-эндпоинт переключения по ходу + событие в журнале кампании. UI: переключатель у владельца. Готово, когда: режим переживает рестарт, переключение видно в журнале.
- **1.2 Промпты режиссёра под режимы.** Новые версии `prompts/director/`: chaos-вариант (принять любое действие, перестроить арку, последствия вместо запретов) и story-вариант (принять действие, следующей сценой мягко вернуть к главной линии). Тесты на загрузку и выбор промпта по режиму.
- **1.3 Усиление action-adjudicator.** Контракт: любое физически возможное свободное действие получает проверку с осмысленной СЛ и последствиями — не отказ и не игнор. Новая версия `prompts/action_adjudicator/`. Eval-набор ~30 импровизаций («прыгаю с люстры на огра», «соблазняю стражника», «поджигаю таверну») в `eval/` с критериями качества ответа; выводы — только по парам прогонов.
- **1.4 Локации на лету + алерт.** В хаос-режиме scene-architect создаёт локации по запросу режиссёра без лимита; после порога (например, 3 за вечер) админ получает предупреждение о расходе токенов через usage-леджер. Готово, когда: алерт виден админу, расход попадает в `/api/admin/usage`.

## Этап 2 — Память кампании и рекапы

- **2.1 Слой фактов.** Модуль `campaign-memory.mjs`: после сцены извлекаются структурированные факты — обещания героев, отношения NPC к партии, долги, последствия решений (включая импровизационные: сожжённая таверна остаётся сожжённой). Хранение как события в event store, проекция в снимок.
- **2.2 Память в контексте агентов.** Выжимка фактов подаётся рассказчику, режиссёру и социальному контроллеру NPC (маркируется как недоверенные данные по существующей схеме `delimitUntrustedData`). Готово, когда: NPC во второй сессии помнит, что партия ему обещала в первой (закреплено eval-сценарием).
- **2.3 Рекап «в прошлой серии».** При открытии кампании после паузы генерируется рекап из слоя фактов; UI-карточка в начале сессии, закрываемая. Для ваншотов не показывается.

## Этап 3 — Глубина боёвки

Порядок внутри этапа — по соотношению эффект/стоимость:

- **3.1 Умная тактика NPC** (детерминированная, без LLM — `npc-turn-scheduler.mjs`): фокус огня по раненым, отход за укрытие при низких ОЗ и морали, фланги, использование дальности. Чисто логика + тесты, ноль токенов.
- **3.2 Среда как оружие.** Интеракции пропсов: опрокинуть стеллаж, поджечь разлитое масло, обрушить люстру — урон/зоны/состояния через существующий механизм `OperateSceneObject` и зоны эффектов. Связка с 1.3: adjudicator может разрешать свободные действия через эти же интеракции.
- **3.3 Калькулятор сложности энкаунтеров.** EncounterAssembler масштабирует бой от фактического состава партии (число героев, уровни) с ярлыками лёгкий/средний/тяжёлый/смертельный. Ситуационный режим «честного мира»: если партия сама провоцирует превосходящую силу, бой собирается честно смертельным, а рассказчик даёт внятное предупреждение до точки невозврата. Готово, когда: тесты покрывают партии 2–5 героев разных уровней.
- **3.4 Монстры.** По нарастающей: резисты/иммунитеты/уязвимости → recharge-способности (дыхание) → заклинания у врагов (переиспользуя движок боевой магии) → legendary actions для боссов. Каждый шаг — отдельный бриф, все касаются rules-engine, поэтому строго последовательно.
- **3.5 Расходники.** Масло, кислота, святая вода, яды, калтропы, алхимический огонь — через существующий движок областей/состояний; снять `limitation: не реализованы` в каталоге предметов.

## Этап 4 — TTS и подсказки

- **4.1 Озвучка в браузере.** Web Speech API: кнопка «озвучить» у нарратива + настройка авто-озвучки на игрока; чтение по завершении абзаца из `narration.complete`. Если качество не устроит — отдельным решением серверный TTS с кешем.
- **4.2 Подсказки «что можно сделать».** Рассказчик в конце нарратива предлагает 2–3 варианта действий для игроков с включённой настройкой; отключается/закрывается на игрока. Не показывается тем, кто выключил.

## Этап 5 — Ассеты заранее

- **5.1 Режим подготовки ассетов.** Админ-страница/команда: заранее сгенерировать и одобрить иллюстрации локаций и NPC будущей кампании (кеш в `storage/generated/`), в рантайме генерация сцен выключена флагом. Портреты NPC, создаваемых на лету в хаос-режиме, берутся из заранее одобренного пула заглушек.

## Порядок и параллельность

Этапы идут последовательно: 0 → 1 → 2 → 3 → 4 → 5, но допускаются два параллельных потока, не пересекающихся по файлам:

- **Поток A (промпты/агенты):** 1.1 → 1.2 → 1.3 → 1.4 → 2.1 → 2.2 → 2.3.
- **Поток B (детерминированная механика):** 3.1 → 3.2 (не трогают промпты; 3.3–3.5 начинать только после ревью 3.2, все правки rules-engine — строго по одному брифу за раз).

Этапы 4–5 — после ревью этапов 1–2 (4.2 зависит от промптов рассказчика).

## Отложено сознательно

Надёжность (бэкап, двойные действия при таймауте, cutover), многоуровневые карты L3–L8, кап уровня выше 12, мобильная поддержка, DOM-тесты клиента. Возвращаемся отдельным решением владельца.
