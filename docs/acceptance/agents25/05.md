# Приёмка исполнителя №05: заклинания 4-го круга

Срез выполнен 22 сентября 2026 на `HEAD c4e570921edea08f8952edef7c437bc5c9182ab3` с учётом уже находящихся в рабочем дереве изменений координатора и других исполнителей. В рамках этого исполнителя runtime, каталоги данных, тесты и Git не менялись; добавлен только этот отчёт.

Источником правил служат текущие карточки [dnd.su](https://www.dnd.su/spells/) 5e14; ссылка на карточку стоит у каждого ID. `docs/spell-source-semantic-levels-4-6.md` использован как указатель исходных ссылок и терминов, а не как доказательство текущего поведения. Текущее поведение проверено через `canonicalCombatSpellFor`, `server/spell-acceptance-audit.mjs`, ветки `CastSpell` в `server/rules-engine.mjs` и существующие тесты.

## Как читать результат

`partial` означает, что карточка проходит существующую серверную ветку и исполняет только названную безопасную часть. `heuristic` означает, что текущая авторитетная команда блокирует применение в `assertMechanicsSupported`; наличие профиля, иконки или визуального теста не является обработчиком. В круге 31 `partial` и 21 `heuristic`, `verified` нет.

Общий путь один: выбор карточки и ресурса проходит через `CastSpell` (`server/rules-engine.mjs:13687`), цели и геометрия — через `spellTargetsAt` (`server/rules-engine.mjs:8902`), затем работают общие ветки `area-save`/`save`, `buff`, `teleport` и `summon`. Unit-тесты ниже доказывают отдельные события, но не обычный HTTP/UI-путь двух игроков, replay/restart, 2D/3D, анимацию и звук.

## Воспроизведённые дефекты текущего кода

Скрипт `C:\Users\anton\AppData\Local\Temp\skazanie-agents25\05\repro-level4.mjs` запускается из корня репозитория; JSON-результат сохранён рядом в `repro-level4.json`.

1. `phantasmal-killer`: после провала начального save завершение хода заклинателя даёт `SpellSavingThrowResolved.trigger = "turn-start"` и `DamageApplied.trigger = "turn-start"`. Карточка требует повтор в конце хода цели. Это не только отсутствие теста: событие и урон наблюдаются в текущем Rules Engine.
2. `vitriolic-sphere`: при провале начального save событие `ConditionAdded` содержит `acid-covered`, но не содержит `recurring_damage`; после перехода к ходу цели не появляется ни одного recurring `DamageApplied`. Карточка dnd.su требует 5к4 кислотой в конце следующего хода. Причина видна в коде: `delayedDamage` оформляется в attack-ветке, тогда как этот ID — `area-save`.
3. `wall-of-fire`: после входа в стену и в конце хода внутри создаются `SpellSavingThrowResolved` с `trigger = "turn-end"`; при успешном save 20 урона 5к8 уменьшается до 10. Карточка требует повторный 5к8 без save с горячей стороны, а save предусмотрен только при появлении стены.
