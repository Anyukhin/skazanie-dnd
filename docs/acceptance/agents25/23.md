## Контракт и изменения

Для профиля `mass-cure-wounds` клиент читает server-owned
`selectTargetsInArea: true`: сначала игрок выбирает видимую точку в дальности
заклинания, затем кликами явно отмечает от 1 до 6 разных существ внутри сферы
30 футов. Область не подбирает цели сама, враги не становятся кандидатами, а
нейтральные существа остаются допустимыми до серверной проверки. Ячейка выше
пятого круга влияет только на лечение, поэтому лимит целей не растёт.

Точка хранится отдельно от наведённой клетки. После её фиксации карта удерживает
центр, рисует сферу и показывает `0/6`…`6/6`; повторный клик по цели снимает её.
`Enter` сразу отправляет один составной `CastSpell` с `to` и `target_ids`, без
промежуточного чипа подтверждения в строке свободного действия. `Escape`
сбрасывает точку и цели до расхода ресурса. В `Longstrider` сохранён общий
multi-target путь; select-поля получили ARIA-подписи «Источник заклинания» и
«Круг ячейки» непосредственно на самих `select`. После обновления server
profile active sphere selection также показывает видимого enemy как обычного
явно выбранного кандидата; финальная допустимость остаётся серверной.

Затронутые файлы:

- `src/DungeonMap.tsx` — двухфазный point/area target flow, Enter/Escape,
  явный target set, нейтральные цели и ARIA-подписи.
- `src/useGameSession.ts` — сериализация `to + target_ids` в CastSpell.
- `src/types.ts` — поле `selectTargetsInArea` в `CombatSpell`.
- `src/TacticalBoard.tsx` — ограничение target hint внутри краёв доски.
- `src/styles.css` — порядок четырёх строк хроники при `action-hints` на
  ширине от 1280px: подсказки больше не перекрывают сообщения.
- `test/multi-target-spell-ui.test.mjs` — контракт point-first, явного списка,
  Enter/Escape и invariant upcast без роста числа целей.
- `test/spell-targeting.test.mjs` — обновлён статический сторож обычного
  point-cast с новой веткой select-in-area.

Сервер, data-профиль, storage, зависимости и конфигурация в рамках этой роли
не менялись.

попытке после source fixes browser backend завершился: `cua.listBrowsers()`
вернул пустой список, поэтому свежие 3D-кадры и запись `Uint8Array` через
`node:fs/promises` получить не удалось. Предыдущий CUA runtime не предоставил
локальный путь сохранения inline bytes; отдельный файл кадра не заявляю и не
выдаю путь-заглушку за артефакт. Остались непроверенными свежий 3D-рендер,
второй браузерный игрок и точные числа лечения в DOM; server profile №08 и его
replay/idempotency тесты это покрывают отдельно.
