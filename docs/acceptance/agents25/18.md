## Источник и дефект

Проверен источник D&D 2014: [DnD.su — «Божественное оружие»
(Spiritual weapon)](https://www.dnd.su/spells/11-spiritual-weapon/). В карточке
указано: 2-й уровень, бонусное действие, дистанция 60 футов, длительность
1 минута; оружие существует, пока заклинание активно, либо пока заклинание не
наложено снова. Длительность и повторное наложение — проверены; прочие семьи
призывов по отдельным страницам не объявляются проверенными.

В базовом движке ветка `spell.kind === 'summon'` создавала фишку и помещала её
сразу после владельца в инициативу, но не сохраняла `durationRounds` на
экземпляре. Поэтому `spiritual-weapon` (концентрация не нужна) оставался на
карте после десяти раундов. Тест-кандидат на базовом срезе воспроизвёл это:
`undefined !== 11` при проверке ожидаемого дедлайна.

## Patch-кандидат и regression

Файлы сохранены только во временном каталоге:

- [summon-expiry.patch](C:/Users/anton/AppData/Local/Temp/skazanie-agents25/18/summon-expiry.patch)
- [baseSHA](C:/Users/anton/AppData/Local/Temp/skazanie-agents25/18/baseSHA)
- тест внутри временной копии: `C:\Users\anton\AppData\Local\Temp\skazanie-agents25\18\repo\test\summon-expiry-candidate.test.mjs`

Patch делает две связанные вещи: при создании боевого призыва фиксирует
`expires_round` в событии `SummonedCreatureCreated`, а при переходе в истёкший
раунд добавляет в поток `SummonedCreatureDismissed` с причиной
`duration_expired`. Дедлайн едет в событии, поэтому replay не перечитывает
текущую карточку заклинания. Концентрирующиеся призывы по-прежнему снимаются
раньше через `ConcentrationEnded`.

Фактические проверки:

- базовый тест в копии `repo-before`: ожидаемо красный, `undefined !== 11`;
- `git apply --check` patch относительно указанного base SHA: успешно;
- patched `node --test test/summon-expiry-candidate.test.mjs`: `1 pass, 0 fail`.

Полный `pnpm verify` не запускался. Shared `server/`, `test/`, `src/`,
`data/` и runtime не изменялись; в репозитории добавлен только этот отчёт.

## Собственный HTTP-срез и браузер

Поднят отдельный сервер на `http://127.0.0.1:8898` с пустым
`ROUTERAI_API_KEY`, `GAME_ENGINE_MODE=enforce` и временным хранилищем
`C:\Users\anton\AppData\Local\Temp\skazanie-agents25-18-storage`.
`GET /api/health` вернул 200 до попытки CUA. Через обычные HTTP auth endpoints
созданы тестовый admin и игрок; затем в кампании `SUMMON-18I` игроку импортирован
жрец 5-го уровня с подготовленным `spiritual-weapon` (state version 13).
Подготовленный UI-маршрут: `/` → вход игрока → кампания `SUMMON-18I` → выбрать
«Божественное оружие» → выбрать свободную видимую клетку → подтвердить → увидеть
фишку и затем её исчезновение на границе минутной длительности.

Обязательный собственный browser-сценарий выполнить не удалось: после
`cua.getState()` инвентарь сначала показал IAB, но `cua.listBrowsers()` вернул
пустой список, а `cua.createBrowserTab('iab', ...)` и `cua.getBrowser(...)`
завершились `Browser is not available`. Вкладки root и порт 8798 не трогались.
Кадр не создан из-за отсутствующего провайдера; этот UI-путь остаётся
непроверенным и требует повторного запуска при доступном CUA. HTTP-сервер и
его временные данные после среза подлежат остановке/удалению владельцем
координации.

Остаток по назначению: полные опубликованные статблоки вариантов духов,
команды бездействия/уклонения, переходы сцен и срок вне боя требуют отдельных
проверок. Наличие фишки, теста или подготовленного HTTP-состояния не считается
браузерной приёмкой.
