# Исполнитель №01: заговоры, 44 ID

Срез проверен на ветке `codex/spell-acceptance-pilots`, относительно базового
SHA `c4e570921edea08f8952edef7c437bc5c9182ab3`, с уже присутствующими правками
координатора. Прямой сайт в этой работе не открывался: источник dnd.su взят из
зафиксированного семантического отчёта
[`docs/spell-source-semantic-levels-0-1.md`](../../spell-source-semantic-levels-0-1.md).
Профиль каталога, наличие override или визуального ассета не считаю доказательством
полной механики.

В текущем каталоге 44 заговора: 32 `partial` допускаются до авторитетного
`CastSpell`, 12 `heuristic` блокируются `MECHANICS_NOT_VERIFIED`; `verified` и
полностью принятых заговоров нет. Семантический отчёт для этих же ID даёт
`shortdescriptionok` 2, `mismatch` 25, `mechanicsgap` 17. Общий профиль аудита
помечает все пять обязательных измерений (`rules`, `playerPath`, `resilience`,
`permissions`, `presentation`) как `pending` для каждого ID.

Общий путь для каждой карточки проходит через `server/combat-spells.mjs` и
`server/rules-engine.mjs:887,13712`; `assertMechanicsSupported` разрешает лишь
`partial`/`verified`. Для разрешённых карточек движок использует общие ветки
атаки (`rules-engine.mjs:14048`), спасброска/области (`:14415`) и усиления
(`:14848`), а масштабирование костей за уровень заговора —
`scaledSpellDice` (`:8397`). Это подтверждает существование общего обработчика,
но не закрывает индивидуальные исключения, обычный HTTP/UI-путь, replay,
права и ручную двухигровую проверку.

Общие зависимости аудита у всех 44: `spell-acquisition`, `target-validation`,
`resource-selection`, `component-contract`. В таблице ниже `+area` означает
`area-geometry`, `+condition` — `condition-lifecycle`, `+concentration` —
концентрацию, `+long-cast` — `long-casting-phases`. В колонке «тесты» указаны
только содержательные прямые проверки; тесты палитры/иконок/галереи не считаются
проверкой механики.

## Приоритетные дефекты с воспроизведением

Все repro ниже используют только временные состояния и внедрённый
`SequenceDiceRng`; runtime/data не менялись.

1. **`lightning-lure`: condition не является притягиванием.**
   [`repro-lightning-lure.mjs`](C:/Users/anton/AppData/Local/Temp/skazanie-agents25/01/repro-lightning-lure.mjs)
   ставит врага в 15 фт., даёт провал Str save (d20=1). Результат: в событиях
   нет `ActorMoved`, позиция остаётся `{x:4,y:1}`, но `DamageApplied` наносит 7
   lightning. В D&D 2014 урон должен зависеть от того, оказался ли враг после
   притягивания в 5 фт.; текущий профиль не задаёт pull geometry.

2. **`green-flame-blade`: вторичная цель не выбирается игроком.**
   [`repro-green-flame-blade.mjs`](C:/Users/anton/AppData/Local/Temp/skazanie-agents25/01/repro-green-flame-blade.mjs)
   ставит две допустимые вражеские цели рядом с первичной. При обычной команде
   только `target_ids: ['target']` secondary damage автоматически уходит в
   `enemy-a` — первый ID после сортировки; `enemy-z` остаётся с 30 HP. Явного
   `secondary_target_id` нет, союзника выбрать нельзя, а попытка передать две
   цели упирается в лимит одной основной цели.

3. **`shillelagh`: condition записывается, но weapon attack не меняется.**
   [`repro-shillelagh.mjs`](C:/Users/anton/AppData/Local/Temp/skazanie-agents25/01/repro-shillelagh.mjs)
   после успешного каста показывает `condition: shillelagh`, затем обычный удар
   той же дубинкой возвращает `attackAbility: str`, `damageExpression: 1d6`.
   Ожидается spell ability (Wis для друида) и d8; в `CONDITION_EFFECTS` и
   item attack profile нет потребителя `shillelagh`.

Близкий четвёртый риск — `booming-blade`: текущая ветка в
`rules-engine.mjs:15328` срабатывает и на forced/reaction movement, потому что
проверяет только ненулевую дистанцию. Он уже имеет прямой тест добровольного
перемещения, поэтому его нужно расширить одновременно с исправлением трёх
дефектов выше.
