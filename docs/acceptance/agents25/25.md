## Результат

Найден один воспроизводимый дефект в прямом phase API `src/combat-audio.ts`.
После `playCue(cue, 'start')` вызов `playCue(cue, 'contact')` возвращал `false` для
того же подтверждённого cue: `seenCueIds.has(cue.id)` блокировал всю последующую
запись, хотя `playedKeys` различает ключи `cue_id:phase`. Одного удаления guard
недостаточно: оно разрешало бы поздний contact после cancel/hidden и прямой contact
параллельно уже запланированному `schedule(cue)`.

Корректированный patch-кандидат сохранён в
`C:\Users\anton\AppData\Local\Temp\skazanie-agents25\25\combat-audio-phase-dedupe.patch`.
Он оставляет `seenCueIds` для queue/SSE dedupe, добавляет bounded sets
`scheduledCueIds`, `cancelledCueIds` и `directCueIds`. Direct IDs сохраняются даже
после окончания source; explicit `cancel(cue_id)` и `cancel()` по известным direct
IDs блокируют позднюю загрузку. Preview namespace обходит cancelled guard, поэтому
preview replay сохраняется:

```diff
-      if (!cueOptions.preview) remember(seenCueIds, cue.id)
+      if (!cueOptions.preview) {
+        remember(seenCueIds, cue.id)
+        remember(scheduledCueIds, cue.id)
+      }
-      return play(cue, phase, cueOptions)
+      if (!cueOptions.preview) remember(directCueIds, cue.id)
+      return play(cue, phase, cueOptions, true, () => cueOptions.preview || !cancelledCueIds.has(cue.id))
+    for (const cueId of cueIds) remember(cancelledCueIds, cueId)
```

Повторный вызов одной фазы блокируется `playedKeys`; `cancel()` помечает и
остановленные active voices, scheduled entries и pending direct cues.

Регрессионный patch теста находится в
`C:\Users\anton\AppData\Local\Temp\skazanie-agents25\25\combat-audio-phase-dedupe.test.patch`.
Он проверяет start → contact, повтор contact, start → cancel → contact, start →
hidden → contact, schedule → direct contact, explicit cancel после завершившегося
FakeSource, preview replay и cancel во время отложенного loader/decode. На копии
существующего `test/combat-audio.test.mjs` baseline: 17/19 PASS (ожидаемо падают
direct contact и pending cancel); patched candidate: 19/19 PASS. Shared `src/` и
`test/` не изменялись. Оба patch-файла проходят `git apply --check` (exit 0).

## Сопоставление с BG3/Larian

Официальные материалы Larian описывают звук как часть обратной связи и микса:
в [Community Update 14](https://baldursgate3.game/news/community-update-14-forging-the-arcane_44)
упомянут dynamic mixing для combat/music/ambience; в [Patch 1](https://baldursgate3.game/news/patch-1-now-live_87)
исправлены поздние и обрезанные SFX, уровни в боевых сценах и намеренная тишина;
в вакансии Larian для Soundscape Designer отдельно указаны interactive mixing
и loudness standards ([Larian Studios](https://larian.com/careers/c79d63e7-de3e-4327-aede-b0a3d85ea3eb)).
Практический вывод для этой проверки: фаза и исход должны быть связаны с
подтверждённым событием, отмена не должна «воскресить» звук, а уровень и
компрессор должны оставлять запас. Это ориентир постановки и feedback, не
замена правилам D&D 2014 и не доказательство того, что все 439 карточек
уникально озвучены.
