## Что найдено в текущем matcher-е

Единственный текущий путь — `spellComponentAvailabilityFor` в
`server/rules-engine.mjs`, с поиском через `spellMaterialItemFor`. Он проверяет
один `costGp` и один каталожный `material_component` с `spell_ids`, возвращает
первый подходящий экземпляр и не различает атомы набора. На входе с
`material.unresolved` он останавливается до поиска инвентаря. Расходующий путь
`spellComponentCostEvents` читает только общий флаг `material.consumed` и всегда
списывает одну единицу одного предмета. Поэтому существующий код не выражает
явные OR/AND, количество, смешанный расход (часть набора расходуется, часть
остаётся) или динамическое «по одному на цель».

## Минимальный patch-кандидат

В `%TEMP%/skazanie-agents25/13/complex-material-requirements.patch` оставлен
bounded patch только для существующего matcher-а. Он добавляет структурные
узлы:

```json
{
  "allOf": [
    { "anyOf": [
      { "item": { "materialKinds": ["kind-a"], "minimumValueCp": 5000, "quantity": 1, "consumed": false } },
      { "item": { "catalogIds": ["srd_5_2_1:item-b"], "quantity": 1, "consumed": false } }
    ] },
    { "item": { "materialKinds": ["kind-c"], "minimumValueCp": 10000, "quantity": 2, "consumed": true } }
  ]
}
```

Сопоставление идёт только с серверным каталогом по `catalog_id`,
`material_component.kind`, `material_component.value_cp` и `spell_ids`. Имя,
описание и присланный клиентом `material_component` не используются. Resolver
резервирует количество при каждом AND-узле, поэтому один стек не удовлетворяет
двум атомам сверх своей `quantity`; OR выбирает одну ветку. Расход формируется
отдельно для каждого атома с `consumed: true`, а не по общему флагу всего
заклинания. Добавлен лимит поиска состояний 256, чтобы недоверенная структура
не превратила проверку в неограниченный перебор.

Кандидат намеренно не добавляет новые предметы, валютный платёж, provenance,
межактерную экипировку или динамические цели. Поэтому он не повышает статус ни
одной из 13 карточек и не объявляет обычный пользовательский CastSpell
готовым. Тестовый fixture использует уже существующие каталожные записи
алмаза/алмазной пыли, но структура повторяет форму `legend-lore`: OR одного
постоянного атома плюс AND двух расходуемых единиц.

## Браузерная smoke-проверка

Собственная Temp-копия запускалась с пустым `ROUTERAI_API_KEY`, отдельным storage
`C:\Users\anton\AppData\Local\Temp\skazanie-agents25\13\storage-bind` и
портом `8894`. Маршрут проверки: `GET /api/health`, затем предполагался обычный
UI-путь карточки заклинания и отказ до расходования компонента. Сервер локально
поднялся (`http://0.0.0.0:8894`, demo mode), но IAB не смогла открыть его в
собственной вкладке: для `127.0.0.1`/локального адреса — `ERR_BLOCKED_BY_CLIENT`,
для `host.docker.internal:8894` — `ERR_CONNECTION_REFUSED`, для `0.0.0.0` —
`ERR_ADDRESS_INVALID`. Поэтому получение компонента, выбор действия и отказ
обычного игрока через UI не достигнуты и не считаются приёмкой.

`mcp__cua_repl` зафиксировал эти ошибки навигации; снимок страницы приложения
не получен, поэтому абсолютного пути к локальному PNG нет: страница приложения
до кадра не загрузилась.
Созданные agent-вкладки с error page закрыть через CUA не удалось: Browser Use
запретил навигацию к внутреннему `data:` error document; root-вкладки не
использовались. Собственный сервер после попытки остановлен.

### Повторная попытка после требования проверить `/api/health`

Сервер той же Temp-копии был поднят на `127.0.0.1:8893` со storage
`C:\Users\anton\AppData\Local\Temp\skazanie-agents25\13\storage-browser`
и пустым ключом LLM. До любого вызова CUA выполнен preflight:

```text
GET http://127.0.0.1:8893/api/health -> 200
{"configured":false,"provider":"RouterAI", ...}
```

После этого CUA-инвентарь вернул `browsers: []`, а попытка открыть свою IAB
вкладку завершилась `Browser is not available: iab`. Прочитанный bundled
`browser-troubleshooting.md` требует при недоступном backend-е сообщить блокер и
не подменять его unrelated browser tool или обходом security. Поэтому UI-сценарий
с компонентом не выполнен: screenshot bytes не получены, локальный кадр не
создавался. Сервер после проверки остановлен. Это повторяет честную границу:
серверный preflight подтверждён, браузерная приёмка заблокирована окружением.
