## Источник и границы

В D&D 5e 2014 свойство `Loading` ограничивает выстрел из конкретного оружия
одним боеприпасом при расходе `action`, `bonus action` или `reaction`, даже если
у существа есть Extra Attack. Crossbow Expert снимает это ограничение только
для арбалетов. Боеприпас расходуется отдельным уже существующим путём
`AmmunitionSpent`; перезарядка не моделируется как дополнительное событие.

Источники и локальный контекст: [оружие и боеприпасы dnd.su](https://www.dnd.su/articles/inventory/96-arms/),
`docs/acceptance/agents25/22.md`, `docs/attack-completion-audit.md`.

## Воспроизведение дефекта

Старый кандидат хранил один `loading_weapon_item_id`. После выстрелов из
экземпляров A и B значение становилось B, поэтому третий выстрел A проходил.
Та же схема не различала действие, бонусное действие и реакцию.

## Кандидат

Patch: [loading-attacks.patch](C:/Users/anton/AppData/Local/Temp/skazanie-wave10/06/patch/loading-attacks.patch).

В `action_economy` добавлен нормализованный серверный реестр
`loading_weapon_item_ids: { action, bonus_action, reaction }`; в каждом списке
хранятся идентификаторы экземпляров, а не catalog id. AttackResolved фиксирует
`loading_action_type` и решение `loading_limit_applies` в событии, поэтому replay
не пересчитывает исключение по изменившемуся листу героя. Action Surge и переход
к следующему действию очищают только action-список; TurnStarted очищает все три.
Вложенные `weapon_attack` прокидывают тип ресурса для bonus/reaction атак и не
тратят обычное action повторно. Crossbow Expert сверяет авторитетный ключ
каталога (`light-crossbow`, `hand-crossbow`, `heavy-crossbow`), поэтому имя
экземпляра не может превратить blowgun или pistol в арбалет.

Пустой боезапас проверяется до броска и до записи marker. Crossbow Expert
распознаётся только для арбалета; духовая трубка, мушкет и пистолет остаются
под ограничением Loading.

## Интеграция, HTTP и CUA

`git apply --check` для patch проходит на текущем дереве `codex/combat-wave10`.
Ветка содержит параллельные изменения других исполнителей; patch не удаляет их
и не меняет shared runtime в ходе этой работы.

Законный HTTP и CUA сценарий оставлен для root после интеграции и запуска стенда:

1. В кампании `dnd_5e_2014` создать fighter 5 уровня с двумя экземплярами
   `light-crossbow` и запасом `bolts-20`, открыть бой двумя обычными сессиями.
2. В первой сессии выполнить выстрел из A, затем из B, затем снова выбрать A.
   Третий запрос должен получить серверный `LOADING_WEAPON_LIMIT`; `AmmunitionSpent`
   и новый `AttackResolved` для отказа отсутствуют.
3. Выполнить Action Surge и выстрелить из A ещё раз. Для законного bonus
   `quick-toss` выбрать метательный кинжал; в окне `readied-attack` проверить
   независимый reaction marker. После reload состояние должно совпасть с replay.
   UI должен показать обычный серверный отказ, не принимать клиентский
   item/profile или `reaction_attack` как источник правила.

Браузерный кадр этим кандидатом не заявляется: CUA запуск требует готового
изолированного HTTP-стенда root, чтобы не конкурировать с его login/logout и
портом.
