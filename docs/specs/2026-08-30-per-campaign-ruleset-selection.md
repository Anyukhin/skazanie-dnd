# Выбор редакции правил для кампании

Статус: проверена
Создана: 2026-08-30
Обновлена: 2026-08-30
Связано: [`ADR-0003`](../decisions/0003-campaign-bound-ruleset-lock.md),
[`cutover D&D 2014`](2026-08-30-dndsu-2014-ruleset-cutover.md), ветка
`codex/specifications`
Заменена: нет

## 1. Зачем это нужно

Владелец мира должен явно выбрать классическую D&D 5e 2014 или ревизию 2024,
а сервер — исполнять и воспроизводить выбранные правила без глобального
переключения всех кампаний. Выбор должен быть видим при создании и в настройках.

## 2. Текущее поведение до доработки

- Сервер загружал один process-wide ruleset по умолчанию.
- Мастер мира не спрашивал редакцию.
- Настройки показывали глобальный ruleset сервера, а не кампании.
- Поля ruleset уже существовали в состоянии, но не образовывали пользовательский
  контракт выбора.

## 3. Желаемое поведение

- В мастере мира доступны `D&D 5e 2014` и `D&D 2024`.
- 2014 выбран по умолчанию как целевая редакция проекта и явно помечен
  `preview`; 2024 помечен как стабильный текущий профиль.
- Сервер сам закрепляет `ruleset_id`, версию, packs и обязательные house rules.
- Владелец или администратор может изменить редакцию в настройках, пока в
  журнале нет ни одного игрового события.
- Смена сохраняется событием `CampaignRulesetChanged`, синхронизируется с
  metadata Event Store и одинаково восстанавливается replay.
- Первое событие, не являющееся сменой ruleset, необратимо блокирует селектор.
- Admin-only импорт готового состояния без журнала сразу блокирует селектор и
  принимает version/packs только из серверного реестра.
- Существующие кампании и старые API-вызовы без выбора остаются на
  `srd_5_2_1`; автоматической конвертации нет.

## 4. Пользовательский сценарий

1. Владелец открывает мастер мира и выбирает редакцию.
2. Перед созданием итоговый экран ещё раз показывает выбор.
3. Сервер создаёт кампанию с соответствующим lock-профилем.
4. До первого игрового события владелец может открыть настройки и изменить
   редакцию.
5. После импорта героя, паузы, хода или другого события настройка становится
   read-only и объясняет причину.

## 5. Правила и ограничения

- Ruleset принадлежит кампании, а не процессу, пользователю или устройству.
- Клиент не задаёт версию, packs, source metadata и обязательные house rules.
- Неизвестный или недоступный профиль отклоняется сервером.
- Cross-edition `source_rule_ids` отклоняются до исполнения команды.
- Preview 2014 включает явное правило совместимости
  `skazanie:2014-preview-legacy-catalogs-v1`: расы, предыстории, starter kit,
  предметы и бестиарий ещё не полностью разделены по редакциям.
- Переключение начатой кампании и переписывание старых событий не входят в
  доработку.

## 6. Технический план

- Реестр профилей и server-owned lock: `server/ruleset-config.mjs`.
- Event-sourced смена и вычисление блокировки: `server/campaign-ruleset.mjs`.
- Создание, settings API и metadata: `server/index.mjs`,
  `server/campaign-bootstrap.mjs`, `server/authoritative-executor.mjs`.
- Provenance и edition-sensitive ветки: `server/rules-engine.mjs`.
- Мастер мира и настройки: `src/AppViews.tsx`, `src/App.tsx`.
- Честное предупреждение при создании героя 2014:
  `src/CharacterCreationWizard.tsx`.

## 7. Критерии готовности

- [x] Обе редакции доступны в мастере мира и итоговом экране.
- [x] Выбранная редакция отправляется при создании и видна в списке кампаний.
- [x] Сервер закрепляет версию и packs, не доверяя этим полям клиента.
- [x] Настройки показывают ruleset конкретной кампании.
- [x] Pre-game смена событийная, идемпотентная и совпадает после replay.
- [x] После первого игрового события смена возвращает `409`.
- [x] Rule provenance не допускает смешения установленных редакций.
- [x] Основные уже перенесённые различия 2014/2024 покрыты тестами.
- [x] Пройден полный `pnpm verify`.
- [x] Пройден ручной браузерный сценарий создания и смены.
- [x] Ограничения preview 2014 видимы в интерфейсе и документации.

## 8. Проверка

```bash
pnpm rules:verify
pnpm content:verify
pnpm spells:verify
pnpm verify
```

Ручной сценарий: создать мир 2014, убедиться в предупреждении preview, сменить
на 2024 в настройках до первого события, вернуть 2014, создать первое игровое
событие и проверить read-only состояние селектора.

## 9. Итог реализации

Реализован per-campaign выбор двух редакций, server-owned lock, событийная
pre-game смена, защита от гонок и повторов idempotency key, актуальная metadata
Event Store и блокировка raw-import без журнала. Preview 2014 разводит
provenance, включая свободный текст и вложенные боевые команды, и несколько
поведенческих правил: `Indomitable`, условия работы `Aura of Protection`,
лечение Hit Die, восстановление Hit Dice длинным отдыхом, а также цену действия
зелья лечения и противоядия у героев и NPC.

`pnpm verify` прошёл: основной корпус — 2730/2730, отдельный полный
MVP-сценарий — 1/1, затем зелёные server typecheck и production build.
`pnpm rules:verify` прошёл 156/156; `content:verify` и `spells:verify` зелёные.
В браузере проверены обе карточки мастера мира, создание миров 2014 и 2024,
смена в настройках с сохранением после reload и живая блокировка после события
`CampaignPaused`. Права второго аккаунта проверены реальным HTTP-тестом; прямой
переход по invite URL в тестовом браузере был остановлен политикой безопасности
Browser Use и не использовался как обходной путь.

## 10. Открытые вопросы

- Нужна ли отдельная пользовательская настройка редакции по умолчанию для
  будущих миров; сейчас основной мастер по продуктовому решению начинает с 2014.
- Когда завершение каталогов 2014 позволит удалить compatibility house rule.
