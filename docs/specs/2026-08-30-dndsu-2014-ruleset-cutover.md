# Переход на D&D 5e 2014 по dnd.su

Статус: в работе
Создана: 2026-08-30
Обновлена: 2026-08-30
Связано: [`ADR-0002`](../decisions/0002-dndsu-2014-authoritative-ruleset.md), ветка `codex/specifications`
Заменяет: направление на SRD 5.2.1 / 2024 для новых кампаний
Заменена: нет

## 1. Зачем это нужно

Игрок должен понимать, по какой редакции разрешается действие, а сохранённая
кампания — получать тот же результат после обновления проекта. Сейчас один
`ruleset_id` скрывает смесь 2014, 2024 и домашних правил. Переход создаёт
проверяемую основу механической честности из
[`product-principles.md`](../product-principles.md#правила-dd-и-сходство-с-baldurs-gate).

## 2. Текущее поведение

- Process-wide и legacy API default используют `srd_5_2_1` / 2024; основной
  мастер мира позволяет явно выбрать partial preview `dnd_5e_2014`.
- Выбор хранится в кампании, меняется событием до первого игрового события и
  затем блокируется.
- Классовые каталоги уже помечены `dndsu-5e-2014-official`.
- Предыстории и часть создания героя следуют 2024.
- Предметы и расходники в основном содержат правила 2024; цена действия зелья
  лечения и противоядия уже ветвится для 2014.
- Заклинания dnd.su включают PHB и официальные дополнения без per-card book
  allowlist; один из подтверждённых overrides (`resistance`) использует 2024.
- Бой всё ещё смешанный, но `Indomitable`, условие работы `Aura of Protection`,
  лечение Hit Die и восстановление Hit Dice уже ветвятся по редакции.
- Аудит foundation обнаруживает около 1200 вхождений `srd_5_2_1` в 114 файлах.

Полный снимок — [`../ruleset-2014-cutover-audit.md`](../ruleset-2014-cutover-audit.md)
и [`../../data/ruleset-cutover-2014.json`](../../data/ruleset-cutover-2014.json).

## 3. Желаемое поведение

- Новая кампания фиксирует явно выбранный `dnd_5e_2014` или `srd_5_2_1` и
  точную версию локального pack.
- До первого игрового события владелец может изменить выбор в настройках;
  смена событийная и после начала игры блокируется.
- Rules Engine, retrieval, предметы, классы, заклинания, существа и экономика
  выбирают данные по ruleset кампании.
- Core содержит только PHB/DMG/MM 2014; дополнения включаются отдельно.
- Каждое намеренное отступление имеет versioned `house_rule_id`.
- Существующая кампания `srd_5_2_1` продолжает replay с прежними каталогами и
  результатами.
- Runtime никогда не обращается к dnd.su.

## 4. Пользовательский сценарий

1. Владелец выбирает D&D 2014 или D&D 2024 в мастере мира.
2. Сервер записывает ID редакции, версию pack и включённые дополнения.
3. Игрок выбирает героя, предмет или заклинание только из разрешённого корпуса.
4. Rules Engine разрешает действие по локальным данным 2014 и сохраняет
   versioned provenance.
5. После обновления и restart replay даёт тот же результат.
6. Старая кампания 2024 открывается без автоматической конвертации.
7. Настройка редакции доступна только до первого игрового события.

## 5. Объём и границы

### Входит

- локальный pack, source registry и allowlist;
- per-campaign выбор pack;
- отдельные каталоги 2014 для героев, предметов, заклинаний и существ;
- поведенческие волны по всем edition-sensitive механикам;
- обратная совместимость старых кампаний;
- integrity, provenance, replay и activation gates.

### Не входит

- полные тексты страниц или книг;
- автоматическая миграция рабочего `storage/`;
- UA, homebrew, unofficial и сторонние книги;
- молчаливое добавление официальных дополнений в core;
- переименование 2024-данных без повторной сверки механики.

## 6. Правила и ограничения

- При конфликте фактов одна сущность переносится целиком из одной редакции.
- Сайт — источник проверки, но не runtime API.
- Старые catalog/stat-block/rule IDs неизменяемы для replay.
- `mechanics_status` повышается только вместе с command/event/reducer и тестами.
- Данные с неустановленными правами блокируют публичный release.
- До завершения activation gate 2014 всегда обозначается как partial preview и
  получает явный compatibility house rule, а не ложный статус полной поддержки.

## 7. Совместимость и данные

Переход аддитивный. `srd_5_2_1` остаётся установленным и обслуживает старые
потоки. `dnd_5e_2014` использует новый namespace. Миграция существующих событий,
snapshots, `catalog_id`, `stat_block_id` и `source_rule_ids` не выполняется.

Process-wide активация 2014 допустима только после закрытия всех доменов в
`data/ruleset-cutover-2014.json`. Per-campaign partial preview уже доступен и
не ослабляет этот gate.

## 8. Технический план

1. **Foundation — выполнено в этой ветке.** Добавить локальный pack,
   source registry, машиночитаемый cutover inventory и audit gate.
2. **Выбор по кампании — выполнен для профиля, persistence и core
   provenance.** Оба pack установлены, мастер и настройки выбирают ruleset,
   смена до начала игры сохраняется событием, Retriever фильтруется по
   `ruleset_id`, а preview-pack нельзя поставить process-wide default. Каталоги
   механики ещё нужно полностью разделить по кампании.
3. **Герой.** Виды/бонусы, backgrounds, starter kit, классы и progression 2014.
4. **Заклинания и общий бой — начато.** Отфильтровать источники, исправить
   оставшиеся 2024 overrides, состояния, отдых и экономику действия. Уже
   разведены `Indomitable`, `Aura of Protection` и базовая механика Hit Dice.
5. **Предметы и экономика.** Новый namespace, цены, attunement, action cost и
   расходники 2014.
6. **Существа и встречи.** Цельные стат-блоки 2014, encounter multiplier,
   spell slots, saves/skills/senses.
7. **Activation.** Переключить только новые кампании, выполнить полный replay,
   HTTP, browser и release audit; старый pack оставить доступным.

## 9. Критерии готовности

### Foundation

- [x] Решение записано ADR.
- [x] Локальный `dnd_5e_2014` загружается и валидируется.
- [x] Русский язык может быть каноническим для pack.
- [x] Каждое базовое правило связано с внешним source registry.
- [x] Полные тексты dnd.su не включены.
- [x] Core allowlist и default-deny для дополнений зафиксированы.
- [x] Audit gate не позволяет объявить активацию при незакрытых доменах.
- [x] Оба pack установлены одновременно, а Retriever не смешивает редакции.
- [x] Preview-pack нельзя поставить process-wide runtime default через environment.
- [x] Мастер мира выбирает 2014/2024 и показывает выбор в итогах.
- [x] Настройки меняют ruleset событием только до первого игрового события.
- [x] Server-owned version/packs нельзя подменить клиентским запросом.
- [x] Cross-edition `source_rule_ids` отклоняются.

### Полный cutover

- [ ] Все Retriever и каталоги выбираются по кампании и не смешивают редакции.
- [ ] Создание и развитие героя соответствуют 2014.
- [ ] Заклинания core имеют per-card edition/book provenance.
- [ ] Предметы, экономика и расходники соответствуют 2014.
- [ ] Бестиарий и encounter budget соответствуют 2014.
- [ ] Edition-sensitive combat/rest/environment правила соответствуют 2014
  либо объявлены house rules.
- [x] Новая кампания может создаваться как preview `dnd_5e_2014` или
  `srd_5_2_1` через штатный HTTP/UI-контракт.
- [ ] Старая `srd_5_2_1` кампания совпадает после replay/restart.
- [ ] Права и release policy проверены отдельно.

## 10. Проверка

### Автоматическая

```bash
pnpm rules:verify
pnpm content:verify
pnpm verify
```

Для каждой поведенческой волны добавляются точечные тесты успеха, отказа,
прав, идемпотентности и replay.

### Ручная

После activation: создать новую кампанию 2014, пройти создание героя, бой,
заклинание, отдых, торговлю, встречу и повышение уровня двумя игроками; затем
перезапустить сервер и повторно открыть старую кампанию 2024.

### Фактический результат

Foundation проверяет 28 базовых правил, 34 термина, 32 связи и 10 внешних
источников. Сервер устанавливает оба pack; мастер мира и настройки закрепляют
профиль за кампанией; смена до начала игры, metadata и replay согласованы;
Retriever и core provenance изолированы по `ruleset_id`. Механические каталоги
остаются частично общими под явным compatibility house rule. Полный runtime
cutover намеренно не объявлен выполненным.

## 11. Итог реализации

На foundation создан локальный ruleset и машиночитаемая карта долга без
изменения рабочего `storage/`. Следующая волна добавила per-campaign выбор двух
редакций, event-sourced pre-game смену и первые edition-sensitive ветки
механики; это partial preview, не завершение cutover.

## 12. Открытые вопросы

- Правовая возможность распространения структурированных данных dnd.su.
- Какие официальные дополнения 2014 будут первыми opt-in packs.
- Должна ли 2024 оставаться доступной для новых миров после полной активации
  2014 или только обслуживать сохранённые кампании.
