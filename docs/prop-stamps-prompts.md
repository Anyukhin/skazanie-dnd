# Промпты для генерации набора штампов реквизита

Рабочий лист для генерации растрового набора под тему «здание с участком».
Покрывает **все 75 записей** реестра `server/asset-registry.mjs`.

Набор генерируется **листами**: 10 картинок, на каждой несколько предметов в
одном стиле. Так набор получается согласованным — стиль плывёт между отдельными
вызовами, но внутри одного кадра держится.

Куда класть готовые файлы и что делать дальше — в конце.

---

## 1. Как этим пользоваться

1. Скопировать **блок стиля** (раздел 2) — он одинаковый во всех промптах и
   именно он держит набор одним набором. Не менять его между листами.
2. К нему добавить **задание листа** из раздела 4.
3. Сгенерировать, скачать, положить под именем из задания листа.
4. Не понравился один предмет — перегенерировать **весь лист**, а не предмет:
   отдельная картинка выпадет из стиля.

Если модель умеет прозрачный фон — включить его. Если нет, фон задаётся
маджентой: это чистый цвет, которого нет ни в одном предмете, поэтому он
вырезается без ореола.

> **Замер первой генерации, 2026-07-26.** Чистую мадженту `#FF00FF` вернули
> только три листа из десяти (04, 05, 06). У остальных семи фон оказался
> «почти маджентой» — угол `rgba(239,11,239)`, ни одного пикселя точного цвета.
> Резать по точному совпадению на них нельзя, нужен допуск и снятие цветной
> каймы по краю предмета. Просить у модели **PNG без повторного сжатия**: муар
> в фоне появляется именно от него.

## 2. Блок стиля — вставлять в каждый промпт без изменений

```
Набор предметов для настольной ролевой карты, вид строго сверху.

Стиль: рисованная карта подземелий, чёткий тёмный контур, плотная заливка,
приглушённая землистая палитра — тёплое дерево, серый камень, латунь, зелень.
Лёгкая фактура материала внутри контура, без фотореализма и без блеска.

Камера строго над предметами, ортогональная проекция. Никакой перспективы,
никакого наклона, боковых стенок не видно. Освещение ровное и рассеянное,
направленной тени нет ни у одного предмета; допустима лишь мягкая симметричная
тень прямо под предметом.

Фон: сплошной чистый цвет #FF00FF без градиентов, теней и текстуры.
Предметы фона не касаются и друг друга не перекрывают.

Строго запрещено: любой текст, буквы, цифры, подписи, логотипы, водяные знаки,
рамки, люди, животные, руки, интерфейс, стрелки, сетка.
```

## 3. Общие правила раскладки

- **Ровная сетка.** Предметы стоят по строкам и столбцам, ячейки одинаковые,
  между ними пустой фон. Порядок чтения — слева направо, сверху вниз.
- **Каждый предмет целиком в своей ячейке** и не выходит за её границы.
- **Пропорция важнее размера.** Предмет занимает на карте определённое число
  клеток 5×5 футов, и его рисунок обязан быть такой же пропорции: стойка 4×1 —
  вытянутая полоса, круглый стол 2×2 — квадрат.
- **Ячейка сетки квадратная всегда, даже для вытянутых предметов.** Вытянутый
  предмет занимает ширину ячейки и ровно ту высоту, которую даёт его пропорция;
  сверху и снизу остаётся пустой фон. **Растягивать предмет на всю высоту
  ячейки нельзя.**

  > Первая версия этого документа задавала вытянутым предметам не пропорцию
  > предмета, а геометрию строки — «каждый в своей горизонтальной полосе».
  > Модель честно залила полосу: очаг вышел 8:1 вместо 2:1, барная стойка 9.7:1
  > вместо 4:1. Замерено на первой генерации 2026-07-26. Отсюда правило выше.
- **Ориентация одна для всех:** предмет «лицом» вниз, к нижнему краю кадра.
  Повороты рендер делает сам, поэтому в наборе нужен один канонический угол.
- Разрешение: **2048×2048** для квадратных листов, **2048×1024** для листов из
  широких полос.

## 5. Куда класть файлы

```
assets-src/prop-stamps/
  sheet-01-hall-wide.png
  sheet-02-furniture.png
  ...
  sheet-10-yard-small.png
```

Каталог **`assets-src/` — промежуточный**, вне `public/`. Это сделано намеренно:

- пока права на набор не зафиксированы, записи реестра **не должны** получать
  поле `raster`. Правило «растровая запись обязана ссылаться на `rightsId`»
  проверяется тестом `test/asset-registry.test.mjs`, и обойти его нельзя;
- `docs/map-library.md` требует сначала зафиксировать источник, лицензию,
  автора, состав и хеши, и только потом подключать набор versioned-каталогом.

Ничего, кроме складывания файлов, на этом шаге делать не надо: набор в игру
не попадёт, пока по правам не будет принято решение.

## 6. Что делает система, когда набор готов

Порядок отсюда — уже мой:

1. **Нарезка.** Инструмент режет лист по сетке, вырезает маджентовый фон,
   обрезает по границам предмета и сохраняет отдельные файлы по именам
   идентификаторов реестра.
2. **Атлас.** Отдельные картинки собираются в один файл с координатами —
   иначе на карту уйдут десятки запросов.
3. **Права.** Источник, модель, дата и хеши каждого файла записываются в
   `data/asset-rights.json`.
4. **Подключение.** У записей реестра заполняется `raster` и `rightsId`.
   Больше ничего менять не нужно: рендер выбирает растр, если он есть, иначе
   вектор, иначе плоскую заливку. Ни модель карты, ни генератор, ни серверная
   валидация про растр не знают — это решение Р3 из
   `docs/tactical-map-plan.md`.

Векторные рисунки при этом **остаются** и продолжают работать: они и есть
обязательный fallback из решения Р6 — карта должна быть играбельна без арта.
