# Документация проекта

Этот каталог хранит продуктовые принципы, описание фактических возможностей,
планы изменений и обоснования важных технических решений. Разные виды
документов отвечают на разные вопросы и не должны дублировать друг друга.

## Общая цель проекта

«Сказание» должно дать группе обычных игроков возможность без человека-ведущего
начать, пройти и завершить связную кампанию со свободой действий уровня
настольной игры, проверяемыми правилами и тактическими боями, по глубине и
удобству похожими на Baldur's Gate 3.

Каноническая полная формулировка, границы сравнения с BG3 и продуктовые
принципы находятся в
[`product-principles.md`](product-principles.md#назначение-и-цель). Этот раздел
служит указателем на неё, а не второй независимой редакцией цели.

Код, события и исполняемые тесты показывают фактическое поведение. Спецификация
фиксирует согласованное изменение, но после реализации не заменяет документы о
текущей архитектуре, покрытии правил и известных ограничениях. Если они
расходятся, расхождение нужно устранить, а не выбирать удобную версию.

## Рабочий цикл

1. Выбрать небольшой наблюдаемый результат для игрока или проекта.
2. Создать документ из [`specs/TEMPLATE.md`](specs/TEMPLATE.md).
3. Согласовать желаемое поведение, границы и критерии готовности.
4. Реализовать изменение в отдельной ветке и worktree.
5. Проверить результат по критериям и записать фактические доказательства.
6. При важном выборе с реальными альтернативами добавить запись в
   [`decisions/`](decisions/README.md).
7. Обновить канонические документы, [`CHANGELOG.md`](CHANGELOG.md) и
   [`ROADMAP.md`](ROADMAP.md), если их фактическое содержание изменилось.

Спецификация не обязательна для небольшой локальной правки, которая не меняет
контракт, пользовательское поведение или архитектурную границу. Запись решения
не создаётся, если альтернативы фактически не рассматривались или выбор не
создаёт долговременных последствий.

## Существующие документы

Планы, аудиты, журналы и контракты, созданные до этой системы, остаются на
месте. Они переносятся или заменяются только по мере работы с соответствующей
областью. [`ROADMAP.md`](ROADMAP.md) служит навигационным слоем над ними и не
переписывает их содержание.

[`MVP.md`](MVP.md) фиксирует раннюю гипотезу о короткой пользовательской сессии.
Она полезна как история проверки продукта, но не ограничивает общую цель полной
связной кампании из `product-principles.md`.
