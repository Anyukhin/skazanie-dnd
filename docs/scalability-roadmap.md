# Масштабируемость и тестируемость: дорожная карта

Составлена 2026-10-05 по аудиту четырёх срезов: тестовая инфраструктура,
архитектура сервера, горячие пути, клиент. Цифры — grep и замеры на копии
рабочих кампаний; где вывод не замерен, это сказано.

## Что мешало

- **HTTP-тесты.** ~80 файлов поднимают `server/index.mjs` дочерним процессом и
  несут свои копии `startServer` (61), `waitForHealth` (69), `request` (68),
  блока окружения и цепочки «админ → вход → кампания → приглашение».
- **Тесты движка.** `dice()` переопределён в 139 файлах, сборка
  `FileEventStore` + `RulesEngine` — 146 раз, заглушка модели — в 46 файлах.
- **`server/index.mjs` не собирается в процессе:** побочные эффекты и `listen`
  при импорте, ~40 синглтонов, часы и кубики не внедряются.
- **`resolveCommandInternal`** — один `switch` на 114 команд (~9,7 тыс. строк)
  с общим замыканием из ~33 переменных; reducer — `switch` на 186 событий.
- **Журнал событий** читался целиком при каждом обращении (3–6 раз на
  действие), GET комнаты делал полную сверку проекции.
- **Клиент** перерисовывал весь экран на каждом кадре потока рассказа;
  поиск путей по карте пересчитывался на каждой перерисовке.

## Волна 1 — эта ветка (`claude/testability-wave1`)

- `test/kit/` — общий набор: сервер с админом, кампанией и игроками, кубики,
  движок с проверкой replay, заглушка модели; `docs/testing.md`.
- Сервер: инкрементальный индекс журнала, ограниченный кэш головы, дешёвый
  GET комнаты с проверкой прав до сверки, без двойного сравнения проекций,
  очистка счётчиков частоты, кэш публичной проекции карты.
- Клиент: без лишних перерисовок от потока, чистая логика сессии в
  `src/game-session-state.mjs` с прямыми тестами, мемоизация путей на карте,
  общий помощник компиляции клиентского TS для тестов.
