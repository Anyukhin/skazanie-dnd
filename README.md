# Сказание

Фраза «Подбегаю к огру и бью его» собирает исполняемый боевой манёвр: сервер
предлагает подходящую клетку, маршрут и цену, а игрок подтверждает их на карте.
Перемещение и один удар выполняются обычными командами и сохраняются одним
пакетом событий. Реакции и опасные поверхности остаются в силе; прерванный
манёвр не откатывает уже произошедшие последствия движения.

Рискованная импровизация через свободный ввод теперь сначала показывает предложение
ведущего: проверку, цену попытки и последствия успеха/провала. Игрок подтверждает
его кнопкой «Подтвердить и бросить» либо отказывается; автобросок не пропускает
это согласование. Если мир изменился, требуется новое предложение. Составной
прыжок с атакой пока получает явное объяснение ограничения вместо молчаливой
подмены обычным ударом. Объём первой итерации и дальнейшие шаги:
[цифровой стол с ИИ-ведущим](docs/digital-table-next-steps.md).

Русскоязычный MVP кооперативной настольной RPG с виртуальным ведущим, общей историей и тактической картой. Вся игровая механика работает через один серверно-авторитетный контур: команды → события → reducer → снимки состояния → проверенное повествование. К нему подключены тактический цикл, событийная смена сцены, EncounterAssembler и торговля с серверными ценами, кошельком, складом и торгом; это всё ещё частичный срез, а не полная реализация D&D.

Целевой ruleset выбран отдельно: классическая D&D 5e 2014 по локальному
версионированному профилю `5e14.dnd.su`. Новый pack `dnd_5e_2014` уже лежит в
репозитории и доступен как честно ограниченный `preview`. При создании мира
владелец выбирает D&D 2014 или D&D 2024; до первого игрового события редакцию
можно изменить в настройках кампании, затем она фиксируется для replay. Создание
героя уже изолировано по `ruleset_id`: профиль 2014 содержит свои расы,
подрасы, расовые прибавки, обязательные расовые выборы, предыстории и варианты
стартовых наборов. Основные расовые особенности первого уровня исполняются
сервером через общие пути атаки, урона, спасброска, движения и отдыха. Остальные каталоги
2014 всё ещё исполняют смешанный baseline `srd_5_2_1`/2014/house rules до завершения
[спецификации cutover](docs/specs/2026-08-30-dndsu-2014-ruleset-cutover.md).
Сохранённые кампании автоматически не переписываются.

Ведущий поддерживает непрерывную кампанию без заранее записанного маршрута: агент создаёт только исходную ситуацию, а следующие главы возникают из подтверждённых решений игроков. При переходе агент-картограф получает публичный контекст сеттинга, героев и видимых врагов, выбирает физический масштаб, планировку и материал новой карты. Подтверждённое групповое решение превращается в системную команду `AdvanceScene` и событие `SceneAdvanced`: reducer переносит группу ко входу, очищает прежний encounter и сохраняет историю глав, посещённые места и незавершённые нити в `state.adventure`. Структурированная карта привязывается к каноническому `location_id`: повторный вход возвращает сохранённую геометрию и изменения, проведённые событиями, независимо от номера главы. Для распознанного поселения Директор одновременно запрашивает `ShopAssembler`; новая лавка создаётся событием `MerchantCreated` в том же commit, а повторный вход в уже известную строку локации использует существующего торговца без сброса stock. Решение группы имеет устойчивую ссылку `interaction_id + resolved_option_id`, исполняется ровно один раз даже при параллельных запросах, а повтор победившего idempotency key читается из committed events без нового вызова картографа/модели.

Кнопки карты мира передают выбранный узел как URI-кодированный `destination_location_id`; сервер сохраняет его в решении группы и сверяет с известным server-owned `worldMap` перед построением маршрута. Канонический ID имеет приоритет над расходящимся отображаемым именем и различает одноимённые точки; старые клиенты без ID продолжают работать по имени.
Автономный пользовательский срез запускается без административных команд: обычный игрок создаёт мир и от одного до пяти героев через мастер кампании, делится отдельными ссылками комнаты с другими игроками, а кнопка «Продолжить сюжет» обращается к server-owned Director Agent. Новые кампании получают детерминированный пресет `one_evening`: сервер выбирает по seed бюджет 3–5 сцен, сообщает Режиссёру текущий номер и принудительно закрывает часы сцены, если предложенные намерения затягивают арку. Последняя сцена всегда имеет фазу `climax` и требует настоящего hard-encounter, созданного и разрешённого именно в ней; ранний или дорожный бой финалом не считается. Заполненные часы квеста закрывают его типизированным `QuestResolved`, записывают подтверждённый факт и следующую цель. Победа сохраняется как `CampaignCompleted`, а гибель последнего героя атомарно добавляет `CampaignFailed` после `HeroDied`. Оба исхода получают эпилог из одного party-visible набора ключевых фактов — квестов, обещаний, судеб NPC, репутации, маршрута и судеб героев; Рассказчик только оформляет подтверждённые данные, а без модели используется детерминированный текст.


## Команда ИИ-ведущего

Ведущий разделён на четыре роли с отдельными версионированными инструкциями:

- **Хранитель мира** отвечает на вопросы о лоре только из видимой памяти кампании, истории глав и посещённых мест. Он не получает инструменты изменения мира, а вопрос не расходует действие.
- **Режиссёр** управляет темпом, развилками, групповыми решениями и переходами. Он может открыть голосование, предложить общий бросок судьбы или карточку выбора, а после принятого решения вызвать смену сцены.
- **Арбитр правил** подбирает правила из закреплённого русско-английского Rule Pack, назначает проверки и использует только серверные броски с `roll_id`/`check_id`.
- **Рассказчик** превращает уже подтверждённые результаты и события в художественный русский текст, но не меняет состояние напрямую.

Маршрутизатор выбирает роль по намерению игрока. Вопросы о лоре, открытие голосования и сам голос бесплатны. Проверка расходует действие только после подтверждённого броска, а реальная смена мира или локации завершает ход. Для решений, затрагивающих весь отряд, агент использует `request_party_decision`: большинство для маршрута, общий d20 для доверия судьбе и явный выбор для необратимых последствий. Принятое решение передаётся Режиссёру, который связывает исход старой главы с новой целью, картой и сюжетным крючком.
Длительные опасности среды записываются инструментом `apply_hazard` и сохраняются сервером между ходами. `resolve_hazard` снимает состояние с обязательной проверкой только после серверного броска с закреплённой характеристикой и достаточной СЛ; реплика игрока сама по себе опасность не отменяет.

Актуальные контракты ролей, которые действительно исполняет модель:
`director/v1`, `narrator/v6`, `action_adjudicator/v1`,
`npc_controller/v1`, `npc_controller/social_v3`, `campaign_creator/v3` и
`map_architect/v4`. Контекст передаётся им как недоверенные данные,
отделённые от системной инструкции. Хранителя мира и Арбитра правил исполняет
сервер детерминированно — из подтверждённой памяти кампании и из Rules Engine
соответственно, — поэтому контракта промпта у них нет.

### Политика творческих вызовов

Обычные перемещения, атаки, магия, торговля, инициатива и стандартные ходы NPC не вызывают LLM: их полностью исполняет единый серверный движок. Агент подключается только там, где нужна новая творческая информация:

- создание открытой исходной ситуации кампании без заранее определённых будущих сцен и финала;
- проектирование каждой новой области с учётом масштаба места, сеттинга, героев и противников;
- перелом боя: смерть участника, а также одно решение морали тяжело раненого врага — продолжать бой, бежать или сдаться;
- свободное нестандартное действие, для которого действительно нужен Арбитр или Режиссёр.

Модель никогда не исполняет координаты, урон или команды напрямую. Даже бегство рассчитывается сервером как допустимый путь, а художественная реплика создаётся только после committed event.

## Что работает

- игровая комната с от одного до пяти героев, журналом, картой, туманом войны, инвентарём и редактором листа;
- аккаунты, `scrypt`-хеши паролей и HttpOnly-сессии; владелец создаёт 1–5 серверных слотов и копирует одну ссылку для всего стола, а сервер атомарно закрепляет за каждым новым игроком ровно одного следующего свободного героя; действия ограничены владельцем героя или администратором;
- RouterAI-рассказчик с локальным fallback и строго разрешёнными инструментами;
- потоковый `narrator/v6`: механика сохраняется до первого SSE-кадра, сырые
  дельты провайдера превращаются в проверенные полные снимки предложений для
  всех участников, reconnect восстанавливает активный текст, а финал оседает
  в общей летописи; повтор одного idempotency key не вызывает модель снова;
- следующий ход вводится своими словами: Рассказчик и Картограф не генерируют готовые варианты действий и не передают их в состояние комнаты;
- свободные действия проходят bounded-разбор `ActionAdjudicator` v2: сервер
  повторно проверяет цель, предмет и proficiency/expertise по текущей сцене и
  листу, выбирает контекстную СЛ 10/15/20, разрешает NPC по роли/alias и
  переносит только собственную вещь героя через `TransferItem`; неоднозначность,
  попытка взять чужое и обыск тела не создают событий и не расходуют ход —
  причём отказ на обыске говорит про конкретное тело правду: если на нём есть
  снаряжение, ведущий так и отвечает, а не заявляет, что содержимого нет;
- один серверно-авторитетный движок для новых и загруженных кампаний, без переключателя режима в интерфейсе;
- серверные броски с `roll_id`/`check_id`, сроком действия, привязкой к кампании и защитой от повторного применения;
- частичный Rule Pack/Rules Engine: 15 правил формализованы детерминированно, ещё 7 структурированы частично; отдых и Hit Dice исполняются сервером, но полный lifecycle сна ещё не закрыт;
- «Дополнительная атака» встроена в действие «Атака»: воин 5-го уровня бьёт дважды, 11-го — трижды, между ударами разрешено перемещение, а трата действия на заклинание закрывает оставшиеся атаки;
- преимущество с возвышенности: разница высот от 5 футов даёт стрелку сверху преимущество, снизу — помеху, в ближнем бою высота не считается. Это не правило SRD, а явно объявленное тактическое правило в духе BG3;
- укрытие считается от линии огня: существо, бочка или стол дают цели +2 к КД, колонна, статуя или дерево — +5, стена перекрывает выстрел целиком; берётся лучшее укрытие, а не сумма, и тот же бонус идёт в спасброски Ловкости против заклинаний. Стрелять сквозь своего танка или мимо колонны теперь заметно хуже, чем сменить позицию;
- внезапность решается сервером при старте боя: Скрытность скрытых нападающих сравнивается с пассивным Восприятием каждого противника, и застигнутый врасплох теряет действие, бонусное действие, перемещение и реакцию до конца своего первого хода; один замеченный нападающий снимает внезапность со всей стороны;
- механические следствия состояний SRD объявлены одной серверной таблицей и действительно исполняются: `incapacitated`/`stunned`/`paralyzed`/`unconscious`/`petrified` закрывают действия и реакции, шесть состояний обнуляют скорость, преимущество и помеха на атаку выводятся из состояний обеих сторон, ближний удар в упор по парализованной или бессознательной цели автоматически критический, эти же состояния автоматически проваливают спасброски Силы и Ловкости, а окаменение даёт сопротивление всему урону; полный корпус состояний, истощение и длительности пока не закрыты;
- append-only event store, optimistic locking, idempotency keys, snapshots и replay;
- server-authoritative переход сцены: `AdvanceScene`/`SceneAdvanced` создаёт или переиспользует карту по `location_id`, сохраняет изменения клеток через события, adventure history и позиции отряда, а bounded `scene_commerce` при входе в поселение может атомарно добавить каталожного торговца через `ShopAssembler`;
- мирные NPC получают событийный пост по `location_id`: после `SceneAdvanced` сервер детерминированно ставит присутствующего NPC на раскрытую свободную клетку у подходящего роли реквизита, сохраняет `NpcPlaced`/`NpcMoved` для replay и отдаёт игроку только bounded `scene_npcs`. Такие NPC не входят в инициативу, но server-owned область или близкий промах могут создать `NpcHarmed`/`NpcDied`, реакцию свидетелей, изменение славы и подтверждённый факт смерти в памяти мира. Вне боя владелец героя может передать собственный снятый предмет живому viewer-visible NPC через ту же `TransferItem`: предмет событийно переезжает в bounded server-only `npc_world.inventories`, который не входит в player projection; кнопка этого действия остаётся в UI backlog;
- мир узнаёт о поступках отряда: летопись поступков выводится редьюсером из подтверждённых событий (убийство и побои мирного NPC, поджог, погром, кража на людях, выломанная на людях дверь, нарушенное и сдержанное слово, крупный дар, защита жителей) и запоминает место, минуту кампании и список свидетелей — живых NPC в сцене. Поступок без свидетелей остаётся тайной ведущего; поступок со свидетелями через детерминированную задержку по тяжести рождает `RecordRumor` и дальше расходится по графу мира со скоростью сутки на локацию, теряя точность на каждом пересказе (три формулировки по дальности, максимум два шага). Часы молвы идут сами — серверным драйвером по мировому времени, без участия клиента. Дошедший слух держит конкретный NPC: он произносит его вслух в разговоре и двигает славу своих фракций существующим механизмом репутации — цены, СЛ разговора, доступность услуг. Слухи и летопись пишутся с видимостью `gm_only`: игрок узнаёт молву только в игре, ведущий видит её лентой «Поступки и слухи» в «Управлении кампанией»;
- побеждённый враг может пережить бой пленным: сдавшийся или нокаутнутый-стабилизированный humanoid/giant/fiend/celestial/dragon на `EndCombat` перестаёт быть боевым актором и становится NPC отряда с детерминированным характером (из сида кампании), постом в сцене и меню; прозвище из таблицы имён достаётся только людям, дьявол и дракон держат своё. Его можно допросить проверкой Запугивания или Убеждения против серверной СЛ — разгром снижает её, каждый вытянутый факт повышает; удачный допрос раскрывает `gm_only`-зацепку памяти мира тем же `KnowledgeRevealed`, что и разговор с NPC, и только допрашивавшему герою. Пленного можно накормить, отпустить (отношение и запись о том, кем он может вернуться), сдать страже в поселении (награда из XP стат-блока и слава закона) или убить — гибель связанного (хоть ножом, хоть накрывшим его площадным заклинанием) и сутки без еды одинаково записываются в летопись поступков как жестокость. Пленные идут с отрядом при смене сцены; игроку видно, кого он держит, но не то, чего пленный ещё не сказал, — и не его стат-блок с XP;
- с выбывшего противника есть что снять, и это тот самый инвентарь, которым он дрался: в **той же фиксации**, что и его выбытие, появляется контейнер добычи — тело (весь lootable-остаток), разоружённый пленный (только оружие: допрашивают обезоруженного, карман остаётся при нём) или брошенный тюк, если переговоры кончились уговором «уйти, оставив добычу». Вещь **переезжает**, а не пересобирается по шаблону, поэтому выпитое зелье не воскресает, а расстрелянный колчан приходит полупустым; пустой контейнер не создаётся вовсе — у волка карманов нет. Смотреть бесплатно, но только вблизи: карточка называет вид, место и число предметов со всей сцены, а содержимое отдаётся лишь тому, чей герой стоит в пяти футах. Взять можно набором и с выбором получателя — целиком или никак: перегруз, исчезнувший экземпляр или чужой получатель отменяют всю команду и **не тратят действие**. В бою обыск одного контейнера стоит действия (правило стола, не SRD), вне боя бесплатен. Невзятое переживает уход со сцены и подъём на другой этаж: контейнер помнит свой ярус и ждёт возвращения. Двое за один кинжал — второй получает конфликт версии вместе со свежим списком, а повтор с тем же ключом идемпотентности возвращает прежний результат, не второй кинжал. Видно это всё на доске и в панели: павший остаётся затемнённой фишкой, рядом с ним висит метка с числом предметов, и щелчок по метке раскрывает карточку добычи — с портретом павшего, картинками вещей, весом, редкостью, выбором количества и получателя, суммарным весом и прогнозом перегруза. Кнопка не врёт: она называет «Взять — действие», «Подойдите ближе», «Не ваш ход» или «Уже забрал такой-то» — и все четыре ответа приходят с сервера, а не выводятся браузером. Опустевшее тело гаснет, а не пропадает рывком, и после победы отряд получает сводку: сколько тел не обыскано, где тайники и сколько предметов останется лежать, если уйти;
- бой не обязан кончаться трупами: посреди схватки можно предложить переговоры — кнопкой хотбара или свободной фразой («кричу им: остановитесь, поговорим!»). Распознаватель фраз детерминированный и с встречными признаками: «перемирием тут и не пахнет, режу его» окриком не считается, а «прекрати бой, или я тебя убью» идёт Запугиванием, а не уговором. Отвечает не красноречие игрока, а мораль стороны: серверная СЛ выводится из доли оставшихся ОЗ уцелевших и доли выбывших, и только потом её сдвигает двухфазный ручной d20 Убеждения или Запугивания. Фанатики не разговаривают — носитель «кровавой ярости» или «неотступной охоты» отказывает до броска, как и всякий, с кем договариваться нечем; действие тратится в любом случае. Успех замораживает очередь обеих сторон целиком — вместе с часами хода, поэтому сервер не пропустит ход героя, пока стороны говорят, — показывает рамку перемирия на доске и карточку условий, а предводитель уцелевших получает профиль собеседника и говорит существующим социальным контуром прямо в бою; жителем локации он не становится и после боя в мире говорящим не остаётся. Условия закрыты сервером: уйти с миром, уйти, оставив добычу (откуп монетой из XP стат-блоков), сложить оружие — сдавшийся дальше идёт обычным путём плена — или разойтись без уговора. Провал даёт насмешку, а повторный окрик в этом бою идёт с помехой. Удар под перемирием разрывает его и остаётся в летописи поступков вероломством наравне с убийством;
- у преступлений на людях есть цена: ступень розыска (0–3) выводится из той же летописи поступков и держится краем карты мира, а не улицей — убийство в деревне помнят и в соседнем городе того же региона. Вес зависит от тяжести (убийство 4, поджог 3, кража 2, побои 1), сутки без новых преступлений снимают очко, а поступок без свидетелей ступень не двигает вовсе. На входе в поселение с ненулевой ступенью стража выходит навстречу, и у офицера четыре ответа: заплатить виру (5/20/60 зм по ступени), сдаться (кошелёк изымают, сутки кампанийного времени уходят под замок, розыск снимается), драться (столкновение собирается существующим ассемблером, розыск поднимается до предела) или бежать — групповой проверкой Скрытности либо Атлетики против пассивного Восприятия стражи, где объявивший побег кидает двухфазный ручной d20 сам. Ушли — розыск остаётся; не ушли — стража на месте, и очков стало больше. Торговец при розыске сначала набавляет цену, а с третьей ступени не имеет дела вовсе. Ведущий видит ступень, очки и срок затухания карточкой «Закон и розыск» и может объявить амнистию; игрок цифры не видит — ему достаются офицер перед носом, косые взгляды и листы «разыскиваются» на столбах;
- в таверне есть чем заняться, и это стоит денег: «сыграть в кости» и «заказать выпивку» — карточки действия в зале, подхватываемые подсказками «что можно сделать». Раунд костей начинает соперник: сервер кидает его публичный d20 и кладёт кость на общий лоток стола, после чего у ручного двухфазного броска героя появляется честная СЛ — ровно «перебить показанное». Ставка выбирается из закрытого серверного набора (мелкая, крупная, отчаянная), банк переезжает целиком, а кошелёк не уходит в минус ни у героя, ни у соперника: ставка проверяется до первого события, и у соседа по столу своя касса на вечер — когда она кончилась, играть с ним больше не о чем. Раунд у каждого героя свой, поэтому один игрок за столом не запирает кости всему залу, а из-за стола всегда можно встать: раунд закрывается без броска и без движения монет — сам по команде или автоматически, если соперника обыграл дочиста товарищ по отряду. Подход к ответному броску (честно, подкрутить, следить за руками) выбирается до кубика и после него уже не меняется: сервер закрепляет его в первой фазе. Честен сосед по столу или шулер — выводится из сида кампании и в состояние не пишется, поэтому узнать это можно только Проницательностью: шулер подменяет кость, а не прибавляет к сумме, и стол видит уже подменённое число. Жульничество работает в обе стороны: герой давит Ловкостью рук против пассивной Проницательности соперника, и провал — это скандал, а не просто неудача: поступок в летописи со свидетелями, отношение обманутого вниз, а на второй раз из заведения выставляют. Стража за кости не приходит: за руку здесь ловит хозяин, а не закон. Выпивка честная и по SRD: кружка эля из кошелька, первые две развязывают язык (+1 к Убеждению до конца сцены, и собеседник видит перед собой человека с кружкой), с третьей идёт спасбросок Телосложения по нарастающей СЛ, а провал вешает `poisoned` — помеху на проверки до продолжительного отдыха. Счёт кружек живёт в сцене, похмелье остаётся с героем;
- у мира есть час и небо: время суток (утро, день, вечер, ночь) выводится из мировых минут кампании, а погода — из сида кампании, номера игрового дня и биома края карты мира, поэтому одинаковый день одинаково выглядит и после перезапуска, и после replay. Сутки погоды идут от рассвета к рассвету, так что «меняется по утрам» — та же граница, а не отдельное правило; смена приходит событиями и строкой летописи. Небо меняет и переход в другой край: климат принадлежит региону, поэтому за границей отряд встречает своё небо — и об этом тоже пишется строка, а не только пересчитывается индикатор. Влияние честное и только под открытым небом: дождь — помеха Восприятию и Выживанию, ночь — Восприятию, туман — дальним атакам, гроза — преимущество Скрытности; под крышей (здание, храм, склеп, пещера, подземелье) не действует ничего — крышу опознаёт тот же распознаватель тем, которым сцену строил генератор карты. Помеха попадает и в карточку ручного двухфазного d20, поэтому игрок видит режим броска до того, как возьмёт кубик. В шапке сцены стоит индикатор «Вечер · Дождь» с подсказкой, чем именно небо сейчас мешает; Рассказчик и Режиссёр получают час и погоду данными. - карты семи базовых типов (`rooms`, `streets`, `open`, `winding`, `cavern`, `ruins`, `radial`) и девяти планировочных наборов (`small-room`, `great-hall`, `keep`, `courtyard`, `crypt`, `cave-cluster`, `village`, `bridge`, `natural`) с масштабами от комнаты до крепости, неровными силуэтами, связанными проходами и проверкой линии выстрела через стены и границы карты; пять собственных светлых top-down подложек покрывают `cave`, `dungeon`, `tavern`, `temple`, `village`, а подходящая фактура цельно проецируется через серверные клетки; доска имеет перспективный 3D-наклон, вращается перетаскиванием и масштабируется колесом мыши без отдельного экранного контрола;
- реквизит сцены стал механикой: контейнеры и останки, алтари и придорожные святилища, костры, книжные полки, столы, завалы, брёвна и дорожные указатели получают server-owned глаголы `inspect/open/take/use`; Rules Engine повторно проверяет соседство, состояние, СЛ, ловушку, последствия 0 ОЗ, экономику действия и выдачу добычи. Осмотр и отдых у костра ограничены по герою, поэтому чужая попытка не закрывает объект для всего отряда. Каждая новая сцена детерминированно получает 2–4 точки интереса из палитры своей темы, но ключ тайника и награды остаётся скрытым до committed события; клик на доске и свободная фраза вроде «разбить бочку топором» сходятся в одной команде `OperateSceneObject`;
- единый визуальный resolver выбирает по серверной теме и `locationId` как собственную подложку доски, так и одну из 17 оригинальных широких иллюстраций заголовка; возврат в локацию сохраняет её вид, а локальный тумблер атмосферы отключает оба декоративных слоя. Процедурный Web Audio после первого жеста даёт девять различимых гармонических тем с приглушённой шумовой текстурой, отдельные фон и эффекты подтверждённых событий и хранит mute и две громкости в `localStorage`; аудиофайлов и нового источника игровой правды нет;
- реквизит рисуется поверх структурированных клеток как визуальная проекция; фактуры пола и стен масштабированы так, чтобы доски и каменные блоки читались мельче, а факел и лестницы используют встроенные top-down ассеты даже на обзорном масштабе;
- владелец кампании или администратор выбирает для группы одну из разрешённых сервером моделей и нейтральный, официальный или ироничный стиль Рассказчика; настройка хранится отдельно для кампании, применяется к реальному `/api/narrate` и переживает restart, произвольный идентификатор модели API не принимает;
- окно истории можно перетаскивать за заголовок и менять за правый нижний угол; положение и размер сохраняются локально отдельно для каждой кампании, а в бою окно ограничивается областью над панелью действий;
- player projection выдаёт врага как идентичность, позицию, состояние жизни, качественную ступень здоровья и безопасные `image`/`creature_type`; точные HP, максимум, КД, скорость, stat block, списки сопротивлений и иммунитетов, скрытые модификаторы и связанные поля событий закрыты, а часть из них появляется только после server-side записи `enemy_knowledge`. Все 50 server-owned профилей имеют индивидуальный локальный PNG 512×512.
- EncounterAssembler доступен Director flow без административной панели: обычный клиент не выбирает stat block, XP, количество или координаты; сервер принимает bounded intent, считает XP budget и выбирает противников из 50 server-owned профилей, а `EncounterCreated` и `CombatStarted` входят в один event commit;
- общий initiative order для героев, врагов и призывов, детерминированный NPC scheduler до следующего управляемого участника, одно bounded-решение морали при 30% ОЗ и автоматическое завершение боя при поражении, бегстве или сдаче одной стороны;
- полный базовый lifecycle 0 ОЗ по SRD 5.2: `unconscious`, автоматический серверный спасбросок от смерти в начале хода, три успеха/провала, натуральные 1/20, провалы от урона, массивный урон, Medicine СЛ 10, стабилизация, возвращение в сознание от лечения и автоматическое восстановление 1 ОЗ через серверные `1d4` часа; Bless/Bane изменяют итог, Beacon of Hope даёт преимущество и максимизирует получаемое лечение; счётчики, модификаторы и оставшееся время видны в журнале/инициативе и сохраняются replay; явный nonlethal knockout доступен только доверенной ближней атаке оружием или заклинанием, оставляет 1 ОЗ, запускает 60-минутный короткий отдых и досрочно снимается лечением либо успешной первой помощью;
- системный боевой журнал обычных действий без LLM и творческая реплика Рассказчика только для committed переломного события; оба сохраняются после reload/restart;
- меню торговца в текущей локации: покупка, продажа, серверная оценка нестандартного предмета и одна проверка торга; UI показывает кассу торговца и итог `цена за единицу × количество`, базовые цены берутся из versioned SRD-каталога либо из versioned server appraisal policy, а деньги героя, касса NPC, предметы и stock изменяются одним идемпотентным event commit;
- боевые расходники в основном исполняются сервером по current SRD 5.2.1: кислота, святая вода, алхимический огонь и масло заменяют один удар действия «Атака» и вызывают спасбросок Ловкости СЛ `8 + DEX + PB`, а не бросок атаки. Кислота наносит 2к6, святая вода — 2к8 только нежити и исчадиям, алхимический огонь — 1к4 сразу и 1к4 в начале ходов от горения; самотушение действием кладёт цель ничком. Разлив масла лужей — официальный режим, простой яд пока применяется Bonus Action. Противоядие на 60 минут даёт преимущество только на серверно распознанные спасброски для избегания или окончания состояния `Poisoned`; оно и зелье лечения тратят Action в 2014 и Bonus Action в 2024. HTTP, идемпотентность и replay покрывают `test/thrown-flasks.test.mjs`, `test/item-effects.test.mjs`, `test/item-effects-api.test.mjs` и `test/antitoxin.test.mjs`.
- единый immutable-каталог из 107 предметов SRD 5.2.1: каждый имеет локальное индивидуальное изображение 512×512, а `test/item-images.test.mjs` связывает файл с точной записью manifest. Серверно исполняются 42 профиля оружия (38 базовых и четыре магических длинных меча) с finesse, versatile, thrown, reach, режимом и характеристикой атаки, а также 14 профилей доспехов/щитов с требованием Силы, штрафом скорости и помехой Скрытности. Магические предметы сохраняют явный `partial`; mastery, расход/перезарядка боеприпасов, training, don/doff, общий crafting и большинство Utilize-эффектов пока не реализованы.

- разделённые роли `IntentParser`, `Adjudicator`, `Narrator` и `Verifier`; модель предлагает структурированный результат, но не записывает состояние напрямую;
- turn traces с редактированием секретов и объяснение решения через `/why` или explanation API;
- совместимый read contract и контролируемая проекция авторитетного состояния в room read-модель.

## Единый движок

```env
DND_DEFAULT_RULESET_ID=srd_5_2_1
DND_DEFAULT_RULESET_VERSION=5.2.1
```

`enforce` — единственный runtime. Валидированные команды и события являются источником истины для механики, после чего результат проецируется в совместимый формат чтения. Старые значения `legacy` и `shadow` при импорте нормализуются в `enforce` и не могут включить отдельный путь исполнения. Переключатель режима и широкая запись room state удалены.

Торговля остаётся bounded vertical slice, но lifecycle торговца уже событийный: административный/агентный контур умеет создать, настроить, пополнить, переместить, открыть и закрыть магазин, а `purse_cp` ограничивает реальную сумму выкупа. Детерминированный `ShopAssembler` собирает лавку, услуги, политику ежедневного пополнения и стартовую кассу только из явного server-owned allowlist и ограниченной policy; Директор автоматически включает его в атомарный переход к распознанному поселению. `AppraiseItem` создаёт server-side аттестацию нестандартного предмета. Сцены и магазины связаны каноническим `location_id`, групповые голоса и общий d20 сохраняются в FileEventStore, а server coordinator выполняет deterministic restock по времени кампании. Манифест покрывает 107 фиксированно оценённых позиций SRD 5.2.1 — 97 предметов базового снаряжения и десять magic-item, — но это не полный корпус и не обещание полной механики: по-прежнему нет electrum, supply/demand, краж, общего crafting и полной derivation Persuasion proficiency/expertise из листа персонажа.

EncounterAssembler остаётся ограниченным vertical slice. Его mini-compendium содержит 50 профилей с локальными миниатюрами, несколькими видами атак и исполняемыми особенностями. Multiattack выполняется несколькими бросками внутри одного Attack action: поддержаны одинаковые атаки, любая комбинация, точная квота разных профилей и заданная последовательность. Director автоматически запрашивает встречу через `/autonomy/advance`, а сервер после подтверждённого исхода замораживает точный reward plan, выдаёт XP, монеты и тематическую добычу отдельными каноническими стадиями, делит награду и только после всех последствий открывает переход. Строки Vulnerabilities/Resistances/Immunities SRD 5.2.1 объявлены у 13 профилей из 50 и исполняются единственным серверным счётчиком урона, поэтому атака, ловушка, зона и заклинание считают их одинаково: сопротивление — половина с округлением вниз, иммунитет — ноль, уязвимость — удвоение; иммунитет к состоянию отменяет само наложение, и причина видна в боевом тексте, а точные списки закрыты от игрока так же, как точные HP и КД. Recharge (X–6) исполняется для одноцелевых способностей: «Паутина» гигантского паука тратится, выпадает из плана NPC и возвращается серверным d6 в начале хода существа, а порог и сам бросок игрокам не показываются. `web-walker` у обоих паучьих профилей снимает доплату только за чистую область заклинания `web`; грязь, статическая и смешанная труднопроходимость оплачиваются обычно. Знание точного положения существа на общей паутине не заявляется без hidden-location subsystem. Шестнадцать гуманоидных профилей носят при себе то, чем действительно бьются: оружие инвентаря выводится из их же `action_profiles`, поэтому гоблин носит тот скимитар, которым машет, а не случайную вещь из таблицы наград; к нему добавляются комплекты боеприпасов диапазоном, изредка расходник и карман медяков. Всё это собирается детерминированно от сида кампании, встречи и самого существа, приезжает экземплярами с замороженным снимком каталога и переживает replay без изменений, а боевые формулы стат-блоков не трогает ни одним числом — инвентарь лежит отдельным полем, доспех в него не пропускается вовсе, и КД противника с полным инвентарём остаётся числом стат-блока. Зверь, слизень и безмозглая нежить остаются без карманов. Этими вещами противник теперь и пользуется: боевое действие стат-блока связано с конкретным экземпляром из инвентаря, поэтому выстрел снимает стрелу, пустой колчан закрывает дальнее действие, а выбитое оружие — ближнее. Тактик четыре и они закрыты кодом, а не моделью: раненый до 30 % ОЗ прикладывается к склянке (раз за бой, бонусным действием, до удара), шпион смазывает клинок ядом до первого удара, а тот, кому в этом ходу ударить нечем, мечет кислоту или алхимический огонь в двадцати футах. Своей механики ни у одной из них нет — лечение, склянка и яд идут теми же событиями, что у героя, и так же переживают replay: выпитое зелье исчезает ровно один раз. Привязка вещи к действию не создаётся молча: формула удара обязана совпасть с каталожной формулой оружия, а одиннадцать настоящих расхождений SRD 5.2.1 (длинный меч капитана стражи бьёт 2к10) объявлены поимённо и сверяются тестом. Игроку инвентарь живого противника не виден ни на карточке, ни в потоке событий — стол видит поступок («Гоблин прикладывается к склянке») и узнаёт о чужом колчане ровно одно, что он опустел; командовать инвентарём врага игрок не может, эта дверь открыта только серверному планировщику ходов. Закрыто при этом и число, а не только имя вещи: у неопознанного существа величина лечения уходит вместе с ОЗ до и после — ровное «+10 ОЗ» назвало бы зелье на 2к4 + 2 не хуже его названия, — и журнал пишет, что раны затянулись. Так же закрыт и смазанный ядом клинок: состояние противника уезжает столу качественной формой — «клинок смазан чем-то тёмным», — без экземпляра вещи из чужого кармана и без каталожного имени дозы, а служебные маркеры движка («тактика за бой уже потрачена») до стола не доезжают вовсе. Правило держится на всех поверхностях разом, включая окно реакции: получивший отравленный удар видит и величину, и что укусов было два, и что второй ядовитый, — но слагаемые приезжают белым списком, без ключа вещи и без идентификатора эффекта. Своё снаряжение это не задевает: свою дозу герой видит на своём клинке поимённо, и в списке бросков хода подпись называет, какой именно клинок сработал. Снятое с тела теперь настоящее: в той же фиксации, что и выбытие противника, появляется контейнер добычи — тело, разоружённый пленный или брошенный по уговору парлея тюк, — и lootable-остаток инвентаря **переезжает** в него, а не пересобирается по шаблону, поэтому выпитое зелье не воскресает, а расстрелянный колчан приходит полупустым. Тематическая таблица наград после встречи никуда не делась и считается отдельно: это два разных источника, а не двойная выплата. Боссы у движка появились, а в бестиарии — ещё нет, и это разные вещи. Существо может объявить магию полем `spellcasting` — СЛ спасброска, бонус атаки заклинаний и список редакции 2024 «неограниченно / X в день», без всяких ячеек, — и произносит её тем же самым `CastSpell`, каким пользуется герой: карточка берётся из каталога проекта, а числа из стат-блока, потому что напечатанную СЛ нельзя вывести формулой класса. Потраченное «X в день» считается маркером и переживает replay; заклинание, которого каталог не знает, отвергается отдельным честным кодом, а не общим «нельзя», — иначе опечатка в записи бестиария читалась бы за столом как решение автора. Легендарные действия работают так, как их читает редакция: вне своего хода, по одному на чужой ход и до трёх между своими, без единой траты собственной экономики — иначе босс, ударивший хвостом после хода героя, приходил бы в свой ход без действия. Запас возвращается в начале хода существа, а Легендарное сопротивление объявляет провалившийся спасбросок успешным по закрытому правилу: на контроль из списка и на урон, который снял бы босса до нуля, — на половине урона от одной стрелы суточный ресурс не жжётся. Обе двери открыты только серверному планировщику ходов: ни игрок, ни администратор за врага не колдуют и легендарными действиями не распоряжаются. Стол при этом видит босса и не видит его листа: в ленте инициативы у него своя рамка и корона, в карточке цели — крупный портрет, рядом полоса легендарных действий пипсами, — а блок заклинаний, СЛ, бонус атаки и вся бухгалтерия запаса закрыты и в состоянии, и в канале событий. Записей бестиария с боссом пока ни одной: сторож требует у каждой уникальный портрет 512×512 с подтверждёнными правами, а провайдер изображений недоступен, поэтому механика проверена синтетическими стат-блоками и ждёт портретов. Это всё ещё не полный набор stat blocks: нет полной поддержки saves/skills, lair actions и recharge-способностей по области (дыхания), условные защиты редакции («немагическое оружие») не переносятся вовсе, а Легендарное сопротивление подключено к основной ветке спасброска против заклинания и не покрывает вторичные вспышки и добавки «при попадании». Два браузера синхронизируются polling-ом комнаты раз в 1,5 секунды и `BroadcastChannel` в одном browser profile; WebSocket push и production-нагрузочный soak пока отсутствуют.

## Локальный запуск

Нужны Node.js `>=20.19.0` и pnpm.

```bash
pnpm install
pnpm dev
```

Vite покажет адрес интерфейса. При первом запуске задайте одноразовый `ADMIN_SETUP_TOKEN` или используйте Windows-лаунчер, который создаёт его автоматически. После первоначальной настройки обычный игрок регистрируется, открывает список кампаний и создаёт новый мир: сервер резервирует выбранные 1–5 безопасных слотов, а интерфейс требует закончить героя владельца до начала игры. Ссылка «Пригласить» содержит `?room=CODE`: каждый следующий зарегистрированный игрок получает ровно один ещё не занятый слот и проходит тот же мастер без панели управления миром. Приглашение одноразовое, поэтому для каждого гостя владелец создаёт отдельную ссылку.

Настройка RouterAI остаётся серверной:

```env
ROUTERAI_API_KEY=...
ROUTERAI_BASE_URL=https://routerai.ru/api/v1
# Первичная модель — по замеру 2026-07-31 (docs/model-benchmark-2026-07-31.md).
# GLM 5.3 Flash добавлена по повторному замеру 2026-08-30. Отдельный строгий
# контракт Рассказчика дал 12/12 принятых ответов при 100% памяти и голосов.
# Подробнее: docs/model-benchmark-2026-08-30-glm-5.3-flash.md.
DND_AI_MODEL=openai/gpt-5.6-luna
DND_AI_FALLBACK_MODELS=z-ai/glm-5.3-flash,z-ai/glm-5.2,deepseek/deepseek-v4-flash,google/gemini-2.5-flash-lite,openai/gpt-4.1-nano
DND_AI_MODEL_TIMEOUT_MS=20000
DND_IMAGE_MODEL=openai/gpt-image-1
```

Ключ не передаётся браузеру. При запуске сервер посылает каждой текстовой модели короткий JSON health-check. Если основная модель возвращает ошибку, таймаут, пустой или некорректный ответ, запрос последовательно переходит к моделям из `DND_AI_FALLBACK_MODELS`; неработающая модель временно исключается из каскада. Детерминированная механика и безопасный локальный fallback доступны и без ключа RouterAI. Необязательное художественное описание критического боевого момента имеет общий бюджет 4 секунды на весь каскад: механический результат уже сохранён, а при превышении бюджета клиент получает детерминированное описание.

## Миграция существующих кампаний

Сначала остановите запись, сделайте полную резервную копию `storage` вне дерева проекта и подтвердите редакцию правил кампании. Затем выполните только dry-run:

```bash
pnpm migrate:dry-run
```

Записывающая миграция запускается отдельно и создаёт byte-for-byte `.bak` перед изменением room JSON:

```bash
pnpm migrate
```

Старая metadata-миграция не выполняет cutover и не должна повторно запускаться над уже существующими event streams. Новые кампании создаются непосредственно в Event Store. Перед переносом старой кампании обязательны `cutover:audit`, replay-сверка, проверенная резервная копия и явный offline import. Полная процедура, критерии остановки и rollback описаны в [руководстве по миграции](docs/migration-guide.md) и [документе удаления legacy](docs/legacy-retirement.md).

## Основные API

- `GET /api/health` — provider, модель, режим, ruleset и инструменты;
- `POST /api/roll` — одноразовый серверный roll artifact; modifier/DC закреплены сервером только для выданного сервером `check_id`;
- `POST /api/narrate` — авторитетный ход по `campaign_id`, action и idempotency key; клиентский state, mode override и raw roll запрещены;
- `GET /api/campaigns/:id/stream` — authenticated SSE комнаты и проверенного
  повествования; события `narration.start/chunk/complete` содержат только
  `message_id`, полный заменяющий `text`, `phase`, `replace` и `replayed`, без
  state, механики и ключа идемпотентности;
- `GET /api/rules/search?q=...&ruleset_id=...` — поиск только внутри разрешённого ruleset/pack;
- `GET /api/health` — кроме состояния сервера возвращает legacy-каталог создания персонажа 2024 для совместимости;
- `GET /api/rulesets/:id/character-creation` — возвращает отдельный versioned-каталог выбранной редакции; для 2014 это расы/подрасы, расовые прибавки, PHB-предыстории и стартовые наборы;
- `POST /api/campaigns` — self-service создание кампании через проверенный `bootstrap`; поля героев от обычного клиента не принимаются как авторитетные, вместо них сервер создаёт выбранные 1–5 слотов; raw `state` разрешён только администратору для диагностики/миграции;
- `POST /api/campaigns/:id/invites` — owner/admin создаёт одну семидневную ссылку для всех ещё свободных слотов стола; сырой token возвращается только при создании;
- `POST /api/campaigns/:id/join` — идемпотентное присоединение по общему `invite_token`; под блокировкой хранилища сервер выдаёт аккаунту один свободный слот, а права и герой сохраняются в campaign-scoped membership;
- `GET|POST /api/campaigns/:id/lifecycle` — чтение и event-sourced переходы `active ↔ paused → completed|failed → archived`; terminal/archive блокируют игровую запись, завершение создаёт детерминированный эпилог;
- `POST /api/campaigns/:id/controls` — owner/admin выполняет `rewind_turn` или `replay_scene` с обязательным idempotency key; сервер добавляет `CampaignRewound` с целевым состоянием, не переписывая журнал и не позволяя откат через смену арки или финал;
- `POST /api/campaigns/:id/system-tick` — совместимый диагностический запуск coordinator; в обычной игре сервер продолжает durable NPC-ходы и пополнение магазинов сам, а `GET /api/rooms/:id` остаётся чистым чтением;
- `POST /api/campaigns/:id/party-decisions/:decisionId/votes` — event-sourced решение с одним голосом на аккаунт, явным воздержанием, пересчётом кворума при отключении и детерминированным исходом по TTL; legacy-кампании без membership используют голос героя;
- `POST /api/campaigns/:id/party-decisions/:decisionId/roll` — один серверный общий d20 и event-sourced исход решения;
- `POST /api/campaigns/:id/autonomy/advance` — обычный игровой запрос «продолжить»; Director Agent выбирает bounded intent, сервер исполняет правила и возвращает только viewer projection; raw `/autonomy/intents` остаётся admin-only диагностикой;
- `PATCH /api/campaigns/:id/engine-mode` — retired endpoint, возвращает `410 ENGINE_MODE_RETIRED`;
- `POST /api/campaigns/:id/commands` — typed commands: до завершения слота разрешён только идемпотентный `ImportCharacter`; затем обычному игроку доступны безопасный combat set и `BargainWithMerchant`/`AppraiseItem`/`BuyItem`/`SellItem` от имени назначенного героя; администратору доступен расширенный диагностический набор;
- `POST /api/campaigns/:id/encounters/assemble` — admin-only сборка и немедленный старт встречи; принимает `difficulty`, `theme`, `expected_state_version` и idempotency key, но не принимает stat block, XP, участников или координаты противников;
- `GET /api/campaigns/:id/merchants/:merchantId?actor_id=...` — публичная витрина и серверные котировки для назначенного героя;
- `POST /api/campaigns/:id/merchants/:merchantId/commands` — `BargainWithMerchant`, `AppraiseItem`, `BuyItem`, `SellItem` или `PurchaseMerchantService` с idempotency key и версией просмотренной котировки; цену услуги сервер выводит заново;
- `POST /api/campaigns/:id/merchants/commands` — admin-only event-sourced `CreateMerchant`, `ConfigureMerchant`, `RestockMerchant`, `MoveMerchant`, `SetMerchantAvailability`;
- `POST /api/campaigns/:id/merchants/assemble` — admin/agent ShopAssembler: создаёт проверенный каталогом proposal для текущей сцены и коммитит его через `CreateMerchant`;
- `GET /api/campaigns/:id/turns/:turnId/explanation` — объяснение применённых правил, бросков и событий; campaign ACL уже действует, но event-level visibility результата пока не реализована.

Команда `/why` в поле действия запрашивает такое же объяснение и не расходует ход.

Граница доверия, формулы цены, provenance и известные ограничения торговли описаны в [контракте экономики](docs/economy-contract.md).

### Пример одного хода

Боевой UI обычного игрока отправляет только идентификаторы героя/цели или координаты назначения. Участники инициативы, модификатор атаки, AC, формула и тип урона, дальность и допустимость пути вычисляются сервером; присланные клиентом overrides этих полей не считаются доверенными.

Расширенный диагностический пример ниже с прямым `ApplyDamage` доступен администратору. Идентификаторы и часть полей сокращены:

```http
POST /api/campaigns/RUNE-742/commands
Content-Type: application/json
X-Idempotency-Key: turn-damage-42

{
  "message": "Герой наносит гоблину 3 рубящего урона",
  "command": {
    "command_type": "ApplyDamage",
    "actor_id": "hero",
    "target_id": "goblin",
    "amount": 3,
    "damage_type": "slashing"
  }
}
```

Сокращённый совместимый ответ:

```json
{
  "narration": "Гоблин получает 3 урона.",
  "engine_mode": "enforce",
  "turn_id": "…",
  "state_version": 2,
  "mechanics": [{
    "event_type": "DamageApplied",
    "target_ids": ["goblin"],
    "payload": { "raw_amount": 3, "applied_amount": 3, "hp_before": 8, "hp_after": 5 },
    "source_rule_ids": ["srd_5_2_1:combat:damage"]
  }],
  "explanation_url": "/api/campaigns/RUNE-742/turns/…/explanation"
}
```

`/why` или `explanation_url` возвращает ту же provenance-цепочку без повторного хода:

```json
{
  "engine_mode": "enforce",
  "rules_used": ["srd_5_2_1:combat:damage"],
  "commands": [{ "command_type": "ApplyDamage", "actor_id": "hero", "target_id": "goblin" }],
  "rolls": [],
  "events": [{ "event_type": "DamageApplied", "source_rule_ids": ["srd_5_2_1:combat:damage"] }],
  "ruling": null,
  "state_version_before": 1,
  "state_version_after": 2
}
```

## Данные и архитектура

- `storage/auth.json` — аккаунты и сессии;
- `storage/rooms/*.json` — временная server-owned compatibility read-модель; публичная полная запись запрещена;
- `storage/engine/` — immutable event batches, metadata и snapshots;
- `storage/turn-traces/` — редактированные traces авторитетных ходов;
- `storage/generated/items/` — runtime-generated изображения предметов;
- `storage/generated/npcs/` — hashed persistent cache портретов важных NPC. Во время игры картинки **не генерируются**: флаг `DND_RUNTIME_IMAGE_GENERATION` выключен по умолчанию, готовое из кеша отдаётся как обычно, а вместо отсутствующего показывается ролевая заглушка. Готовятся портреты заранее, режимом подготовки ассетов в админской зоне (`/api/campaigns/:id/asset-preparation`, доступ администратору и владельцу кампании, до 20 позиций за запуск общим счётом на все виды картинок, расход идёт в usage-леджер);
- `storage/generated/locations/` — hashed persistent cache иллюстраций локаций. Готовятся тем же режимом подготовки; в игре (`GET /api/campaigns/:id/locations/:locationId/illustration`) картинка берётся **только из кеша** — модель оттуда не зовётся ни при каком флаге, а видимость локации решает проекция зрителя. Шапка сцены показывает готовую иллюстрацию, если она есть, и остаётся с библиотечной подложкой, если нет;
- `data/rule_packs/srd_5_2_1/` — Rule Pack;
- `prompts/*/v1.txt` — версионированные prompts ролей.

Файловое хранилище рассчитано на один процесс и небольшую кампанию. Event commit и compatibility projection связаны outbox/checkpoint; acknowledgement выполняется только после совпадения канонического SHA-256. Для нескольких серверов нужен транзакционный repository, например PostgreSQL.
